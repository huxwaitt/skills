# Amazon Web Services: capabilities, connectivity, CLIs, docs, limits (as of 2026-11-14)

## 6. AI and agent capabilities
- **Amazon Bedrock AgentCore is the agent platform, GA since October 2025.** AWS announced AgentCore GA in October 2025 in nine Regions, with VPC support, 8-hour execution windows, session isolation, A2A protocol support, and Gateway turning APIs and Lambda functions into MCP tools. Source: https://aws.amazon.com/about-aws/whats-new/2025/10/amazon-bedrock-agentcore-available/
- **AgentCore has 13 modular services as of 2026-11.** The devguide lists Harness, Runtime, Memory, Gateway, Identity, Code Interpreter, Browser, Observability, Payments, Evaluations, Optimization, Policy and Registry. They work alone or together with any framework (CrewAI, LangGraph, LlamaIndex, Strands Agents, Google ADK, OpenAI Agents SDK) and any model. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html
- **AgentCore harness (managed agent loop) has been GA since June 2026.** You define a model, system prompt and tools in one config (`CreateHarness`) and call `InvokeHarness`. Each session runs in an isolated microVM with filesystem and shell. Public preview started in April 2026, and the What's New post is dated 2026-06-17. Since November 2026 the defaults use Strands with Claude Opus 5 in commercial Regions. Source: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-harness-generally-available ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Runtime hosts agents or MCP servers in containers or direct code (serverless microVMs).** It supports the HTTP (port 8080 `/invocations`, `/ws`), MCP (port 8000 `/mcp`), A2A (port 9000 `/`) and AG-UI protocols, with SigV4 or OAuth 2.0 inbound auth. An "Instances" compute type with capacity providers was added in August 2026 and runs on EC2 in your account. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-service-contract.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Memory provides short-term and long-term memory, including episodic memory.** Episodic memory was added in December 2025, TTL on long-term records in October 2026, and direct `IngestData` in August 2026. Short-term memory moved to consumption-based pricing in October 2026. Source: https://aws.amazon.com/about-aws/whats-new/2025/12/amazon-bedrock-agentcore-policy-evaluations-preview/ ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Identity is the agent identity and credential vault.** It provides workload identities, OAuth2 and API-key credential providers for outbound calls, and token vault storage. It works with Cognito, Okta, Entra ID and Auth0. Additions include OBO token exchange (April 2026), Private Key JWT client auth (July 2026) and a Consent Portal (September 2026). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **Policy in AgentCore has been GA since March 2026.** Policies sit in a policy engine attached to an AgentCore Gateway and are evaluated on every tool call. You author them in natural language that converts to Cedar. The devguide now names the policy language Dogwood, which is Cedar-compatible. Bedrock Guardrails support was added in June 2026. Source: https://aws.amazon.com/about-aws/whats-new/2026/03/policy-amazon-bedrock-agentcore-generally-available/ ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html
- **AgentCore Evaluations has been GA since 2026-03-31.** It offers online evaluation of sampled production traces and on-demand evaluation for CI/CD, with 13 built-in evaluators plus custom LLM-judge or Lambda evaluators. At GA it was in nine Regions. Batch Evaluations and A/B Testing went GA in June 2026, and Failure Insights entered preview in June 2026. Source: https://aws.amazon.com/about-aws/whats-new/2026/03/agentcore-evaluations-generally-available/ ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Optimization (Recommendations, configuration bundles, A/B testing) has been GA since June 2026.** It optimizes system prompts and tool descriptions from traces, using A/B traffic splitting through Gateway. It was in public preview from April 2026. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Observability emits OTEL-compatible telemetry to CloudWatch.** Cross-account monitoring was added in April 2026. Since 2026-07-20, new agents write spans to their own log group by default, and older agents keep `aws/spans`. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Browser and Code Interpreter provide managed computer and browser use and code sandboxes.** Browser is a cloud Chrome runtime for Playwright and BrowserUse, with OS-level interaction since April 2026. Code Interpreter runs Python, JavaScript and TypeScript, with Node.js since March 2026. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Payments is in preview (since May 2026).** It handles x402 and Machine Payments Protocol microtransactions, with Coinbase CDP and Stripe (Privy) wallets. Regional availability is limited (secondary). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AWS Agent Registry (formerly "AgentCore Registry") has been GA since August 2026.** It is a governed catalog of MCP servers, agents, skills and tools, with approval workflows, hybrid search and a native MCP endpoint. It entered public preview in April 2026 and reached AWS GovCloud (US-West) on 2026-11-06. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html ; https://aws.amazon.com/about-aws/whats-new/2026/11/aws-agent-registry-govcloud-us-west/
- **Bedrock Agents is now "Bedrock Agents Classic" in maintenance mode.** It has been closed to new customers since 2026-07-30, gets no new features and has no planned end-of-life date. AWS recommends migrating to the AgentCore harness, or to code-defined agents on AgentCore Runtime. A migration skill is in the Agent Toolkit for AWS. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/agents-classic-maintenance-mode.html
- **Bedrock Knowledge Bases and Guardrails are not affected by Agents Classic maintenance mode.** In AgentCore you connect a knowledge base through AgentCore Gateway. Guardrails set on the model still apply, and agent-level enforcement goes through Gateway policies. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/agents-classic-maintenance-mode.html
- **Amazon Bedrock Managed Knowledge Base (fully managed RAG) has been GA since June 2026.** It manages vector storage and offers hybrid search, reranking and agentic multi-hop retrieval. It has six native connectors: S3, SharePoint, Confluence, Google Drive, OneDrive and Web Crawler. It integrates natively with AgentCore. Source: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-managed-knowledge-base/
- **Bedrock Guardrails cross-account safeguards have been GA since April 2026.** You enforce guardrails across an AWS Organization from the management account, at organization, account or application level. Source: https://aws.amazon.com/about-aws/whats-new/2026/04/bedrock-guardrails-cross-account-safeguards/
- **The Bedrock model catalog is serverless, and models are enabled by default.** Anthropic models before Claude Opus 4.7 still need a one-time first-time-use form (`PutUseCaseForModelAccess`), filed once per account or org. Starting with Claude Opus 4.7 the form is not needed, and it never applies through `bedrock-mantle`. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html ; https://aws.amazon.com/blogs/security/simplified-amazon-bedrock-model-access/
- **Amazon SageMaker AI covers custom model training, fine-tuning and hosting.** Serverless model customization (SFT, DPO, RFT, LoRA, full fine-tuning) launched in December 2025 and has expanded through October 2026. Training session APIs launched in October 2026. Both run in a few Regions (us-east-1, us-west-2, ap-northeast-1, eu-west-1; training sessions also ap-south-1). Source: https://aws.amazon.com/about-aws/whats-new/2025/12/new-serverless-model-customization-capability-amazon-sagemaker-ai/ ; https://aws.amazon.com/about-aws/whats-new/2026/10/training-session-apis-on-sagemaker-ai/
- **Lambda durable functions bring checkpointed multi-step workflows into Lambda.** They offer `steps` and `waits`, suspend for up to one year without compute charges, and support Python 3.13/3.14 and Node.js 22/24. They launched in December 2025, initially GA in us-east-2. Source: https://aws.amazon.com/about-aws/whats-new/2025/12/lambda-durable-multi-step-applications-ai-workflows/
- **Step Functions has an optimized integration for the AgentCore harness.** The resource is `arn:aws:states:::bedrockagentcore:invokeHarness`. It is request-response only (no `.sync` or `.waitForTaskToken`), and it returns only the final assistant text in Converse shape. The Task state is capped at 900 s even if `TimeoutSeconds` is higher, and the harness keeps running after the Task times out. Source: https://docs.aws.amazon.com/step-functions/latest/dg/connect-bedrockagentcore.html
- **AWS Quick (formerly Amazon Quick and Amazon Quick Suite, formerly QuickSight) is the business-user agent workspace.** It offers chat agents, autonomous and always-on agents, flows, apps and deep research. The rename to AWS Quick was announced in November 2026, and Quick Sight remains its BI component. Source: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-quick-aws-quick/ ; https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-quick-always-on-agents-sharper-feed-enterprise-controls/
- **Amazon Q Developer has been split and renamed.** Q Developer CLI and IDE became Kiro, and the Q Developer console became the Kiro console. In November 2026, Q Developer in the AWS Console was renamed "AWS assistant". Source: https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/upgrade-to-kiro.html ; https://aws.amazon.com/about-aws/whats-new/2026/11/q-developer-renamed-aws-assistant/

## 7. Connectivity
- **AWS MCP Server is AWS's managed remote MCP server and has been GA since 2026-05-06.** It is part of the Agent Toolkit for AWS, and its preview was announced at re:Invent 2025. One endpoint lets an agent call any AWS API, run sandboxed Python, search and read docs, and load agent skills. It has IAM guardrails, CloudWatch metrics and CloudTrail logging, at no additional charge. Source: https://aws.amazon.com/about-aws/whats-new/2026/05/aws-mcp-server/
- **AWS MCP Server endpoints follow the pattern `https://aws-mcp.<region>.api.aws/mcp`.** The setup guide lists us-east-1, us-west-2, ap-southeast-1, ap-southeast-2, ap-northeast-1, eu-central-1, eu-west-1 and eu-west-2. This is newer than the GA post (May 2026), which listed only us-east-1 and eu-central-1. Source: https://docs.aws.amazon.com/agent-toolkit/latest/userguide/getting-started-aws-mcp-server.html
- **AWS MCP Server has about a dozen tools in two groups.** No-credential tools: search and read documentation, list Regions, regional availability. IAM-authenticated tools: `aws___call_aws` (any API), run script in a sandbox, retrieve skill, get tasks, S3 presigned URL. Source: https://aws.amazon.com/blogs/networking-and-content-delivery/how-amazon-cloudfront-secures-and-accelerates-the-aws-mcp-server/ ; https://aws.amazon.com/blogs/security/understanding-iam-for-managed-aws-mcp-servers/
- **AWS MCP Server auth option A is OAuth 2.1 through AWS Sign-in.** No local proxy is needed. The principal needs the managed policy `AWSMCPSignInOAuthAccessPolicy` (`signin:AuthorizeOAuth2Access`, `signin:CreateOAuth2Token`). Access tokens last 1 hour and auto-refresh for up to 12 hours. Some clients (Claude Desktop, Cursor, VS Code, Codex, Gemini CLI, Copilot CLI, Kiro IDE) need `?oauth=initialize` appended to the URL. Multi-profile switching is not supported. Source: https://docs.aws.amazon.com/agent-toolkit/latest/userguide/getting-started-aws-mcp-server.html
- **AWS MCP Server OAuth also has a headless client-credentials path.** Run `aws signin create-oauth2-token-with-iam --grant-type client_credentials`. It signs with SigV4 and returns a Bearer token that lasts 3600 s. The OAuth announcement is dated 2026-07-09. Source: https://aws.amazon.com/blogs/security/introducing-oauth-support-for-aws-mcp-server/
- **AWS MCP Server auth option B is SigV4 through the MCP Proxy for AWS.** Run `uvx mcp-proxy-for-aws-cli@latest https://aws-mcp.us-east-1.api.aws/mcp --metadata AWS_REGION=us-west-2`, which needs AWS CLI ≥ 2.32.0 and uv. This option supports read-only mode, multiple profiles and a default Region. Claude Code example: `claude mcp add aws-mcp https://aws-mcp.us-east-1.api.aws/mcp --transport http` for OAuth. Source: https://docs.aws.amazon.com/agent-toolkit/latest/userguide/getting-started-aws-mcp-server.html
- **MCP Proxy for AWS (`mcp-proxy-for-aws`, PyPI) is GA, open source and at version 1.8.0 (2026-11-03).** It SigV4-signs MCP traffic to AWS-hosted MCP servers and to AgentCore Gateway or Runtime endpoints, and has read-only mode and retries. GA was announced in October 2025. Source: https://aws.amazon.com/about-aws/whats-new/2025/10/model-context-protocol-proxy-available/ ; https://pypi.org/pypi/mcp-proxy-for-aws/json
- **IAM context keys `aws:ViaAWSMCPService` (bool) and `aws:CalledViaAWSMCP` (string) cover all AWS-managed MCP servers.** Example values for `aws:CalledViaAWSMCP` are `aws-mcp.amazonaws.com`, `eks-mcp.amazonaws.com` and `ecs-mcp.amazonaws.com`. Use the keys in IAM policies or SCPs to deny or limit actions an agent takes through MCP, for example to deny S3 deletes through MCP. Source: https://aws.amazon.com/blogs/security/understanding-iam-for-managed-aws-mcp-servers/
- **AWS Knowledge MCP Server (remote, no AWS account, rate-limited) has been GA since October 2025.** The endpoint is `https://knowledge-mcp.global.api.aws`, and it needs no auth. Tools: `search_documentation`, `read_documentation`, `recommend`, `list_regions`, `get_regional_availability`. AWS now recommends the AWS MCP Server instead. Source: https://aws.amazon.com/about-aws/whats-new/2025/10/aws-knowledge-mcp-server-generally-available/ ; https://aws.amazon.com/blogs/infrastructure-and-automation/accelerate-region-expansion-with-the-aws-knowledge-mcp-server/
- **The AWS setup guide says to remove `aws-api-mcp-server` and `aws-knowledge-mcp-server` when you adopt AWS MCP Server.** Overlapping tools confuse agents. Source: https://docs.aws.amazon.com/agent-toolkit/latest/userguide/getting-started-aws-mcp-server.html
- **awslabs/mcp is the open-source suite of local AWS MCP servers.** It is Apache-2.0 and lists 63 servers in categories from Core to Healthcare. Most run with `uvx awslabs.<server-name>@latest` over stdio; SSE was removed on 2025-05-26. The README calls the Agent Toolkit for AWS the successor for production. Source: https://awslabs.github.io/mcp/ ; https://github.com/awslabs/mcp
- **Three awslabs/mcp servers are deprecated.** The Cloud Control API MCP Server is replaced by the AWS IaC MCP Server. The Amazon Kendra Index and Amazon Q Business Anonymous MCP servers are replaced by AWS MCP Server. The awslabs site still labels AWS MCP Server "in preview", which is stale since its GA in May 2026. Source: https://github.com/awslabs/mcp ; https://awslabs.github.io/mcp/
- **AWS API MCP Server reached v1.0.0 in October 2025 (local, open source, container in ECR Public).** It added streamable HTTP, elicitation, a deny-list and consent for mutating actions, and `get_execution_plan` (experimental). Source: https://aws.amazon.com/about-aws/whats-new/2025/10/aws-api-mcp-server-v1-0-0-release/
- **Service-specific managed MCP servers exist, and the managed EKS MCP Server is in preview.** The EKS endpoint is `https://eks-mcp.<region>.api.aws/mcp` with IAM actions `eks-mcp:InvokeMcp`, `eks-mcp:CallReadOnlyTool` and `eks-mcp:CallPrivilegedTool`. ECS has its own MCP actions (`ecs-mcp:UseMcp`, `ecs-mcp:InvokeReadOnlyTools`). Source: https://docs.aws.amazon.com/eks/latest/userguide/eks-mcp-tool-configurations.html ; https://docs.aws.amazon.com/service-authorization/latest/reference/list_ecs-mcp.html
- **AgentCore Gateway turns APIs, Lambdas and MCP servers into one MCP endpoint.** MCP targets are aggregated into a single virtual MCP server with one `tools/list`. Target types: Lambda functions, API Gateway REST API stages, OpenAPI schemas, Smithy models, remote MCP servers, built-in integration templates and built-in connectors. Gateway also offers semantic tool search and target-level 3LO OAuth, which went GA in April 2026. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-targets-mcp.html
- **AgentCore Gateway also has HTTP passthrough targets and inference targets (both since June 2026).** Inference targets route LLM traffic to providers through model-based routing. AgentCore Runtime targets went GA in June 2026. October 2026 added a Step Functions connector, MCP Tasks, model fallback and private CA for targets. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-supported-targets.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Gateway built-in integration templates cover 16 providers.** They are Amazon, Asana, BambooHR, Brave, Coinbase x402 Bazaar, Confluence, Jira, Microsoft, PagerDuty, Salesforce, ServiceNow, Slack, Smartsheet, Tavily, Zendesk and Zoom. Built-in connectors include the Web Search Tool (GA June 2026) and Web Answer (GA November 2026, us-east-1). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-integrations.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Gateway inbound auth options are JWT, IAM or offloaded.** JWT uses `CUSTOM_JWT` with `discoveryUrl`, `allowedAudience`, `allowedClients`, `allowedScopes` and `customClaims`. IAM uses `AWS_IAM` and needs `bedrock-agentcore:InvokeGateway`. Offloaded modes are "Authenticate only" and `NONE`. The AgentCore CLI defaults to `NONE` (unauthenticated) if you omit `--authorizer-type`. Outbound auth to targets uses the IAM role, API keys or OAuth through AgentCore Identity. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-inbound-auth.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-using-auth-ex-starter.html
- **AgentCore Gateway URL pattern is `https://{gateway-Id}.gateway.bedrock-agentcore.{Region}.amazonaws.com`.** The control plane is `bedrock-agentcore-control.<region>.amazonaws.com`, and the service principal is `bedrock-agentcore.amazonaws.com`. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **Bedrock has two inference endpoints, `bedrock-runtime.{region}.amazonaws.com` (recommended) and `bedrock-mantle.{region}.api.aws`.** `bedrock-runtime` serves InvokeModel, Converse, OpenAI-compatible Chat Completions and Responses (at `/openai/v1`), and the Anthropic Messages API. `bedrock-mantle` serves Responses, Chat Completions and Messages. Both run on the same Mantle engine at the same per-token price. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html
- **Only `bedrock-runtime` supports Guardrails, intelligent prompt routing, custom inference profiles, batch and Provisioned Throughput.** Only `bedrock-mantle` supports server-side tools (such as web search), background inference (`background=true`), Projects and Workspaces. Mantle inference IAM uses `bedrock-mantle:CreateInference`. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html ; https://docs.aws.amazon.com/bedrock/latest/userguide/scaling-throughput-best-practices.html
- **Bedrock API keys (bearer tokens) work with the OpenAI SDK.** Set `OPENAI_BASE_URL` to the Bedrock base URL and `OPENAI_API_KEY` to the Bedrock key. Short-term keys last up to 12 hours and inherit the caller's IAM permissions, and AWS recommends them. Long-term keys create an IAM user with `AmazonBedrockLimitedAccess` and are meant for exploration only. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html ; https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html
- **AWS SDKs for agent work: boto3 1.44.3, Strands Agents 1.65.0, `bedrock-agentcore` 1.26.0 (2026-11-10).** These are the Python packages for AWS calls, the open-source agent framework and the AgentCore runtime SDK (`BedrockAgentCoreApp`). There is also an AgentCore client in the SDK for Python v4 docs (`pip install aws-sdk-bedrock-agentcore`). JS/TS uses the `@aws-sdk/*` v3 clients. Source: https://pypi.org/pypi/bedrock-agentcore/json ; https://docs.aws.amazon.com/sdk-for-python/v4/reference/clients/bedrock-agentcore/ ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-python-sdk-reference.html
- **A2A and AG-UI are supported agent protocols on AgentCore Runtime.** The `ProtocolConfiguration.serverProtocol` values are `MCP | HTTP | A2A | AGUI`, and the port is configurable from 8000 to 12000, except 8443. Source: https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/API_ProtocolConfiguration.html
- **AWS Quick is an MCP client for external MCP servers.** It supports SSE and streamable HTTP, with 3LO, 2LO or no auth. It discovers OAuth through RFC 9728 and Dynamic Client Registration. Since August 2026 it can enable MCP servers and agents from AWS Agent Registry. Source: https://docs.aws.amazon.com/quick/latest/userguide/mcp-integration.html ; https://aws.amazon.com/about-aws/whats-new/2026/08/aws-agent-registry-agents-mcp-servers-quick/
- **AWS Quick has built-in action connectors to SaaS.** Thirteen were added in April 2026: Google Workspace apps, Zoom, QuickBooks, Airtable and Dropbox. They sit alongside the earlier Salesforce, Jira, ServiceNow and Microsoft 365 connectors. Source: https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-quick-google-workspace-zoom/ ; https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-quick-custom-apps-natural-language/
- **The common event-driven agent pattern is EventBridge (rules or Scheduler) to Lambda to `InvokeAgentRuntime`.** AWS samples trigger AgentCore Runtime agents from schedules and webhooks this way. Source: https://aws.amazon.com/blogs/machine-learning/building-a-context-aware-ai-assistant-on-agentcore-and-openclaw/
- **PrivateLink has interface endpoints for Bedrock.** The suffixes are `bedrock`, `bedrock-runtime`, `bedrock-mantle`, `bedrock-agent` and `bedrock-agent-runtime`, each as `com.amazonaws.<region>.<suffix>`. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html
- **PrivateLink has three interface endpoints for AgentCore.** They are `com.amazonaws.<region>.bedrock-agentcore` (data plane), `com.amazonaws.<region>.bedrock-agentcore-control` and `com.amazonaws.<region>.bedrock-agentcore.gateway`. Endpoint policies can only filter IAM principals, so OAuth callers need `Principal: *`. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/vpc-interface-endpoints.html
- **JDBC and ODBC drivers don't apply to this scope.** The in-scope services (IAM, Bedrock, AgentCore, Lambda, Step Functions, EventBridge) are reached through HTTPS APIs and SDKs, and database drivers belong to separate database services. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html

## 8. CLIs and infrastructure as code
- **AWS CLI v2 is at 2.40.3, tagged 2026-11-13.** The changelog is on GitHub. Source: https://raw.githubusercontent.com/aws/aws-cli/v2/CHANGELOG.rst ; https://api.github.com/repos/aws/aws-cli/commits/2.40.3
- **On Windows, install AWS CLI v2 with the signed PowerShell script (recommended) or an MSI.** The script `irm https://awscli.amazonaws.com/v2/install.ps1 | iex` installs per user to `%LOCALAPPDATA%\Programs\Amazon\AWSCLIV2`, and `-System` installs for all users. The MSIs are `msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi` (all users) and `AWSCLIV2-User.msi` (current user). Source: https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html
- **On Linux and macOS, install AWS CLI v2 with `curl -fsSL https://awscli.amazonaws.com/v2/install.sh | bash`.** Add `--system` for all users. Source: https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html
- **A winget package `Amazon.AWSCLI` exists in the winget-pkgs repo (newest manifest 2.40.2).** AWS install docs do not list winget. (secondary) Source: https://github.com/microsoft/winget-pkgs/tree/master/manifests/a/Amazon/AWSCLI
- **`aws login` signs the CLI in with console credentials and is the recommended local-dev method.** It works for root, IAM users and federated identities, and `--remote` handles devices without a browser. Credentials auto-refresh every 15 minutes for up to the principal's session limit (max 12 h). The cache is `%USERPROFILE%\.aws\login\cache` (override with `AWS_LOGIN_CACHE_DIRECTORY`), and the profile gets `login_session = <arn>`. Use `aws logout [--all]` to sign out. Source: https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html
- **You can restrict `aws login` with IAM.** Target `arn:aws:signin:region:account-id:oauth2/public-client/localhost` (same device) and `.../remote` (cross-device). For SDKs that don't support login credentials yet, serve them through `credential_process`. Source: https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html
- **`aws configure sso` and `aws configure sso-session` set up IAM Identity Center sign-in.** They write an `[sso-session]` section with `sso_start_url`, `sso_region` and `sso_registration_scopes = sso:account:access`, plus a profile with `sso_account_id` and `sso_role_name`. You then run `aws sso login [--profile X | --sso-session Y]`. Tokens are cached in `~/.aws/sso/cache`. Source: https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html ; https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html
- **PKCE has been the default `aws sso login` flow since CLI 2.22.0.** It must complete on the same device. Use `--use-device-code` for headless devices. ## 10. Limits and gotchas
- **Bedrock `bedrock-runtime` throttling is per model and per Region (TPM, sometimes also RPM).** All APIs share the quota: InvokeModel, Converse, Responses and Chat Completions, even though quota names say "InvokeModel". `bedrock-mantle` quotas are counted separately, with separate input and output TPM and no RPM. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-runtime.html ; https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-mantle.html
- **Bedrock output tokens burn down quota faster than input tokens.** For recent Claude models, each output token counts as 5. Quota use = input + cache-write input + output × burndown rate. Source: https://aws.amazon.com/blogs/machine-learning/global-cross-region-inference-for-latest-anthropic-claude-opus-sonnet-and-haiku-models-on-amazon-bedrock-in-thailand-malaysia-singapore-indonesia-and-taiwan/
- **An unset `max_tokens` is a top cause of agent throttling.** Bedrock reserves input + `max_tokens` at admission, and if `max_tokens` is unset it reserves the model maximum (for example 64,000 for Claude Sonnet). The unused part is returned after completion. Source: https://aws.amazon.com/blogs/machine-learning/optimize-your-applications-for-scale-and-reliability-on-amazon-bedrock/ ; https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-mantle.html
- **Cross-Region inference (CRIS) profiles raise throughput, and each profile type has its own quota pool.** Geographic profiles use prefixes such as `us.` and `eu.`, and global profiles use `global.`. Quotas such as "Global cross-Region model inference tokens per minute for ${Model}" are viewed and raised in the source Region. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html ; https://aws.amazon.com/blogs/machine-learning/access-openai-gpt-models-on-amazon-bedrock-from-canada-with-cross-region-inference/
- **Cross-Region inference fails with `AccessDeniedException` when SCPs block destination Regions.** Geographic CRIS needs every destination Region allowed. Global CRIS needs `aws:RequestedRegion` = `unspecified` and the Region-agnostic ARN `arn:aws:bedrock:::foundation-model/...`. Alternatively, exempt with the `bedrock:InferenceProfileArn` condition key. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html ; https://repost.aws/knowledge-center/bedrock-access-denied-exception
- **Some Bedrock features are rejected on `bedrock-runtime` Responses calls.** On `bedrock-runtime`, the Responses API rejects `background=true` (400) and application inference profiles (400), and has no server-side tools. Stored responses belong to the Region that served them. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html
- **A wrong `bedrock-mantle` path prefix makes requests fail.** Some models are served under `/v1` and others under `/openai/v1`, and a wrong prefix returns "model ... isn't supported on this route". Listing models against the `bedrock-runtime` `/openai/v1` URL returns `404 UnknownOperationException`. Source: https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html ; https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html
- **AgentCore Runtime session limits.** The synchronous request timeout is 15 min, async jobs run up to 8 h on microVMs (14 days on Instances), and payloads are capped at 100 MB. Streaming connections last up to 60 min, the idle timeout defaults to 15 min (`idleRuntimeSessionTimeout`), and the max session lifetime defaults to 8 h (`maxLifetime`). Session storage is 1 GB. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **AgentCore Runtime throttles at 1,000 TPS for data-plane calls and 25 TPS for new sessions.** Both are adjustable and shared per account. They were simplified in August 2026 from 200 TPS and per-endpoint limits. Control-plane mutations are 50 TPS (not adjustable). Active sessions are 5,000 in us-east-1 and us-west-2, and 2,500 in other Regions. Cross-account calls count against the owner's quota. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html ; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html
- **AgentCore Runtime image and resource limits.** Images are capped at 2 GB on platform V1 and 10 GB on V2. Direct-code zips are 250 MB compressed and 750 MB uncompressed. Environment variables are 4 KB per agent. Sessions get 2 vCPU/8 GB by default, up to 8 vCPU/32 GB with resource configurations on V2. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **AgentCore Gateway limits (all adjustable).** Defaults: 100 targets per gateway, 1,000 tools per target, 15 min invocation timeout and 6 MB tool payloads. Tool-call and tool-list rates are 200 TPS per gateway and per account, with 5,000 concurrent connections. Search-based tool calls are 25 per minute. Web Search and Web Answer are 10 TPS each. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **AgentCore Memory, Browser and Code Interpreter limits.** Memory: 150 resources per Region, 200 `CreateEvent` per second per account, 5 per second per actor and session, and 150,000 TPM for long-term extraction (adjustable). Browser and Code Interpreter allow 1,000 concurrent sessions each, with 1 vCPU/4 GB and 2 vCPU/8 GB per session respectively. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **AgentCore Policy has a 400 KB Cedar schema cap per policy engine.** The schema grows with tool count and parameter complexity across all attached gateways. Split engines if you hit it. Policy APIs run at 1 to 5 TPS (not adjustable). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html
- **A Gateway-to-Runtime auth mismatch fails with "Authorization method mismatch".** An IAM runtime needs an IAM (SigV4) or Caller-IAM target, and a JWT runtime needs an OAuth or token-passthrough target. Source: https://repost.aws/knowledge-center/bedrock-resolve-authorization-method
- **AWS MCP Server rate limits are not adjustable.** Authenticated requests get 10 per second sustained per account per Region. Unauthenticated requests get 5 per second per source IP and only the read-only knowledge tools. Throttled requests return 429. Source: https://docs.aws.amazon.com/agent-toolkit/latest/userguide/aws-mcp-limits.html
- **Lambda limits for agent tools.** The timeout is 900 s (90 min for Managed Instances async and ESM invocations). Synchronous payloads are 6 MB each way, async payloads 1 MB, and streamed responses up to 200 MB, at 2 MBps after the first 6 MB. Default concurrency is 1,000 per Region, and new accounts start lower. Source: https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html
- **STS role chaining caps sessions at 1 hour.** `AssumeRole` `DurationSeconds` goes up to 43,200 s (12 h), subject to the role's max session setting. When you chain roles, any value above 3,600 s fails. Source: https://repost.aws/knowledge-center/iam-role-chaining-limit
- **Region gaps.** AgentCore Payments is preview-only in a few Regions, and SageMaker serverless customization runs in four Regions. Managed Knowledge Base launched in us-east-1, us-west-2, ap-southeast-2, ap-northeast-1, eu-west-1, eu-central-1, eu-west-2 and GovCloud (US-West). Source: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-managed-knowledge-base/ ; https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-sagemaker-muse-qwen-ministral/
- **Recent renames.**
  - Amazon Bedrock Agents became Bedrock Agents Classic (maintenance mode, 2026-07-30).
  - AgentCore Registry became AWS Agent Registry (GA, August 2026).
  - Amazon QuickSight became Amazon Quick Suite (October 2025), then Amazon Quick (2026), then AWS Quick (November 2026).
  - Amazon Q Developer CLI and IDE became Kiro (November 2025).
  - Q Developer in the AWS Console became AWS assistant (November 2026).
  - Source: https://docs.aws.amazon.com/bedrock/latest/userguide/agents-classic-maintenance-mode.html ; https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-quick-aws-quick/ ; https://aws.amazon.com/about-aws/whats-new/2026/11/q-developer-renamed-aws-assistant/
