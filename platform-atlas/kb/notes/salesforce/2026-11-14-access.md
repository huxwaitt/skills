# Salesforce: access, identity, roles, governance and commercial model (as of 2026-11-14)

Research note: developer.salesforce.com and admin.salesforce.com returned HTTP 403 to automated fetches and help.salesforce.com renders client-side only. Claims citing those hosts are based on the official page text as indexed by search. The full text of the official PDF guides on resources.docs.salesforce.com (REST API, Metadata API and Salesforce DX guides v68.0 Winter '27, and the Limits Quick Reference) was read directly.

## 1. Getting access
- **Unit of tenancy is the Salesforce org.** Each customer has a production org. Sandboxes, scratch orgs and Developer Edition orgs are separate orgs with their own users, metadata and API allocations. There is no account, project or workspace layer above the org for API access. Source: https://help.salesforce.com/s/articleView?language=en_US&id=platform.create_test_instance.htm&type=5
- **Sandbox types and refresh intervals.** Developer and Developer Pro sandboxes can be refreshed every 1 day, Partial Copy every 5 days and Full every 29 days. Developer and Developer Pro copy metadata only, Partial Copy copies a template-defined sample of data, and Full copies all data and metadata. Source: https://help.salesforce.com/s/articleView?language=en_US&id=platform.create_test_instance.htm&type=5 ; https://help.salesforce.com/s/articleView?id=000387743&language=en_US&type=1
- **Sandbox storage.** Developer sandboxes get 200 MB of data storage (400 MB with a storage upgrade), Developer Pro gets 1 GB (2 GB upgraded), Partial Copy gets 5 GB, and Full matches production. Partial Copy and Full sandboxes are not available in Professional Edition. Source: https://help.salesforce.com/s/articleView?language=en_US&id=sf.data_sandbox_environments.htm&type=5
- **Scratch orgs come from a Dev Hub.** Dev Hub can be enabled in Developer, Enterprise, Unlimited or Performance Edition orgs. Supported scratch org editions are Developer, Enterprise, Group and Professional. Each scratch org has 500 MB of data and 50 MB of file storage. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf ; https://developer.salesforce.com/docs/platform/sfdx-dev/guide/sfdx-dev-scratch-orgs-editions-and-allocations.html
- **Scratch org allocations by Dev Hub edition (DX Developer Guide v68.0, updated 2026-09-25).** Allocations are active/daily: Developer Edition or trial 3/6, Enterprise 40/80, Unlimited 100/200, Performance 100/200. The daily count is a rolling 24-hour window. Partner business orgs have different allocations. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf
- **Scratch org lifetime.** Duration is 1 to 30 days, set at creation with `sf org create scratch --duration-days`, and the default is 7 days. Source: https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_org_create_scratch.html ; https://developer.salesforce.com/docs/atlas.en-us.sfdx_dev.meta/sfdx_dev/sfdx_dev_scratch_orgs.htm
- **Scratch org features for Agentforce.** The `Einstein1AIPlatform` scratch org feature gives access to Agentforce, Prompt Builder, Model Builder and the Models API. It also requires `einsteinGptSettings > enableEinsteinGptPlatform` in the definition file's settings. `CustomerDataPlatform` and `CustomerDataPlatformLite` enable the Data Cloud license in scratch orgs. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf
- **Developer Edition includes Agentforce and Data Cloud.** Since March 2025 the free Salesforce Developer Edition includes Agentforce and Data Cloud (now Data 360). An April 2026 update added Agentforce Vibes IDE, Claude Sonnet 4.5 as the default coding model and hosted MCP servers, rolling out to existing orgs gradually. Source: https://developer.salesforce.com/blogs/2025/03/introducing-the-new-salesforce-developer-edition-now-with-agentforce-and-data-cloud ; https://developer.salesforce.com/blogs/2026/04/new-developer-edition-agentforce-vibes-claude-mcp
- **Developer Edition orgs expire through inactivity.** A Developer Edition org can expire if nobody logs in, and trial orgs expire on their expiration date. When a Dev Hub trial or DE org expires, its package versions are lost. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf
- **Developer Edition usage caps.** One Salesforce blog lists 5 MB of data, two Salesforce user licenses and 150 LLM calls per hour for Developer Edition, for non-commercial use. These figures come from a dated Japanese-language Salesforce blog. (unverified) Source: https://developer.salesforce.com/jpblogs/2016/04/developer-edition-signup/
- **Editions changed on 2026-09-03.** Salesforce launched Core ($195/user/month), Advanced ($395) and Max ($550) editions for Agentforce Sales, Agentforce Service and Agentforce Industries. Every edition bundles Agentforce, Slack and Slackbot, embedded agentic analytics, data security and Premier Success Plans. Pricing on existing legacy editions (Enterprise, Unlimited) is unchanged. Source: https://www.salesforce.com/news/stories/salesforce-simplifies-editions-2026/
- **Agentforce 1 Edition became Max Edition.** Max keeps the Agentforce 1 price of $550/user/month, and existing Agentforce 1 Edition customers can upgrade to Max at no extra cost. The pricing page now shows the card as "Max Edition". Source: https://www.salesforce.com/news/stories/salesforce-simplifies-editions-2026/ ; https://pricingsaas.com/companies/salesforce.agentforce/diffs/2026W41 (secondary)
- **Some sources say Enterprise and Unlimited are retired for new sales.** Third-party write-ups say the new editions replace Enterprise and Unlimited. Salesforce's own announcement only compares against "legacy" Enterprise and Unlimited and does not state a retirement. (secondary) Source: https://salesforcedictionary.com/blogs/salesforce-core-advanced-max-editions-2026 ; https://www.salesforceben.com/salesforce-announces-3-replacement-editions-bundling-ai-slack-and-security/
- **How enterprises buy.** Licenses, add-ons and extra API calls are bought through a Salesforce account executive or in-org through the Your Account app. Flex Credits can be bought as Pre-Purchase, PayGo or Pre-Commit (Pre-Commit is "widely available later this year"). Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf ; https://www.salesforce.com/agentforce/pricing/
- **Day-one asks for an engineer on a client engagement.**
  - A named user in a sandbox (Developer Pro or Partial Copy), plus a Dev Hub-enabled org if using scratch orgs.
  - The org's My Domain login URL (`https://<domain>.my.salesforce.com`, or `<domain>--<sandbox>.sandbox.my.salesforce.com`).
  - An external client app for the integration, plus a dedicated Salesforce Integration user.
  - Confirmation that Agentforce, Einstein generative AI and Data 360 are provisioned and which licenses exist (Einstein Agent licenses, Agentforce add-ons, Flex Credits).
  - Whether API Access Control is on.
  - The MFA/SSO setup.

  This list is compiled from the sections below. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf ; https://help.salesforce.com/s/articleView?language=en_US&id=platform.integration_user.htm&type=5

## 2. Identity and authentication
- **External client apps replace connected apps.** "Creating connected apps is restricted as of Spring '26." Existing connected apps keep working during and after Spring '26, Salesforce recommends external client apps (ECAs), and anyone who must create new connected apps has to contact Salesforce Support (REST API Developer Guide v68.0, updated 2026-10-09). Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_rest.pdf ; https://developer.salesforce.com/docs/platform/api-rest/guide/intro-oauth-and-connected-apps.html
- **Salesforce CLI exception for Dev Hub.** Orgs authorized for Salesforce CLI need an ECA (preferred) or a connected app. The default `Salesforce CLI` connected app is supplied. If you authorize a Dev Hub and plan to run `sf org create scratch|sandbox`, you must create a connected app instead of an ECA. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf
- **ECA OAuth flow switches (Metadata API `ExtlClntAppGlobalOauthSettings`, API 60.0+).**
  - `isClientCredentialsFlowEnabled` turns on client credentials.
  - `certificate` (a PEM certificate) enables the JWT Bearer flow.
  - `isDeviceFlowEnabled` turns on the device flow.
  - `isTokenExchangeEnabled` and `isSecretRequiredForTokenExchange` cover token exchange.
  - `isPkceRequired` defaults to true.
  - `isNamedUserJwtEnabled` (API 61.0+) issues JWT-based access tokens instead of opaque ones.
  - `isRefreshTokenRotationEnabled` turns on refresh token rotation.
  - `isCodeCredFlowEnabled` (API 61.0+) turns on the Authorization Code and Credentials flow for headless login.

  Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf
- **The client credentials flow needs an execution user.** In `ExtlClntAppOauthConfigurablePolicies`, `clientCredentialsFlowUser` names the execution user that tokens are issued for, and "this user must have the API Only permission". The flow returns no refresh token, scopes are assigned on the app rather than in the request, and anyone holding the consumer key and secret can mint tokens. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf ; https://help.salesforce.com/s/articleView?id=sf.meta_configure_client_credentials_flow_for_external_client_apps.htm&language=en_US&type=5 ; https://help.salesforce.com/s/articleView?language=en_US&id=xcloud.remoteaccess_oauth_client_credentials_flow_ca.htm&type=5
- **JWT bearer flow for CI and server-to-server work that needs a user context.** `sf org login jwt --client-id <consumer key> --jwt-key-file server.key --username <user> --instance-url <My Domain URL>` authorizes an org using a private key whose `server.crt` certificate is uploaded to the ECA. Salesforce points to JWT Bearer for integrations that need a user context. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf ; https://help.salesforce.com/s/articleView?id=000886201&language=en_US&type=1
- **Username-password OAuth flow and SOAP `login()` are on the way out.** Salesforce publishes a guide to migrating from the OAuth username-password flow to client credentials. SOAP API `login()` in API versions 31.0–64.0 retires in Summer '27. The org setting `OauthOidcSettings.blockOAuthUnPwFlow` blocks the username-password flow, and `blockOAuthUsrAgtFlow` blocks the user-agent flow. Source: https://help.salesforce.com/s/articleView?id=000886201&language=en_US&type=1 ; https://help.salesforce.com/s/articleView?id=005387171&language=en_US&type=1 ; https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf
- **Salesforce Integration user license.** The license grants API-only access and is paired with the `Minimum Access - API Only Integrations` profile. API-only access can't be removed from that profile. Extra rights come through permission sets that use the `Salesforce API Integration` permission set license. The license was introduced in Winter '23 (release 242). Source: https://help.salesforce.com/s/articleView?language=en_US&id=platform.integration_user.htm&type=5 ; https://help.salesforce.com/s/articleView?id=release-notes.rn_api_integration_license.htm&language=en_US&release=242
- **Free Integration user licenses.** Enterprise, Unlimited and Performance Edition orgs get five Salesforce Integration user licenses at no cost, and Developer Edition orgs get one. More can be purchased. Source: https://admin.salesforce.com/blog/2023/best-practices-for-configuring-your-integration-user ; https://developer.salesforce.com/blogs/2024/02/invoke-rest-apis-with-the-salesforce-integration-user-and-oauth-client-credentials
- **The old integration profile was superseded.** `Minimum Access - API Only Integrations` replaced `Salesforce API Only System Integrations` (Summer '23, release 248), because the old profile wrongly granted CRUD on custom objects. Source: https://help.salesforce.com/s/articleView?id=release-notes.rn_api_new_user_profile.htm&language=en_US&release=248&type=5
- **Recommended setup for an external agent calling Salesforce REST APIs.**
  1. Create a Salesforce Integration user with the `Minimum Access - API Only Integrations` profile.
  2. Grant object and field access through permission sets on the `Salesforce API Integration` PSL.
  3. Create an ECA with client credentials (or JWT bearer) and set that user as the execution user.
  4. Pre-authorize the app by profile or permission set.
  5. Call the token endpoint at `https://<MyDomain>.my.salesforce.com/services/oauth2/token`.

  Source: https://developer.salesforce.com/blogs/2024/02/invoke-rest-apis-with-the-salesforce-integration-user-and-oauth-client-credentials ; https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf
- **Agent API OAuth setup (Agentforce).**
  - The ECA needs scopes `api`, `refresh_token`/`offline_access`, `chatbot_api` and `sfap_api`.
  - Enable the client credentials flow and "Issue JWT-based access tokens for named users".
  - Turn off "require secret" for the web server and refresh token flows, and turn off "require PKCE".
  - Set a Run As user that has at least API Only access.
  - The token is minted against the My Domain URL.
  - Any flow that yields a JWT-based access token works.

  Source: https://developer.salesforce.com/docs/ai/agentforce/guide/agent-api-get-started.html
- **Agent API `bypassUser` flag.** On Agent API session creation, `bypassUser: true` runs the session as the agent's assigned agent user, and `false` runs it as the token's user. Source: https://developer.salesforce.com/docs/ai/agentforce/guide/agent-api-get-started.html
- **Agent identity: the agent user.** Agentforce Service Agents run as a dedicated agent user with the `Einstein Agent` user license and the `Einstein Agent User` profile, not a seat-consuming Salesforce license. Salesforce CLI can create one with `sf org create agent-user`. That user has no password and can't log in interactively. Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_user.htm&type=5 ; https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_org_create_agent-user.html
- **Employee agents run as the invoking user.** Employee agents (formerly Agentforce (Default) / Copilot) run in the signed-in employee's context. Access to a specific employee agent is controlled with permission sets or profiles ("Manage Employee Agent Access"). Source: https://help.salesforce.com/s/articleView?id=ai.agent_manage_aea_access.htm&language=en_US&type=5 ; https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_setup_explore_types.htm&type=5
- **Undocumented `agentAuthLinking` setting.** `OauthOidcSettings` has a boolean `agentAuthLinking` field with no description in the guide. It may relate to linking agent and user identities. (unverified) Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf
- **My Domain URLs.** Salesforce recommends the enhanced My Domain login URL ending in `my.salesforce.com` (for example `https://exciting.sandbox.my.salesforce.com`), not the `.lightning.force.com` URL, because it survives instance migrations. Set it in `sfdcLoginUrl` or pass `--instance-url`. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf
- **MFA is contractually required, with technical enforcement for all users.** MFA has been contractually required since 2022-02-01 for both direct and SSO logins. Salesforce enforces MFA for all users beginning 2026-06-26, after which the "Require multi-factor authentication (MFA) for all direct UI logins" setting can't be turned off. Source: https://security.salesforce.com/mfa/ ; https://admin.salesforce.com/blog/2026/prepare-your-org-for-salesforce-mfa-enforcement ; https://help.salesforce.com/s/articleView?id=005321561&language=en_US&type=1
- **SSO logins and phishing-resistant MFA for privileged users.** SSO logins satisfy the MFA requirement only if the IdP sends valid AMR/ACR claims. Otherwise users are prompted to enroll in Salesforce MFA. Admins and users with powerful permissions such as `Modify All Data` must present a phishing-resistant MFA signal or enroll in Salesforce phishing-resistant MFA. Source: https://help.salesforce.com/s/articleView?id=005321563&language=en_US&type=1 ; https://admin.salesforce.com/blog/2026/prepare-your-org-for-salesforce-mfa-enforcement
- **Supported MFA methods.** Salesforce Authenticator, third-party TOTP apps, WebAuthn/U2F security keys and built-in authenticators. Source: https://security.salesforce.com/mfa/
- **SAML/OIDC SSO and SCIM.** Salesforce supports SAML 2.0 and OpenID Connect SSO through My Domain and Auth. Providers, and the Salesforce Identity documentation covers SCIM user provisioning. I could not verify the current doc pages for these. (unverified) Source: https://help.salesforce.com/s/articleView?language=en_US&id=sf.security_overview_2fa.htm&type=5
- **No keyless workload identity federation found.** Salesforce documents no OIDC federation from GitHub Actions or other clouds. CI pipelines use the JWT bearer flow with a stored private key. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf

## 3. Roles and permissions
- **Permission model.** Access is additive. Each user has exactly one profile. Permission sets and permission set groups add object, field, user and app permissions. Permission set licenses (PSLs) gate which permission sets a user's license can carry. Record visibility comes from org-wide defaults, role hierarchy and sharing. Source: https://help.salesforce.com/s/articleView?language=en_US&id=sf.standard_profiles.htm&type=5 ; https://developer.salesforce.com/docs/platform/field-reference/references/field-reference/salesforce-field-reference-permissionset.html
- **Service agent user permissions.**
  - Org-wide defaults: Internal.
  - Permission set group `AgentforceServiceAgentUserPsg`, which bundles the `Agentforce Service Agent User`, `Data Cloud User` and `Prompt Template User` permission sets.
  - Permission set `Agentforce Service Agent Secure Base`.
  - An agent-specific `<Agent_Name>_Permissions` permission set. Grant object access by editing this set.

  Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_user.htm&type=5 ; https://www.salesforceben.com/agentforce-permissions-explained-agent-users-access-and-security/ (secondary)
- **CLI-created agent user.** `sf org create agent-user` assigns the `Einstein Agent User` profile and the permission sets `AgentforceServiceAgentBase`, `AgentforceServiceAgentUser` and `EinsteinGPTPromptTemplateUser`. `AgentforceServiceAgentBase` is probably the API name of "Agentforce Service Agent Secure Base". Source: https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_org_create_agent-user.html
- **Custom agent permission sets must fit the Einstein Agent license.** Any custom permission set for a service agent user must be compatible with the Einstein Agent license. Permissions outside the license fail with "The user license doesn't allow the permission" (for example, Edit Messaging Sessions). Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_user.htm&type=5 ; https://trailhead.salesforce.com/trailblazer-community/feed/0D5KX00000akxul0AA (secondary)
- **Agent builder permissions.**
  - Building service agents needs `Manage Agentforce Service Agents` and `Manage AI Agents`, or `Customize Application`.
  - Building employee agents needs `Manage AI Agents` or `Customize Application`.
  - Agentforce Studio and the new Agentforce Builder need `Manage AI Agents`.
  - `Manage AI Agents` grants org-wide management of all agents, so Salesforce says to assign it narrowly.

  Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_setup_explore_types.htm&type=5 ; https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_builder_studio.htm&type=5 ; https://trailhead.salesforce.com/content/learn/modules/agentforce-specialist-certification-maintenance-summer-25/learn-whats-new-with-agentforce-and-service-cloud
- **`Agentforce Default Admin` permission set.** It is referenced for the retiring Agentforce (Default) agent and Agent for Setup, alongside `View Setup and Configuration`. Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_setup_enable_default.htm&type=5
- **Keep management and runtime permission sets apart.** Never put builder permission sets on the agent user or runtime permission sets on human admins. (secondary) Source: https://www.salesforceben.com/agentforce-permissions-explained-agent-users-access-and-security/
- **Least privilege for an external agent's runtime identity.**
  - Use a Salesforce Integration user with `Minimum Access - API Only Integrations`, with every permission removed from the profile itself.
  - Grant object and field access only through `Salesforce API Integration` PSL-backed permission sets.
  - Never use a System Administrator user as the execution user, because the token inherits that user's rights.

  Source: https://admin.salesforce.com/blog/2023/best-practices-for-configuring-your-integration-user ; https://developer.salesforce.com/blogs/2023/03/using-the-client-credentials-flow-for-easier-api-authentication
- **Managing ECA OAuth policies.** Admins configuring ECA OAuth policies need the user permission "View all External Client Apps, view their settings, and edit their policies". Pre-authorization uses `permittedUsersPolicyType = AdminApprovedPreAuthorized` with profiles (`commaSeparatedProfile`) or permission sets (`commaSeparatedPermissionSet`). Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf ; https://help.salesforce.com/s/articleView?language=en_US&id=xcloud.preauth_user_app_access_through_eca.htm&type=5
- **Who grants what on the client side.** A Salesforce System Administrator (or a delegated admin with `Manage Users`, `Customize Application` or `Manage AI Agents`) creates the integration and agent users, assigns permission sets and PSLs, creates ECAs and enables Agentforce. A Data 360 admin assigns Data 360 permission sets. Licenses and Flex Credits are bought by the client's Salesforce account owner through the AE. Source: https://help.salesforce.com/s/articleView?id=ai.agent_setup_enable.htm&language=en_US&type=5 ; https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_user.htm&type=5
- **Data 360 permission sets.** Standard Data 360 permission sets include `Data Cloud Admin`, `Data Cloud Architect`, `Data Cloud Data Aware Specialist`, `Data Cloud Marketing Manager` and `Data Cloud User`, the last of which is assigned to service agent users. Only `Data Cloud User` was confirmed in a current source. (unverified) Source: https://help.salesforce.com/s/articleView?language=en_US&id=ai.agent_user.htm&type=5

## 4. Governance, security and compliance
- **API Access Control.** With API Access Control on (Setup > API Access Control), API access is limited to allowlisted connected apps that are installed and unblocked. Installed apps default to "Admin approved users are pre-authorized", so only users whose profile or permission set is tied to the app can use it. Some orgs must ask Salesforce Support to enable it. Source: https://help.salesforce.com/s/articleView?language=en_US&id=xcloud.security_api_access_control_all_users.htm&type=5 ; https://www.salesforceben.com/a-salesforce-admins-guide-to-auditing-connected-apps/ (secondary)
- **`Use Any API Client` permission.** It bypasses API Access Control. Since the week of 2025-12-08 it no longer lets users self-authorize uninstalled connected apps. That ability moved to the `Approve Uninstalled Connected Apps` permission (Summer '25), which Salesforce says to limit to trusted admins and developers. Source: https://help.salesforce.com/s/articleView?id=005228838&language=en_US&type=1 ; https://help.salesforce.com/s/articleView?id=xcloud.shr_use_any_api_restriction.htm&language=en_US&type=5
- **Connected app usage restrictions since September 2025.** Uninstalled connected apps were restricted to users with the new approval permission. Install-and-allowlist the agent's app before go-live, or its users get blocked. Third-party tools such as DBAmp broke in orgs with API Access Control on (reported 2025-11-04). Source: https://admin.salesforce.com/blog/2025/get-ready-for-changes-to-connected-app-usage-restrictions ; https://community.cdata.com/ideas/if-you-use-api-access-control-salesforce-change-may-stop-dbamp-on-nov-4-2025-1722 (secondary)
- **Developer Console with API Access Control.** There is a known article on Developer Console behavior when API Access Control is enabled. Check it before enabling the control in orgs where developers use Dev Console. Source: https://help.salesforce.com/s/articleView?id=005132451&language=en_US&type=1
- **Network controls.** ECA OAuth policies include IP relaxation and session/refresh-token policies (refresh-token expiry is set under App Authorization > OAuth Policies). Profile login IP ranges and org trusted IP ranges also apply. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sfdx_dev.pdf ; https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf
- **Hyperforce data residency.** Hyperforce lets customers choose the region their org runs in (examples named: U.S., U.K., Germany, India, Japan, and more). Customer data is generally stored in the org's country when the services in use are available there, though some products have components elsewhere. Hyperforce has no extra cost. Source: https://www.salesforce.com/products/platform/hyperforce/
- **EU Operating Zone.** EU Operating Zone is a paid Hyperforce offering that stores and processes EU customer data within the EU boundary, with 24/7 EU-based support. Source: https://www.salesforce.com/products/platform/hyperforce/
- **Einstein Trust Layer zero data retention.** Salesforce has zero data retention agreements with external LLM partners such as OpenAI and Azure OpenAI: prompts and responses are deleted after the response returns. Salesforce-managed models hosted inside the Salesforce trust boundary (for example Anthropic Claude) keep data inside that boundary under the same zero data retention policy. Source: https://help.salesforce.com/s/articleView?id=sf.generative_ai_trust_arch.htm&language=en_US&type=5 ; https://developer.salesforce.com/docs/ai/agentforce/guide/trust.html
- **Data masking is off for agent actions.** The Trust Layer masks detected PII with placeholders before prompts leave Salesforce and de-masks responses. Masking is disabled when an agent action calls a prompt template, and still applies to prompt templates used directly. Source: https://help.salesforce.com/s/articleView?id=ai.agent_trust_data_masking.htm&language=en_US&type=5 ; https://help.salesforce.com/s/articleView?id=sf.generative_ai_trust_arch.htm&language=en_US&type=5
- **Other Trust Layer controls.** These include dynamic grounding, toxicity detection, prompt defense and an audit trail with feedback stored in Data 360. Source: https://help.salesforce.com/s/articleView?language=en_US&id=sf.generative_ai_trust_layer.htm&type=5 ; https://developer.salesforce.com/blogs/2023/10/inside-the-einstein-trust-layer
- **Salesforce Shield.** Shield bundles Event Monitoring (80+ event types including agent actions, user and agent activity, streaming to SIEM), Platform Encryption (BYOK and externally held keys starting with AWS, covering Data 360 data), Field Audit Trail (up to 200 fields per object, up to 10 years) and Data Detect. Components can be bought separately, and pricing is quote-based. Source: https://www.salesforce.com/platform/shield/
- **Audit of AI agents.** Shield Event Monitoring tracks what data humans and AI agents access, and Salesforce positions it for securing Agentforce deployments. Agent session tracing and the Trust Layer audit trail are stored in Data 360. Source: https://www.salesforce.com/platform/shield/ ; https://help.salesforce.com/s/articleView?language=en_US&id=sf.generative_ai_trust_layer.htm&type=5
- **Compliance attestations.** Salesforce maintains a set of compliance certifications and attestations, but the portal page did not list names. Headline names commonly cited are SOC 1, SOC 2, SOC 3, ISO/IEC 27001, 27017 and 27018, PCI DSS, HIPAA-eligible, and FedRAMP (Government Cloud). (unverified) Source: https://compliance.salesforce.com/en

## 5. Commercial model
- **Flex Credits (consumption pricing for agents).** List price is USD $500 per 100,000 Flex Credits (EUR 500, GBP 400, JPY 60,000, AUD 700, SEK 5,000). A standard Agentforce action costs 20 Flex Credits (about $0.10), and an Agentforce Voice action costs 30 Flex Credits. Shown on the pricing page on 2026-11-14. Source: https://www.salesforce.com/agentforce/pricing/
- **Flex Credit metering unit.** The unit is the action ("a specific function that an AI agent executes"). Usage is tracked in near real time in Digital Wallet, which is free for customers with Digital Wallet-enabled products. Flex Credits were introduced in May 2025. Source: https://www.salesforce.com/agentforce/pricing/ ; https://www.salesforce.com/news/stories/pricing-update-2025/
- **Per-action token threshold and sandbox rate.** Third-party guides say each action includes up to 10,000 tokens and that sandbox actions cost 16 credits. Neither is on the official pricing page. (secondary) Source: https://www.jitendrazaa.com/blog/salesforce/salesforce-agentforce-credits-cost-model-complete-guide-2026/ ; https://www.eesel.ai/blog/salesforce-flex-credits
- **Per-conversation pricing.** USD $2 per conversation (EUR 2, GBP 1.60), positioned for external customer-facing agents. Conversation pricing, Agentforce add-ons and Agentforce 1 Editions are not available on the PayGo or Pre-Commit models. Help Agent Resolutions are listed at $2 (USD only). Shown 2026-11-14. Source: https://www.salesforce.com/agentforce/pricing/
- **Per-user Agentforce add-ons and licenses (list prices shown 2026-11-14).**
  - Agentforce add-ons for Sales, Service, Field Service and Operations: $125/user/month.
  - Agentforce Industries add-ons: $150/user/month.
  - `Agentforce User License`: $5/user/month. It requires Flex Credits and deploys agents company-wide with access to limited CRM objects.
  - `Agentforce Coworker User License`: $50/user/month, including 30 MB of indexing per user per month.

  Source: https://www.salesforce.com/agentforce/pricing/
- **What the add-ons include.** The Agentforce add-ons and Agentforce 1 Editions went GA on 2025-06-17, replacing Einstein add-ons and Einstein 1 Editions. The add-ons include unmetered Agentforce usage for licensed employees and Prompt Builder. Source: https://www.salesforce.com/news/stories/pricing-update-2025/
- **Flex Credits included with editions (announced 2026-09-03).** Core includes 500,000 Flex Credits, Advanced 1 million and Max 2.75 million per org per year. Max Edition is listed from $550/user/month including the Agentforce add-on. The earlier Agentforce 1 Edition included 1 million Flex Credits and 2.5 million Data Services Credits per org per year (2025-06-17). Source: https://www.salesforce.com/news/stories/salesforce-simplifies-editions-2026/ ; https://www.salesforce.com/agentforce/pricing/ ; https://www.salesforce.com/news/stories/pricing-update-2025/
- **Salesforce Foundations.** Listed at $0, including Agentforce Builder, Prompt Builder, Agent Script, Agentforce Coworker and Agentforce Vibes. Shown 2026-11-14. Source: https://www.salesforce.com/agentforce/pricing/
- **Data 360 pricing.** Flex Credits cost $500 per 100k and are interchangeable between Data 360 and Agentforce. The alternatives are Profiles at $240 per 1k profiles/year and Enterprise Profiles at $420 per 1k profiles/year. Legacy Data Services Credits remain for existing customers. Ingestion is free. Agentforce pricing examples exclude Data 360 credits. Shown 2026-11-14. Source: https://www.salesforce.com/data/pricing/ ; https://www.salesforce.com/agentforce/pricing/
- **Daily API request allocation (Limits Quick Reference, updated 2026-09-11).**
  - Enterprise Edition (and Professional with API access): 100,000 + (licenses × calls per license) + purchased API Call Add-Ons, with 1,000 calls per `Salesforce` or `Salesforce Platform` license.
  - Unlimited and Performance Edition: the same formula with 5,000 calls per license.
  - Developer Edition: 15,000.
  - Full sandbox: 5,000,000, unless created from a template.

  Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf ; https://developer.salesforce.com/docs/platform/salesforce-app-limits-cheatsheet/guide/salesforce-app-limits-platform-api.html
- **What counts against the API allocation.** It is enforced on the org-wide aggregate over 24 hours, not per user. REST, SOAP, Bulk API, Bulk API 2.0 and most Connect REST APIs count. Calls from installed managed packages count, while some Salesforce apps (for example the Salesforce mobile app) don't. Usage shows in the `Sforce-Limit-Info` header, `/services/data/vXX.X/limits` and the "API Request Limit per Month" entitlement. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf
- **Over-limit behavior.** Paid active orgs get limited soft overage up to a hard cap. Trial orgs, Developer Edition and sandboxes get none. Past the cap, calls fail with HTTP 403 `REQUEST_LIMIT_EXCEEDED`. Extra API calls can be bought in increments of 200 to 10,000 per 24 hours. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf ; https://developer.salesforce.com/blogs/2024/11/api-limits-and-monitoring-your-api-usage
- **Concurrency and timeout limits.** Concurrent long-running requests (20 seconds or longer) are capped at 25 in production orgs and sandboxes and 5 in Developer Edition and trial orgs. REST and SOAP calls time out after 10 minutes, and query calls follow SOQL limits. Source: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf
- **Shield and EU Operating Zone pricing.** Both are paid add-ons with quote-based pricing. Hyperforce itself has no added cost. Source: https://www.salesforce.com/platform/shield/ ; https://www.salesforce.com/products/platform/hyperforce/
