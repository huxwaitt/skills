# Databricks: access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Databricks renamed its platform to "Data + AI Platform".** The Databricks product name changes page lists "Data + AI Platform" as the current name, with "Databricks Data Intelligence Platform", "Data Intelligence Platform" and "Databricks Lakehouse Platform" as former names (page last updated 2026-11-10; no rename date given). Source: https://docs.databricks.com/aws/en/resources/product-name-changes
- **A Databricks account contains one or more workspaces, and only account admins create workspaces.** Workspaces are managed from the account console; with Unity Catalog enabled, identities (users, groups, service principals) are managed at the account level and account admins assign them to workspaces. Source: https://docs.databricks.com/aws/en/admin/admin-concepts
- **The account admin who creates a Databricks workspace becomes its workspace admin automatically; other account admins do not.** Other account admins have no workspace access by default but can grant themselves or others the workspace admin role on any workspace in the account. Source: https://docs.databricks.com/aws/en/admin/admin-concepts ; https://learn.microsoft.com/en-us/azure/databricks/admin/admin-concepts
- **Unity Catalog is enabled by default on newer Databricks accounts.** Accounts created after 2023-11-08 (AWS) or 2023-11-09 (Azure) might have Unity Catalog enabled by default, with an auto-created metastore per region. Source: https://docs.databricks.com/aws/en/admin/admin-concepts ; https://learn.microsoft.com/en-us/azure/databricks/admin/admin-concepts
- **Identity federation is on by default for all new Databricks workspaces since 2026-06-09.** The rollout applies to all new workspaces, including those not attached to a Unity Catalog metastore; existing workspaces are not affected. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/june
- **Databricks on AWS has two platform tiers, Premium and Enterprise; Standard tier is end-of-life.** New accounts start on Premium; remaining Standard tier workspaces were automatically upgraded to Premium on 2025-10-01; account admins upgrade to Enterprise from account console Settings. Source: https://docs.databricks.com/aws/en/admin/account-settings/account
- **Azure Databricks Premium tier corresponds to the AWS/GCP Enterprise tier.** Databricks pricing pages state that Azure's Premium tier maps to Enterprise on AWS and GCP. Source: https://www.databricks.com/product/pricing/model-serving
- **An AWS Marketplace account can be the payment method for a Databricks account.** Several AWS Marketplace accounts can link to one Databricks account, each Marketplace account links to only one Databricks account, and cancelling in AWS Marketplace only removes the payment method; contract accounts go through the Databricks account team. Source: https://docs.databricks.com/aws/en/admin/account-settings/account
- **Databricks on AWS Marketplace offers a 14-day free trial then pay-as-you-go, with private offers for custom pricing.** The AWS Marketplace listing describes up to $400 in trial credits and metering in Databricks Consumption Units (shown 2026-11-14); private offers are requested from Databricks sales. (secondary) Source: https://aws.amazon.com/marketplace/pp/prodview-wtyi5lgtce6n6
- **Databricks Free Edition accounts cannot be upgraded to the full platform.** Free Edition users must create a new account through the Databricks Free Trial sign-up. Source: https://docs.databricks.com/aws/en/admin/account-settings/account
- **On Azure, creating the first Azure Databricks workspace in an Entra ID tenant creates the Databricks account.** A Microsoft Entra ID Global Administrator must establish the first account admin by signing in at `https://accounts.azuredatabricks.net`; the account console is not available in Azure Government regions. Source: https://learn.microsoft.com/en-us/azure/databricks/admin/admin-concepts
- **Creating an Azure Databricks workspace requires the Azure RBAC Contributor or Owner role at subscription level, or a custom role.** The custom role needs `Microsoft.Databricks/workspaces/*`, `Microsoft.Databricks/accessConnectors/*`, resource group read/write and deployment permissions; Azure Contributor/Owner on the subscription also grants workspace admin on first login. Source: https://learn.microsoft.com/en-us/azure/databricks/admin/admin-concepts
- **Day-one asks for an engineer joining a Databricks engagement.** Ask for: workspace URL and account ID; a user assigned to the workspace with the needed entitlements; a dedicated Databricks service principal for the agent with OAuth secret or a workload identity federation policy; `USE CATALOG`/`USE SCHEMA`/`SELECT`/`EXECUTE` grants on the target catalog and schema; `CAN USE` on a SQL warehouse; `CAN QUERY` on serving endpoints or `EXECUTE` on Unity Gateway model services; whether user authorization (OBO) is enabled; and the network policy/ingress rules in force. (synthesis of sources in sections 2-4) Source: https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication

## 2. Identity and authentication
- **Databricks account-level SSO supports SAML 2.0 and OIDC with unified login.** With account-level SSO enabled, all users including admins sign in via SSO; up to 20 emergency access users can use username, password and security key; unified login is mandatory for accounts created after 2023-06-21 or that had not configured SSO before 2024-12-12. Source: https://docs.databricks.com/aws/en/security/auth/single-sign-on/
- **Databricks recommends automatic identity management over SCIM for syncing users and groups.** SCIM provisioning is the fallback when the IdP does not support automatic identity management; JIT provisioning creates users on first login; supported IdPs include Microsoft Entra ID, Okta, OneLogin, AWS IAM Identity Center, Keycloak and JumpCloud. Source: https://docs.databricks.com/aws/en/security/auth/single-sign-on/
- **Automatic identity management with Microsoft Entra ID is GA since 2026-05-26.** It syncs users, service principals and groups from Entra ID without SCIM. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/may
- **Automatic identity management with Okta is GA since 2026-07-03.** Public Preview began 2026-06-09; Okta is the source of truth for group memberships. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/july ; https://docs.databricks.com/aws/en/release-notes/product/2026/june
- **Account access denylist for automatic identity management is in Public Preview since 2026-05-22 (AWS and GCP).** Account admins can block users, groups or service principals from the account; denying a group blocks its members. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/may
- **SCIM provisioning cannot sync service principals; Entra ID service principals sync via automatic identity management.** Source: https://docs.databricks.com/aws/en/admin/users-groups/service-principals
- **A Databricks service principal is an API-only identity for automation.** Account admins add service principals to the account and assign them to workspaces; workspace admins can also add them; the creator becomes a service principal manager. Source: https://docs.databricks.com/aws/en/admin/users-groups/service-principals
- **Databricks service principals have two roles: `Service principal manager` and `Service principal user`.** Managers manage roles on the service principal (account admins hold it on all service principals); the user role lets someone run jobs as the service principal and is not inherited by managers; workspace admins can create tokens for a service principal only if they also hold the user role. Source: https://docs.databricks.com/aws/en/admin/users-groups/service-principals
- **Databricks recommends OAuth token federation as the preferred authentication method.** The auth overview lists OAuth token federation (recommended), OAuth M2M for service principals, and OAuth U2M for users; PATs are labelled legacy. Source: https://docs.databricks.com/aws/en/dev-tools/auth/ ; https://docs.databricks.com/aws/en/dev-tools/auth/pat
- **Databricks unified authentication uses `DATABRICKS_HOST`, `DATABRICKS_ACCOUNT_ID`, `DATABRICKS_CLIENT_ID` and `DATABRICKS_CLIENT_SECRET`.** Databricks recommends a configuration profile in `.databrickscfg` instead of manually set environment variables. Source: https://docs.databricks.com/aws/en/dev-tools/auth/
- **Databricks OAuth M2M access tokens last one hour.** The workspace token endpoint is `https://<databricks-instance>/oidc/v1/token`, the account endpoint is `https://accounts.cloud.databricks.com/oidc/accounts/<account-id>/v1/token`, the grant is `grant_type=client_credentials&scope=all-apis`, and the response has `expires_in: 3600`. Source: https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m
- **A Databricks service principal can have at most five OAuth secrets, each valid up to 730 days.** Account admins and workspace admins can create secrets; the secret is shown only once; a secret without scopes gets `all-apis`. Source: https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m
- **Unused Databricks service principal OAuth secrets are auto-deleted after 90 days since 2026-09-16.** Source: https://docs.databricks.com/aws/en/release-notes/product/2026/september ; https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m
- **Databricks service principal OAuth secrets can be restricted to API scopes since 2026-08-29.** Scopes such as `sql`, `jobs` or `unity-catalog` cannot be changed after generation; a secret with the `authentication` scope can create tokens with any scope. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/august ; https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m
- **OAuth on-behalf-of for Databricks service principals is GA and on by default since 2026-11-12.** A user holding the `Service Principal Manager` role can use the standard U2M flow to act as that service principal without creating an OAuth secret; it was Beta from 2026-05-20. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/november ; https://docs.databricks.com/aws/en/release-notes/product/2026/may
- **OAuth device code flow for headless machines is in Beta since 2026-10-30.** It issues a workspace-level OAuth token after browser sign-in on another device; admins enable it on the Previews page. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october
- **OAuth custom identity claims let one Databricks service principal filter data per end user (announced 2026-10-19).** A custom claim added to the service principal's OAuth token can drive row filtering. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october
- **Default OAuth apps for external AI agents are GA since 2026-10-27.** ChatGPT, Codex, Claude, Claude Code and Cursor connect to Databricks MCP servers with default OAuth client IDs, so an account admin does not need to create an OAuth app. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october
- **Databricks OAuth token federation has two forms: account-wide token federation and workload identity federation.** Account-wide federation lets all users and service principals exchange IdP JWTs for Databricks OAuth tokens; workload identity federation lets an external workload authenticate as a specific Databricks service principal via a federation policy, with no Databricks secret. Source: https://docs.databricks.com/aws/en/dev-tools/auth/oauth-federation
- **Databricks workload identity federation supports GitHub Actions, Azure DevOps, GitLab CI/CD, CircleCI, AWS IAM workloads, Jenkins, Terraform Cloud and Bitbucket Pipelines.** Source: https://docs.databricks.com/aws/en/dev-tools/auth/oauth-federation-provider
- **GitHub Actions federation uses issuer `https://token.actions.githubusercontent.com` and `DATABRICKS_AUTH_TYPE=github-oidc`.** Create the policy with `databricks account service-principal-federation-policy create <SP_NUMERIC_ID>`, grant `id-token: write`, set `DATABRICKS_HOST` and `DATABRICKS_CLIENT_ID`; audience defaults to the account ID; GitHub repos created, renamed or transferred on or after 2026-07-15 use numeric-ID subjects such as `repo:org@123/repo@456:environment:prod`. Source: https://docs.databricks.com/aws/en/dev-tools/auth/provider-github
- **Databricks PATs are scoped to one workspace and cannot automate account-level APIs.** A user can create up to 600 PATs per workspace; PATs unused for 90 days are revoked automatically. Source: https://docs.databricks.com/aws/en/dev-tools/auth/pat
- **New Databricks PATs default to a 730-day maximum lifetime, set by `maxTokenLifetimeDays`.** Databricks recommends lifetimes under 90 days; the setting applies only to new tokens; users get expiry email about seven days ahead. Source: https://docs.databricks.com/aws/en/admin/access-control/tokens
- **Databricks workspace admins can disable PAT authentication per workspace.** PATs are enabled by default; disabling blocks PAT auth and creation but does not delete tokens; Partner Connect and some partner integrations need PATs; managing PATs requires Premium or above; account admins can review and revoke tokens in the account console Token report. Source: https://docs.databricks.com/aws/en/admin/access-control/tokens
- **Databricks PATs support API scopes and (Preview) auto-scoping.** `POST /api/2.0/token/create` accepts a `scopes` array (empty array means full access; literal `all-apis` is rejected) and `autoscope_enabled`; auto-scoping narrows a token to observed APIs after 30 days and is a workspace preview; list scopes with `GET /api/2.0/token-scopes`. Source: https://docs.databricks.com/aws/en/dev-tools/auth/pat
- **Expiring service principal token emails are GA since 2026-07-22.** Workspace admins are emailed when a service principal token with a lifetime over seven days, used at least once, expires within seven days. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/july
- **Databricks has no separate "agent identity" type; an agent's runtime identity is a Databricks service principal.** On Databricks Apps, each app gets a dedicated, non-shareable service principal that is deleted with the app, and its credentials are injected as `DATABRICKS_CLIENT_ID` and `DATABRICKS_CLIENT_SECRET`. Source: https://docs.databricks.com/aws/en/dev-tools/databricks-apps/auth ; https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication
- **Databricks recommends deploying new agents on Databricks Apps rather than Model Serving.** Apps give full control over code, server configuration and deployment, and support more OBO scopes. Source: https://docs.databricks.com/aws/en/agents/custom-agents/model-serving/agent-authentication-model-serving
- **Agents on Databricks Apps use "App authorization" (default) or "User authorization" (Public Preview).** App authorization was formerly called service principal auth; User authorization was formerly on-behalf-of-user (OBO), must be enabled by a workspace admin, and receives the downscoped user token in the `x-forwarded-access-token` header; both can be combined in one agent. Source: https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication
- **Databricks Apps user authorization requires declared scopes such as `sql`, `genie`, `files`, `model-serving` and `ai-gateway`.** Defaults are `iam.access-control:read` and `iam.current-user:read`; scopes are set in `user_api_scopes`; workspace admins control the allowlist via `allowedAppsUserApiScopes` (default `*`; empty array disables user authorization); scope changes take up to 5 minutes; existing apps must restart after first enablement. Source: https://docs.databricks.com/aws/en/dev-tools/databricks-apps/auth ; https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication
- **Agents on Model Serving use automatic authentication passthrough, on-behalf-of-user (Public Preview) or manual credentials.** Passthrough runs with the deployer's permissions using short-lived credentials for resources declared via the `resources` parameter of `log_model()`; Databricks recommends passthrough where possible; manual auth passes long-lived credentials through environment variables. Source: https://docs.databricks.com/aws/en/agents/custom-agents/model-serving/agent-authentication-model-serving
- **Model Serving OBO is disabled by default, needs a workspace admin to enable it, and requires MLflow 2.22.1 or later.** Declare scopes with MLflow `AuthPolicy`/`UserAuthPolicy(api_scopes=[...])` (e.g. `model-serving`, `ai-search`) and create clients inside `predict` with `WorkspaceClient(credentials_strategy=ModelServingUserCredentials())` from `databricks_ai_bridge`; UC Volumes are not supported. Source: https://docs.databricks.com/aws/en/agents/custom-agents/model-serving/agent-authentication-model-serving
- **Lakebase Postgres accepts a one-hour Databricks OAuth token as the Postgres password.** Each identity needs a Postgres role created with the `databricks_auth` extension; tokens are workspace-scoped, need SSL, and are generated with the CLI `generate-database-credential` or SDKs; native Postgres password auth is off by default for new projects; the PgBouncer pooler does not support OAuth. Source: https://docs.databricks.com/aws/en/oltp/projects/authentication

## 3. Roles and permissions
- **Databricks admin roles are `Account admin`, `Workspace admin`, `Metastore admin`, `Marketplace admin` and `Billing admin`.** Account admin manages workspaces, cloud resources, identities, settings and subscriptions; workspace admin manages one workspace's identities and compute; metastore admin manages privileges and ownership in a Unity Catalog metastore; marketplace admin manages the Marketplace provider profile; billing admin views budgets and manages serverless usage policies. Source: https://docs.databricks.com/aws/en/admin/admin-concepts
- **Databricks workspace admins are members of the reserved `admins` system group.** In identity-federated workspaces a directly assigned group can be added to `admins`. Source: https://learn.microsoft.com/en-us/azure/databricks/admin/admin-concepts
- **The Unity Catalog metastore admin role is optional for workspaces created after 2023-11-08, and auto-enabled metastores have none.** Workspace admins get metastore-level create privileges via the system group `_workspace_admins_<workspace_name>_<workspace_id>` and own the workspace catalog; a metastore admin is still needed to change ownership of objects you don't own; Databricks recommends assigning the role to a group. Source: https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/admin-privileges
- **Unity Catalog securable hierarchy is metastore > catalog > schema > objects.** Schema objects include tables, views, materialized views, volumes, functions, models, features, flows and secrets; external locations, storage/service credentials, connections, services, shares and clean rooms sit outside the schema tree. Source: https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges
- **Reading a Unity Catalog table requires `SELECT` on the table plus `USE CATALOG` and `USE SCHEMA` on its parents.** `SELECT` can be inherited from a schema or catalog grant; `USE CATALOG`/`USE SCHEMA` grant no data access by themselves. Source: https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges
- **Calling a Unity Catalog function or registered model requires `EXECUTE` plus `USE CATALOG` and `USE SCHEMA`.** Models are a type of function; `EXECUTE` on a model also allows viewing version metadata and downloading model files. Source: https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges
- **Other Unity Catalog privileges relevant to agents include `READ VOLUME`, `WRITE VOLUME`, `USE CONNECTION`, `ACCESS` (service credentials), `BROWSE`, `READ METADATA`, `CREATE SERVICE`, `CREATE SECRET`, `MANAGE` and `MANAGE ACCESS CONTROL`.** `ALL PRIVILEGES` excludes `MANAGE`, `READ METADATA`, `EXTERNAL USE SCHEMA` and `EXTERNAL USE LOCATION`; fine-grained `INSERT`/`UPDATE`/`DELETE` are Beta; `EXTERNAL USE SCHEMA` is Preview. Source: https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges
- **Unity Catalog secrets support `BROWSE` and up to 1,000 secrets per schema (announced 2026-11-02).** `BROWSE` on a catalog exposes secret metadata without values. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/november
- **Databricks workspace object permission levels.** Serving endpoints: `CAN VIEW`, `CAN QUERY`, `CAN MANAGE`; SQL warehouses: `CAN VIEW`, `CAN MONITOR`, `CAN USE`, `IS OWNER`, `CAN MANAGE`; Genie Agents: `CAN VIEW`, `CAN RUN`, `CAN EDIT`, `CAN MANAGE`; jobs: `CAN VIEW`, `CAN MANAGE RUN`, `IS OWNER`, `CAN MANAGE`; secret scopes: `READ`, `WRITE`, `MANAGE`; AI Search endpoints and Lakebase projects: `CAN CREATE`, `CAN USE`, `CAN MANAGE`. Source: https://docs.databricks.com/aws/en/security/auth/access-control/
- **Databricks Apps permissions are `CAN USE` and `CAN MANAGE`.** `CAN MANAGE` is needed to edit app settings and scopes. Source: https://docs.databricks.com/aws/en/dev-tools/databricks-apps/auth
- **Least-privilege grants for an agent on Databricks Apps (app authorization).** SQL warehouse `Can Use`; Model Serving endpoint `Can Query`; UC function `Can Execute`; Genie Agent `Can Run`; AI Search index `Can Select`; UC table `SELECT`; UC connection `Use Connection`; UC volume `Can Read`/`Can Read and Write`; Lakebase `Can Connect and Create`; MLflow experiment `Can Edit`; use a dedicated service principal per app. Source: https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication
- **Automatic authentication passthrough on Model Serving supports declared resources with minimum MLflow versions.** SQL warehouse `Use Endpoint` (2.16.1), serving endpoint `Can Query` (2.13.1), UC function `EXECUTE` (2.16.1), Genie Agent `Can Run` (2.17.1), AI Search index `Can Use` (2.13.1), UC table `SELECT` (2.18.0), UC connection `Use Connection` (2.17.1), Lakebase `databricks_superuser` (3.3.2); not supported for Unity Gateway model services. Source: https://docs.databricks.com/aws/en/agents/custom-agents/model-serving/agent-authentication-model-serving
- **Granting an agent a Genie Agent also requires grants on its dependencies.** The identity needs access to the Genie Agent's underlying tables, SQL warehouses and UC functions; workspace MCP endpoints need access to every index and function in the referenced schemas; MCP Services need `EXECUTE` plus `USE CATALOG` and `USE SCHEMA`. Source: https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication
- **Querying a Unity Gateway model service requires `EXECUTE` on the service plus `USE CATALOG` and `USE SCHEMA`; all account users have `EXECUTE` on `system.ai` by default.** Queries are evaluated against the service owner's privileges, so the owner must keep `EXECUTE` on every destination including fallbacks; restrict access by revoking the account users group's schema-level grant on `system.ai`; managing `system.ai` needs metastore admin or `MANAGE`. Source: https://docs.databricks.com/aws/en/ai-gateway/govern-model-services
- **Databricks workspace entitlements are `workspace-consume`, `workspace-access`, `databricks-sql-access`, `allow-cluster-create` and `allow-instance-pool-create`.** Consumer access lets a user view shared dashboards, Genie Agents and Apps, query Unity Gateway services and query SQL warehouses from BI tools, but not create Unity Gateway assets. Source: https://docs.databricks.com/aws/en/security/auth/entitlements
- **From 2026-06-15 the Databricks `users` group is being changed to carry no entitlements.** New principals receive only the entitlements selected when they are added, instead of inheriting `workspace-access` and `databricks-sql-access` from `users`. Source: https://docs.databricks.com/aws/en/security/auth/entitlements
- **Consumer access to query Unity Gateway services is GA since 2026-10-15.** Users with the consumer access entitlement no longer need an account admin to enable a preview; admins can apply budgets and rate limits. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october
- **Databricks RBAC (assumable roles) is GA since 2026-08-19.** Public Preview began 2026-07-22; a role is a group with the `Assume` permission; while acting as a role only the role's permissions apply; an account admin enables RBAC for the account, then workspace admins per workspace; audit logs record `run_by` and `run_as`. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/august ; https://docs.databricks.com/aws/en/security/auth/rbac/
- **A Databricks service principal or agent can get a role-scoped OAuth token by adding `assume_group=<group-id>` to the workspace token request.** Account-level token requests do not support role assumption; both the service principal and role must be assigned to the workspace; users can pick a role at `databricks auth login`. Source: https://docs.databricks.com/aws/en/security/auth/rbac/switch-roles
- **ABAC policies can check the calling OAuth application and whether a request is on behalf of a user (Beta, 2026-08-21).** This can restrict what an agent reads on a user's behalf; identity attributes from the IdP for ABAC column masks are Beta since 2026-08-13. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/august
- **ABAC DENY policies cover AI securables (model, MCP, agent and skill services) in Beta since 2026-11-12.** Source: https://docs.databricks.com/aws/en/release-notes/product/2026/november
- **Serverless usage policies (formerly serverless budget policies) tag serverless usage for cost attribution.** Workspace admins create them; permissions are `User` and `Manager`; account-wide view needs `Billing admin`; tags land in `custom_tags` of `system.billing.usage`; covers notebooks, jobs, Lakeflow pipelines, model serving, Lakebase Autoscaling and Apps. Source: https://docs.databricks.com/aws/en/admin/usage/budget-policies ; https://docs.databricks.com/aws/en/resources/product-name-changes
- **Budget access can be delegated with the `Budget Manager` and `Budget Viewer` roles (announced 2026-10-16).** Account and workspace admins grant them to users, groups or service principals. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october

## 4. Governance, security and compliance
- **AI Gateway is now named Unity Gateway.** Former names are AI Gateway, Unity AI Gateway and Mosaic AI Gateway; Unity Gateway is GA since 2026-08-04, while service policies and agent services remain Beta. Source: https://docs.databricks.com/aws/en/resources/product-name-changes ; https://docs.databricks.com/aws/en/release-notes/product/2026/august
- **Unity Gateway governs models, agents, MCP servers and tools as Unity Catalog securables.** Features: rate limits, traffic splitting, fallbacks, Smart Routing, per-user budgets, service policies (guardrails), MCP tool filtering (built-in `system.ai.github_policy`), usage tracking and inference tables; it fronts Foundation Model APIs in `system.ai`, BYOK external providers, custom model services, MCP tools, UC functions and HTTP connections. Source: https://docs.databricks.com/aws/en/ai-gateway/
- **Unity Gateway API and developer tools are GA since 2026-09-16, and the `ug` CLI for coding agents shipped 2026-09-22.** The API manages model services, model provider services and MCP services via Terraform, CLI and SDKs; `ug` connects Claude Code, Codex and similar tools. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/september
- **Unity Gateway guardrails include partner guardrails via external service policies (Beta, 2026-10-07) and a Jailbreak guardrail for MCP tool calls (Beta, 2026-10-21).** Custom service policies can require request tags (Beta, 2026-10-09) and can be written in Python (Beta, 2026-11-11, select regions). Source: https://docs.databricks.com/aws/en/release-notes/product/2026/october ; https://docs.databricks.com/aws/en/release-notes/product/2026/november
- **Legacy AI Gateway guardrails on serving endpoints use Llama Guard for safety and Presidio for PII.** Older docs state output guardrails are not supported for embeddings or streaming, and guardrails/fallbacks are not supported on custom model endpoints; up to 20 rate limits (5 group-specific) per endpoint as QPM/TPM. (unverified against the current Unity Gateway docs) Source: https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints
- **Unity Gateway usage is recorded in system tables.** `system.ai_gateway.usage` (Public Preview) holds request/response details, tokens, latency and routing; `system.ai_gateway.external_model_spend` (Beta) estimates external model spend; `system.serving.endpoint_usage` and `system.serving.served_entities` (Public Preview) cover serving endpoints; default retention is 395 days. Source: https://docs.databricks.com/aws/en/admin/system-tables/
- **Databricks audit logs are in `system.access.audit` (Public Preview, 395-day retention).** Access requires account admin plus metastore admin by default, or grants of `USE CATALOG` on `system` and `USE SCHEMA`/`SELECT` on the schemas; billing data is in `system.billing.usage` and `system.billing.list_prices` (indefinite retention); configurable retention 30-3,650 days is Beta via `st_retention`. Source: https://docs.databricks.com/aws/en/admin/system-tables/

- **Databricks serverless egress control uses account-level network policies with Full Access or Restricted Access mode.** Requires Enterprise tier; one policy per workspace; Restricted Access allows UC external locations, listed FQDNs and S3 buckets and same-workspace APIs; supports dry-run mode; covers notebooks, jobs, SQL warehouses, Lakeflow pipelines, Model Serving and Databricks Apps (limited); external model providers and MCP servers must be added as allowed destinations. Source: https://docs.databricks.com/aws/en/security/network/serverless-network-security/network-policies
- **Blocking specific internet destinations in Databricks network policies is in Public Preview since 2026-06-23.** Blocks apply via the network policies REST API regardless of access mode. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/june
- **Databricks context-based ingress control is GA since 2026-07-21.** Account admins write allow/deny rules combining identity, request type (workspace UI, API, Apps runtime, Lakebase runtime), source IP, private endpoints and partner platforms; requires Enterprise tier; IP access lists are ANDed with ingress policies; account-level policies and cross-workspace access are Beta. Source: https://docs.databricks.com/aws/en/security/network/front-end/context-based-ingress ; https://docs.databricks.com/aws/en/release-notes/product/2026/july
- **ChatGPT and Claude can be allowed as partner platforms in context-based ingress policies (announced 2026-11-10).** Databricks maintains their IP ranges so hosted MCP clients can be allowed without tracking IPs. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/november
- **Databricks network connectivity configurations (NCCs) are account-level regional objects that manage serverless private endpoints.** Account admins create NCCs and attach them to workspaces in a region; private endpoints are charged per hour and per GB processed; the legacy stable IP list was decommissioned. Source: https://docs.databricks.com/aws/en/security/network/serverless-network-security/

Source: https://docs.databricks.com/aws/en/security/network/ ; https://docs.databricks.com/aws/en/release-notes/product/2026/october ; https://docs.databricks.com/aws/en/release-notes/product/2026/july ; https://docs.databricks.com/aws/en/release-notes/product/2026/august
- **Private connectivity on Azure: front-end and back-end Azure Private Link, VNet injection, secure cluster connectivity, and serverless private endpoints via NCC.** Serverless can reach Azure Storage, SQL Database and VNet resources through private endpoint rules. Source: https://docs.databricks.com/aws/en/databricksiq/databricksiq-trust

## 5. Commercial model
- **Databricks bills consumption in Databricks Units (DBUs) at per-second granularity, pay-as-you-go or under committed-use contracts.** Prices vary by cloud, region and tier; storage and networking are billed separately; Azure Databricks is billed through the Azure subscription. Source: https://www.databricks.com/product/pricing
- **Foundation Model APIs bill pay-per-token as DBUs per million tokens, with priority pay-per-token and provisioned throughput options.** Shown 2026-11-14: example SKU price $0.07/DBU (AWS us-east-1), e.g. Llama 3.3 70B 7.143 input / 21.429 output DBU per 1M tokens; provisioned throughput is DBU per hour per 50 model units with on-demand, 1-month and 3-month reservations; priority tier is requested with `service_tier: "priority"`. Source: https://www.databricks.com/product/pricing/foundation-model-serving ; https://docs.databricks.com/aws/en/machine-learning/foundation-models/
- **Model Serving GPU endpoints bill DBUs per hour by GPU type.** Shown 2026-11-14: e.g. A10G 1 GPU 20.00 DBU/h, H100 1 GPU 100.00 DBU/h, H100 8 GPU 800.00 DBU/h. Source: https://www.databricks.com/product/pricing/model-serving
- **Databricks Apps bill DBUs per hour by compute size.** Medium (2 vCPU, 6 GB) 0.5 DBU/h default; Large (4 vCPU, 12 GB) 1 DBU/h; XLarge (12 vCPU, 48 GB) 3 DBU/h in some regions. Source: https://docs.databricks.com/aws/en/dev-tools/databricks-apps/compute-size
- **Genie Agents, Genie Code and Genie One moved to pay-as-you-go DBU billing on 2026-07-08.** Users get 150 free DBUs of LLM usage per month; user usage of Genie One and Genie Agents is free through 2027-01-31, but service principal usage is excluded from the promotion and billed; Genie Code usage above 150 DBUs gets a 25% discount through 2027-01-31. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/july ; https://docs.databricks.com/aws/en/release-notes/product/2026/august ; https://docs.databricks.com/aws/en/genie/
- **Databricks budgets are GA since 2026-07-06, including Unity Gateway budgets with per-user thresholds and blocking.** External provider spend (Amazon Bedrock, Azure AI Foundry) can be tracked and capped since 2026-08-28 via "External Model Spend in Budgets" (Beta); AI Functions usage counts toward Unity Gateway budgets since 2026-11-01; budget alert webhooks are Beta since 2026-11-10; a Spend Status API shipped 2026-10-26. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/july ; https://docs.databricks.com/aws/en/release-notes/product/2026/august ; https://docs.databricks.com/aws/en/release-notes/product/2026/november ; https://docs.databricks.com/aws/en/release-notes/product/2026/october
- **Unity Gateway can apply a price multiplier to external model spend estimates (announced 2026-09-19).** It reflects negotiated provider rates for model provider services only. Source: https://docs.databricks.com/aws/en/release-notes/product/2026/september
- **Undiscounted per-SKU list prices are published in the Databricks Price List and in `system.billing.list_prices`.** Source: https://www.databricks.com/product/pricing ; https://docs.databricks.com/aws/en/admin/system-tables/
