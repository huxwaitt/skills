# OpenAI: capabilities, connectivity, CLIs, docs, limits (as of 2026-11-14)

## 6. AI and agent capabilities
- **OpenAI flagship API models are the GPT-6 family.** The models page lists `gpt-6-astra` (most capable, recommended default), `gpt-6.1-sol` (near-Astra at lower cost), `gpt-6.1-terra` (fast; visual reasoning, computer use, writing) and `gpt-6-luna` (most efficient, high volume); knowledge cutoffs Apr 30 2026 (Astra, Sol), Jun 1 2026 (Terra) and May 18 2026 (Luna). Source: https://developers.openai.com/api/docs/models
- **OpenAI GPT-6 release dates.** Per the API changelog, GPT-6 Astra shipped 2026-09-03, GPT-6 Sol and GPT-6 Luna 2026-09-22, GPT-6.1 Sol 2026-09-29 (with Multi-agent in beta) and GPT-6.1 Terra 2026-10-26. Source: https://developers.openai.com/api/docs/changelog
- **OpenAI specialized API models.** Cyber models are `gpt-6-cyber` and `gpt-5.6-cyber`, for authorized security work. Image models are `gpt-image-2.6-sunburst`, `gpt-image-2.6-flare`, `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare`. Realtime speech models are `gpt-live-1`, `gpt-realtime-2.1`, `gpt-realtime-2.1-mini`, `gpt-realtime-2`, `gpt-realtime-translate` and `gpt-realtime-1.5`. Transcription models are `gpt-transcribe`, `gpt-live-transcribe` and `gpt-realtime-whisper`. GPT-Rosalind (life sciences) is limited to approved organizations. Source: https://developers.openai.com/api/docs/models
- **OpenAI deprecations already past their shutdown date.** `gpt-4.5-preview` shut down 2025-07-14. `o1-mini` shut down 2025-10-27. `codex-mini-latest` shut down 2026-02-12. `chatgpt-4o-latest` shut down 2026-02-17. `gpt-4-0314` and `gpt-4-0125-preview` shut down 2026-03-26. The `gpt-4o-realtime-preview`, `gpt-4o-audio-preview` and mini variants shut down 2026-05-07. `dall-e-2` and `dall-e-3` shut down 2026-05-12. Source: https://developers.openai.com/api/docs/deprecations
- **OpenAI 2026-07-23 shutdowns.** `computer-use-preview`, `gpt-4o-search-preview`, `gpt-5.1-codex-mini`, `gpt-5-codex`, `gpt-5.1-codex`, `gpt-5.1-codex-max`, `gpt-5.2-codex`, `gpt-5-chat-latest`, `gpt-5.1-chat-latest`, `o3-deep-research` and `o4-mini-deep-research` shut down 2026-07-23 (notice 2026-04-22). Source: https://developers.openai.com/api/docs/deprecations
- **OpenAI shutdowns from August to October 2026.** `gpt-5.2-chat-latest` and `gpt-5.3-chat-latest` shut down 2026-08-10. Videos API with `sora-2` and `sora-2-pro` shut down 2026-09-24, with no one-to-one replacement. `gpt-3.5-turbo-instruct`, `babbage-002` and `davinci-002` shut down 2026-09-28. `gpt-5.4-cyber` shut down 2026-10-01. The `gpt-3.5-turbo`, `gpt-4`, `gpt-4-turbo`, `gpt-4o-2024-05-13`, `gpt-4.1-nano`, `gpt-image-1`, `o1`, `o1-pro`, `o3-mini` and `o4-mini` families shut down 2026-10-23. Source: https://developers.openai.com/api/docs/deprecations
- **OpenAI upcoming shutdowns, late 2026.** `/v1/prompts` (reusable prompt objects), the Evals platform and Agent Builder shut down 2026-11-30. `gpt-image-1-mini`, `gpt-image-1.5` and `chatgpt-image-latest` shut down 2026-12-01. `gpt-5`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5-pro`, `o3` and `o3-pro` shut down 2026-12-11; replacements are `gpt-6.1-sol`, `gpt-6.1-terra` and `gpt-6-luna`. Source: https://developers.openai.com/api/docs/deprecations
- **OpenAI upcoming shutdowns, 2027.** Self-serve fine-tuning job creation ends 2027-01-06. `tts-1`, `tts-1-hd` and `gpt-4o-mini-tts` shut down 2027-01-06. `gpt-4o-2024-08-06`, `gpt-4o-2024-11-20`, `gpt-4o-mini-2024-07-18`, `gpt-4.1-2025-04-14` and `gpt-4.1-mini-2025-04-14` shut down 2027-01-14, replaced by `gpt-6-luna`. `gpt-realtime`, `gpt-audio` and `gpt-realtime-mini` shut down 2027-01-20. `gpt-image-2` shuts down 2027-02-10. `whisper-1`, the `gpt-4o-*-transcribe` models and `/v1/audio/translations` shut down 2027-02-26. `gpt-5.1`, `gpt-5.3-codex` and `gpt-5.4-nano` shut down 2027-04-01. Source: https://developers.openai.com/api/docs/deprecations
- **OpenAI Responses API is the recommended API.** The migration guide states "While Chat Completions remains supported, Responses is recommended for all new projects". Responses are stored by default (30-day TTL); `store: false` disables storage and is enforced for Zero Data Retention organizations. Source: https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://developers.openai.com/api/docs/guides/conversation-state
- **OpenAI Chat Completions API is still supported.** Chat Completions is still an API status page component and a supported Batch endpoint. Chat Completions requests are stored by default for new accounts. Source: https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://status.openai.com/
- **OpenAI Assistants API is shut down.** It was deprecated 2025-08-26 and sunset 2026-08-26, and is "no longer available". The replacement is the Responses API plus the Conversations API. Source: https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://developers.openai.com/api/docs/deprecations
- **OpenAI Conversations API holds durable conversation state.** It was released 2025-08-20. A conversation object stores items (messages, tool calls, tool outputs). You pass its ID as the `conversation` parameter on Responses calls. Conversation items are not subject to the 30-day response TTL. The alternatives are chaining with `previous_response_id` (prior input tokens are still billed) or manual replay. Source: https://developers.openai.com/api/docs/guides/conversation-state ; https://developers.openai.com/api/docs/changelog
- **OpenAI Responses compaction.** Client-side compaction uses `/responses/compact` (added 2025-12-11). Server-side compaction uses `context_management` with `compact_threshold` on `/responses` (launched 2026-02-10, together with Skills and the Hosted Shell tool). Source: https://developers.openai.com/api/docs/guides/conversation-state ; https://developers.openai.com/api/docs/changelog
- **OpenAI Responses built-in tools.** The tools guide lists web search (`web_search`), file search (`file_search`), tool search (`tool_search`, requires gpt-5.4 or later), remote MCP (`mcp`), function calling (`function`), Shell, Skills, computer use, image generation and Programmatic Tool Calling. It gives no per-tool GA/beta status. Source: https://developers.openai.com/api/docs/guides/tools
- **OpenAI Responses features added in 2026.** WebSocket mode for Responses launched 2026-02-23. GPT-5.6 (2026-07-09) brought Programmatic Tool Calling and Multi-agent orchestration (beta). GPT-6 Astra (2026-09-03) brought async tool calling and mid-turn steering controls. Ultrafast mode for GPT-6.1 Sol arrived 2026-10-08. 12-hour prompt caching arrived 2026-10-20. Source: https://developers.openai.com/api/docs/changelog
- **OpenAI code interpreter tool.** The type is `code_interpreter`. The container is `{"type":"auto"}` with `memory_limit` `1g` (default), `4g`, `16g` or `64g`, or an explicit container created through `/v1/containers`. A container expires after 20 minutes idle and cannot be reactivated. Source: https://developers.openai.com/api/docs/guides/tools-code-interpreter
- **OpenAI computer use tool.** It is enabled with `tools: [{type: "computer"}]` and emits `computer_call`, `computer_call_output` and `computer_screenshot` items. Examples use `gpt-6.1-sol`. For `gpt-6-astra` OpenAI recommends code execution, with `computer` still supported. Environments are self-run (SDK `ComputerToolset`), partners (Browserbase, Browser Use, Daytona, E2B Desktop) or an OpenAI-hosted browser via the Agents API. Source: https://developers.openai.com/api/docs/guides/tools-computer-use
- **OpenAI file search and vector stores.** The tool is `{"type":"file_search","vector_store_ids":[...]}` with optional `max_num_results` and metadata `filters`. Add `include: ["file_search_call.results"]` to return the raw results. Files must reach status `completed` (indexed) before they are searchable. The file search rate limit is 500 RPM on Build and 1000 RPM on Launch/Grow. Source: https://developers.openai.com/api/docs/guides/tools-file-search
- **OpenAI background mode.** Set `background: true` on Responses, then poll while the status is `queued` or `in_progress`, or cancel via the cancel endpoint. Use `background` together with `stream` to resume streams with `starting_after` (a `sequence_number` cursor). ZDR projects still keep background response data on disk for about 10 minutes. Source: https://developers.openai.com/api/docs/guides/background
- **OpenAI Agents API is a hosted agent runtime (public beta).** It launched in public beta 2026-09-10 at `https://api.openai.com/v1/agents` (for example `POST /v1/agents/sessions`) and requires the `OpenAI-Beta: agents=v1` header. OpenAI describes it as a managed Codex harness with compaction, multi-agent, programmatic tool calling and MCP. Environments are `openai_hosted`, `self_hosted` or `none`. Computer use was added 2026-09-29 and scheduled automations 2026-10-23. Source: https://developers.openai.com/api/docs/guides/agents-api/quickstart ; https://developers.openai.com/api/docs/changelog ; https://developers.openai.com/api/docs/guides/agents
- **OpenAI Agents API data handling.** Data residency is US-only. The Agents API does not support Zero Data Retention, even with a self-hosted sandbox. `multi_agent.max_concurrent_subagents` caps parallel subagents. The OpenAI-hosted sandbox is billed at container rates. Source: https://developers.openai.com/api/docs/guides/agents-api/tools
- **OpenAI Agents SDK (Python) primitives.** The package is `openai-agents` (`pip install openai-agents`; version 0.24.0 on PyPI; Python >=3.10). Primitives are agents, handoffs and agents-as-tools, guardrails (input/output), sessions (memory), tracing, sandbox agents, MCP tools, realtime agents (`gpt-realtime-2.1`) and voice pipelines. It uses the Responses API by default. Source: https://openai.github.io/openai-agents-python/ ; https://pypi.org/pypi/openai-agents/json
- **OpenAI Agents SDK (TypeScript) packages.** `@openai/agents` (0.22.0 on npm) depends on `@openai/agents-core`, `@openai/agents-openai` and `@openai/agents-realtime`. The realtime entry point is `@openai/agents/realtime` (`RealtimeAgent`, `RealtimeSession`, WebRTC/WebSocket transports). MCP classes are `MCPServerStdio`, `MCPServerSSE` and `MCPServerStreamableHttp`. Source: https://openai.github.io/openai-agents-js/ ; https://registry.npmjs.org/@openai/agents/latest
- **OpenAI Agents SDK sandbox agents.** `SandboxAgent` (Python and TS) runs in an isolated workspace defined by a `Manifest`, with the capabilities `Shell`, `Filesystem`, `Skills`, `Memory` and `Compaction`. Clients include `UnixLocalSandboxClient`, `DockerSandboxClient`, `E2BSandboxClient`, `ModalSandboxClient` and `DaytonaSandboxClient`, plus Blaxel, Cloudflare, Databricks and Vercel. Source: https://developers.openai.com/api/docs/guides/agents/sandboxes
- **OpenAI Agent Builder (AgentKit) is deprecated.** It launched at DevDay 2025-10-06 with ChatKit, deprecation was announced 2026-06-03, and shutdown is 2026-11-30. To migrate, export the workflow code (the "Code" button) to the Agents SDK, or move to ChatGPT Workspace Agents. Source: https://developers.openai.com/api/docs/guides/agent-builder ; https://developers.openai.com/api/docs/deprecations
- **OpenAI ChatKit remains available.** It is an embeddable chat UI. Packages are `@openai/chatkit-react`, chatkit-js and chatkit-python. The recommended path for new work is a self-hosted ChatKit server (Python SDK) backed by any agent service, for example the Agents SDK. Agent Builder-hosted workflows (by workflow ID) are supported only through the transition. Source: https://developers.openai.com/api/docs/guides/chatkit
- **OpenAI Evals platform is deprecated.** It became read-only for existing users 2026-10-31 and shuts down 2026-11-30. The deprecations page names Promptfoo as the replacement, and the Evals guide suggests Datasets. Source: https://developers.openai.com/api/docs/guides/evals ; https://developers.openai.com/api/docs/deprecations
- **OpenAI fine-tuning is winding down.** New users cannot access it. Existing users can still create jobs until self-serve job creation ends 2027-01-06 (notice 2026-05-07). Supported methods are SFT, DPO (`gpt-4.1-2025-04-14`, `gpt-4.1-mini-2025-04-14`, `gpt-4.1-nano-2025-04-14`) and vision (`gpt-4o-2024-08-06`). Fine-tuned models stay usable until their base model is deprecated. Source: https://developers.openai.com/api/docs/guides/fine-tuning ; https://developers.openai.com/api/docs/deprecations
- **OpenAI Realtime API.** It went GA 2025-08-28, and the beta interface (`OpenAI-Beta: realtime=v1`) was removed 2026-05-12. Browsers connect with WebRTC via `/v1/realtime/calls` using an ephemeral secret from `POST /v1/realtime/client_secrets`; servers use WebSocket. It supports functions, MCP servers and connectors. Outbound SIP calling for GPT-Live opened to all organizations 2026-11-02. Source: https://developers.openai.com/api/docs/guides/realtime ; https://developers.openai.com/api/docs/changelog
- **OpenAI Decisions API** went GA 2026-10-22 with `gpt-6-luna`, after a 2026-10-06 beta. Its scope relative to agents was not researched. Source: https://developers.openai.com/api/docs/changelog
- **OpenAI Sora/Videos API is retired.** The Videos API with `sora-2` and `sora-2-pro` shut down 2026-09-24, with no one-to-one replacement. Source: https://developers.openai.com/api/docs/deprecations
- **Codex surfaces.** Codex runs in the ChatGPT desktop, mobile and web apps, the Codex CLI, the Codex IDE extension and Codex Cloud. Builder tools are the Codex SDK, a GitHub Action and non-interactive mode. Integrations cover GitHub, GitLab (beta), Slack and Linear. Source: https://learn.chatgpt.com/docs
- **Codex recommended models.** Recommended models are `gpt-6-astra`, `gpt-6.1-sol` (500,000-token default context in Codex), `gpt-6.1-terra` (needs CLI 0.159.0 or later; not in the IDE extension) and `gpt-6-luna`. Reasoning efforts are Light/Low, Medium, High, Extra High, Max and Ultra (subagents). GPT-5.5 retires from ChatGPT-sign-in Codex 2026-10-14, a retirement that does not affect API-key sessions. Source: https://learn.chatgpt.com/docs/models
- **Codex GitHub code review.** Comment `@codex review` on a PR, or enable Automatic review in Codex settings. Codex flags only P0/P1 issues in GitHub. Rules go in a `## Code Review Rules` section of `AGENTS.md`. `@codex security review` (research preview) runs a security pass. Source: https://learn.chatgpt.com/docs/third-party/github

## 7. Connectivity
- **OpenAI REST API base URL and auth.** The base URL is `https://api.openai.com/v1`, and auth is `Authorization: Bearer <API key or workload-identity access token>`. `OpenAI-Organization` and `OpenAI-Project` headers select the organization and project. Admin endpoints need an Admin API key. Every response carries `x-request-id`, and you can send an optional `X-Client-Request-Id` (ASCII, 512 characters or fewer). The REST version is v1 (`openai-version: 2020-10-01`). Source: https://developers.openai.com/api/reference/overview
- **OpenAI official SDKs.** Packages are Python `openai` (3.51.0 on PyPI, Python >=3.10), JS/TS `openai` (npm; Node, Deno, Bun), .NET `OpenAI` (NuGet), Java `com.openai:openai-java`, Go `github.com/openai/openai-go/v3` and Ruby gem `openai`. There is also an `openai` CLI via `brew install openai/tools/openai`. SDKs read `OPENAI_API_KEY`. Source: https://developers.openai.com/api/docs/libraries ; https://pypi.org/pypi/openai/json
- **OpenAI Responses remote MCP tool definition.** It is declared as `{"type":"mcp","server_label":...,"server_url":...}`. Optional fields are `allowed_tools`, `server_description`, `defer_loading` (for tool search), `require_approval` and `authorization` (an OAuth access token). OpenAI does not store `authorization`, so resend it on every request. Supported transports are Streamable HTTP and HTTP/SSE. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp
- **OpenAI Responses MCP approvals.** `require_approval` takes `"always"`, `"never"` or `{"never":{"tool_names":[...]}}`, and approval is required by default. The model emits `mcp_approval_request` (`mcpr_...`), and you reply with an `mcp_approval_response` input item (`approve`, `approval_request_id`) using `previous_response_id`. Each approval covers one call. Tools are discovered via the `mcp_list_tools` output item, and calls appear as `mcp_call` items. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp
- **OpenAI Responses MCP limits and billing.** Rate limits are 1000 RPM on Build and 2000 RPM on Launch/Grow. You pay only tokens for tool definitions and calls, with no per-call fee. The tool also works in Chat Completions. It is compatible with ZDR and data residency. With `store=true`, data sent to MCP servers is logged for 30 days unless ZDR applies. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp
- **OpenAI connectors (`connector_id`) are legacy.** Connectors were added to Responses 2025-08-21 and are deprecated for models released after 2026-09-01; older models keep support. The IDs are `connector_dropbox`, `connector_gmail`, `connector_googlecalendar`, `connector_googledrive`, `connector_microsoftteams`, `connector_outlookcalendar`, `connector_outlookemail` and `connector_sharepoint`. For GitHub, use GitHub's official remote MCP via `server_url`. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp ; https://developers.openai.com/api/docs/changelog
- **OpenAI Secure MCP Tunnel reaches private MCP servers.** It connects local or private MCP servers to the Responses `mcp` tool via `tunnel_id`. It was released 2026-05-19 for enterprise customers. A dedicated guide URL was not found. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp ; https://developers.openai.com/api/docs/changelog
- **OpenAI hosts a docs MCP server.** It runs at `https://developers.openai.com/mcp` (Streamable HTTP) and gives read-only search and page content over OpenAI developer docs. Add it to Codex with `codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp`, or `[mcp_servers.openaiDeveloperDocs] url = "https://developers.openai.com/mcp"` in `~/.codex/config.toml`. Source: https://developers.openai.com/learn/docs-mcp
- **OpenAI Agents API MCP attachment.** MCP servers go in the agent's `tools` array as `type: "mcp"` with `server_label` and a `transport` object (HTTP with `server_url`). The API key needs the scopes `api.agents.read`, `api.agents.write` and `api.responses.write`. Source: https://developers.openai.com/api/docs/guides/agents-api/tools ; https://developers.openai.com/api/docs/guides/agents-api/quickstart
- **OpenAI ChatGPT plugins / Apps SDK are built on MCP.** Docs moved to the "ChatGPT plugins and Apps SDK" set at `developers.openai.com/plugins`; `/apps-sdk` now serves Plugins content. A plugin bundles skills and/or an MCP server, with optional UI. ChatGPT and Codex share one plugin directory. Submission goes through the ChatGPT Directory review. Source: https://developers.openai.com/apps-sdk ; https://developers.openai.com/plugins/quickstart ; https://developers.openai.com/llms.txt
- **OpenAI Apps SDK UI uses the MCP Apps standard.** UI is a `ui://` resource with MIME `text/html;profile=mcp-app`, linked from tools via `_meta.ui.resourceUri`. `_meta["openai/outputTemplate"]` is a ChatGPT compatibility alias. `window.openai` extensions (`requestCheckout`, `requestModal`, `uploadFile`, `setWidgetState`) are optional. Packages are `@modelcontextprotocol/ext-apps` and `@modelcontextprotocol/sdk`, plus optional `@openai/apps-sdk-ui`. Source: https://developers.openai.com/plugins/build/chatgpt-ui
- **OpenAI ChatGPT custom MCP servers (developer mode).** In ChatGPT Plugins, select "+" then "Add custom MCP server", and set the URL and auth (OAuth, none, or mixed). The feature is labeled "Elevated risk". Transports are SSE and streaming HTTP. OAuth registration uses static credentials, CIMD or DCR. Tools without the `readOnlyHint` annotation count as write actions, and write actions require confirmation. Source: https://developers.openai.com/api/docs/guides/developer-mode ; https://developers.openai.com/plugins/quickstart
- **OpenAI webhooks.** Webhooks were added to the API 2025-06-24, together with the web search tool. Event types were not researched. Source: https://developers.openai.com/api/docs/changelog
- **OpenAI models on Amazon Bedrock.** Since 2026-06-01, OpenAI models (for example `us.openai.gpt-6-sol` and `us.openai.gpt-6-luna` in `us-east-1`, GPT-6 Astra in `us-west-2`) are on Bedrock Runtime and Mantle with Responses- and Chat Completions-compatible endpoints. Remote MCP, hosted file search, the shell tool, image generation, Programmatic Tool Calling and WebSockets are not available there. Source: https://developers.openai.com/api/docs/guides/amazon-bedrock ; https://developers.openai.com/api/docs/changelog
- **Azure OpenAI / Microsoft Foundry (pointer only).** OpenAI models including `gpt-6-astra` (2026-09-03), `gpt-6-luna`, `gpt-6-sol` and `gpt-6.1-sol` are sold by Azure as "Foundry Models sold by Azure", with Azure deployments, regions and auth. Cover this under the Azure/Foundry platform. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure
- **OpenAI A2A support was not found.** No A2A protocol support appeared in the API docs reviewed. MCP is the cross-vendor tool protocol across Responses, the Agents SDK, the Agents API, ChatGPT and Codex (unverified). Source: https://developers.openai.com/api/docs/llms.txt

## 8. CLIs and infrastructure as code
- **Codex CLI install on Windows.** Use `npm install -g @openai/codex` (version 0.169.0 on npm; `engines.node >=16`; binary `codex`) or the PowerShell installer `powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"`. The Windows page says `winget` "should be available". macOS/Linux use `curl -fsSL https://chatgpt.com/codex/install.sh | sh` or `brew install --cask codex`. Source: https://github.com/openai/codex ; https://registry.npmjs.org/@openai/codex/latest ; https://learn.chatgpt.com/docs/windows/windows-sandbox
- **Codex CLI current release.** The latest GitHub release is `rust-v0.169.0` (0.169.0, published Nov 13). It fixed `codex exec` keeping project config and MCP servers disabled in untrusted directories, and Windows sandbox issues with `cmd.exe`/PowerShell. The license is Apache-2.0. Source: https://github.com/openai/codex/releases/latest
- **Codex sign-in.** `codex login` signs in with ChatGPT (browser flow). `printenv OPENAI_API_KEY | codex login --with-api-key` uses an API key (billed at API rates). `codex login --with-access-token` reads `CODEX_ACCESS_TOKEN` and needs admin permission. `codex login --device-auth` (beta) suits headless machines. `codex login status` and `codex logout` check and clear credentials. Without device auth, copy `~/.codex/auth.json` or forward localhost:1455. Source: https://learn.chatgpt.com/docs/auth
- **Codex credential storage.** `cli_auth_credentials_store` is `file` (`auth.json` under `CODEX_HOME`, default `~/.codex`), `keyring`, `auto` or `ephemeral`. Admins can force `forced_login_method` (`chatgpt` or `api`) and `forced_chatgpt_workspace_id`. Under workload identity federation (beta for Codex; `OPENAI_IDENTITY_TOKEN_FILE`), `codex login` and `codex logout` are rejected. Source: https://learn.chatgpt.com/docs/auth ; https://developers.openai.com/api/docs/guides/workload-identity-federation
- **Codex config.toml locations.** User config is `~/.codex/config.toml`. Project config is `.codex/config.toml`, loaded only for trusted projects. Project files cannot set `model_provider`, `profiles`, `openai_base_url`, `otel` and similar keys. Profiles are `$CODEX_HOME/<name>.config.toml`, selected with `--profile`. Source: https://learn.chatgpt.com/docs/config-file/config-reference
- **Codex sandbox and approval modes.** `sandbox_mode` is `read-only`, `workspace-write` or `danger-full-access`. `approval_policy` is `on-request`, `never` or `{granular = {...}}`; `untrusted` is no longer supported and `on-failure` is deprecated. `approvals_reviewer` is `user` or `auto_review`. `[sandbox_workspace_write]` takes `writable_roots` and `network_access`. Source: https://learn.chatgpt.com/docs/config-file/config-reference ; https://learn.chatgpt.com/docs/sandboxing
- **Codex CLI flags and subcommands.** Flags: `--sandbox`/`-s`, `--ask-for-approval`/`-a`, `--dangerously-bypass-approvals-and-sandbox`/`--yolo`, `--approve-for-me`/`--not-so-yolo` (on-request plus workspace-write), `-m`, `-p`, `-c key=value`, `-C`, `--search` and `--oss`. ## 10. Limits and gotchas
- **OpenAI usage tiers.** The tiers are now Free, Build, Launch and Grow, replacing Tier 1–5. Free has a $100/month usage limit. Build needs $5 in purchases ($500/month). Launch needs $100 ($5,000/month). Grow needs $500 ($200,000/month). Tiers upgrade automatically. Source: https://developers.openai.com/api/docs/guides/rate-limits
- **OpenAI standard rate limits per tier (shown 2026-11-14).** Build: Astra/Sol/Terra 5,000 RPM and 1M TPM; Luna 5,000 RPM and 2M TPM. Launch: 10,000 RPM and 4M TPM; Luna 10M TPM. Grow: 15,000 RPM and 40M TPM; Luna 30,000 RPM and 180M TPM. Limits also apply as RPD, TPD and IPM. Long-context models have separate limits shown in the console. Source: https://developers.openai.com/api/docs/guides/rate-limits
- **OpenAI 429 behavior.** A `429` with `slow_down` can occur within RPM/TPM if traffic ramps too fast. Above 1M input TPM, grow traffic by no more than 50% every 15 minutes. Failed requests still count against limits. Honor `Retry-After` and the `x-ratelimit-*` headers (including the `-project-tokens` variants). A `503 server_is_overloaded` is not a rate limit. The SDKs auto-retry eligible 429/503 responses. Source: https://developers.openai.com/api/docs/guides/rate-limits
- **OpenAI Batch API limits.** Batch covers `/v1/responses`, `/v1/chat/completions`, `/v1/embeddings`, `/v1/completions`, `/v1/moderations`, `/v1/images/generations` and `/v1/images/edits`. It has a 24h window and a 50% discount. A batch holds at most 50,000 requests with a 200 MB input file, and you can create 2,000 batches/hour. The per-model queued-token cap is shown in Platform settings. Outputs expire after 30 days by default (`output_expires_after`, minimum 1 hour). Source: https://developers.openai.com/api/docs/guides/batch ; https://developers.openai.com/api/docs/guides/rate-limits
- **OpenAI request header and file limits.** Total request headers must stay under 64 KiB, and custom header values at or under 60 KiB. Oversized headers may fail with no `x-request-id`. File inputs to models must be under 50 MB per file and 50 MB combined per request (upload with purpose `user_data`). Source: https://developers.openai.com/api/reference/overview ; https://developers.openai.com/api/docs/guides/file-inputs
- **OpenAI auth propagation delay.** Revoked API keys stop working within seconds, but most other auth changes take up to 15 minutes to propagate. Source: https://developers.openai.com/api/reference/overview
- **OpenAI `previous_response_id` gotchas.** Top-level `instructions` do not carry over through `previous_response_id`, so resend them every turn. Chained input tokens are billed again. In WebSocket mode, an uncached ID needs a resend with `previous_response_id: null` and the full input. Source: https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://developers.openai.com/api/docs/guides/conversation-state
- **OpenAI MCP `authorization` is not persisted.** The Responses MCP `authorization` token is not stored, so it must be resent on every request, including approval follow-ups. Keep `mcp_list_tools` in context to avoid re-listing tools each turn. Source: https://developers.openai.com/api/docs/guides/tools-connectors-mcp
- **Codex MCP gotchas.** The default MCP startup timeout is 10 s and the tool timeout 60 s. Project `.codex/config.toml` (including MCP servers) loads only in trusted projects. ChatGPT web ignores local Codex config and uses plugins. Codex reads only the first 512 characters of a server's `instructions` reliably. Source: https://learn.chatgpt.com/docs/extend/mcp
- **Codex Windows troubleshooting.** Error `1385` means the sandbox users lack a logon right, which IT must grant. Share `CODEX_HOME/.sandbox/sandbox.log` with support but never `.sandbox-secrets/`. If the IDE extension hangs, install VS Build Tools (C++) and the x64 VC++ Redistributable. Windows 10 is best effort (1809+). Source: https://learn.chatgpt.com/docs/windows/windows-sandbox
- **OpenAI renames and moves.** Usage tiers 1–5 became Free/Build/Launch/Grow. The Assistants API became Responses plus Conversations (2026-08-26). Agent Builder moves to the Agents SDK or Workspace Agents (2026-11-30). Evals moves to Promptfoo (2026-11-30). `connector_id` connectors move to remote MCP `server_url` (models after 2026-09-01). The Apps SDK docs set is now "ChatGPT plugins and Apps SDK". Codex docs moved to learn.chatgpt.com. `codex mcp-server` was replaced by `codex app-server`. Source: https://developers.openai.com/api/docs/guides/rate-limits ; https://developers.openai.com/api/docs/deprecations ; https://developers.openai.com/api/docs/guides/tools-connectors-mcp ; https://learn.chatgpt.com/docs/codex-sdk
