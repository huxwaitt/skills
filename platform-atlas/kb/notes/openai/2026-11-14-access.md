# OpenAI: access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Two separate tenancy models.** OpenAI API Platform access is an organization, which contains projects. ChatGPT Enterprise, Business and Edu access is a ChatGPT workspace. OpenAI's docs list six control boundaries: ChatGPT workspace, local clients, Codex cloud, Platform API, plugins and connected systems. "A request must pass every boundary that applies to it." Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md
- **ChatGPT workspace roles do not reach the API Platform.** The Platform API boundary covers "Organization and project membership, API keys, model access, usage, and billing for API-authenticated work". It does not cover ChatGPT workspace membership, local-client access or Codex cloud access. Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md
- **OpenAI API organization model.** Organization settings show the organization name and ID. A user in several organizations sends a header (`OpenAI-Organization`, and `OpenAI-Project` for the project) to choose the one billed; otherwise the default organization is billed. OpenAI recommends separate projects for staging and production, with their own rate and spend limits. Source: https://developers.openai.com/api/docs/guides/production-best-practices ; https://developers.openai.com/api/docs/guides/terraform.md
- **API Platform self-serve onboarding.** An organization starts on the Free tier and moves up usage tiers automatically as its total credit purchases grow (see section 5). Enterprise features such as Zero Data Retention, Private Link and India or UAE residency are granted through OpenAI sales. Source: https://developers.openai.com/api/docs/guides/rate-limits ; https://developers.openai.com/api/docs/guides/private-link.md
- **ChatGPT Enterprise rollout runs in a fixed order.** The admin rollout guide orders the work as: 1) assign owners for workspace access, local runtime policy, Codex cloud, connected systems and reporting; 2) configure workspace access and identity; 3) set local runtime requirements (`requirements.toml`); then standardize repository config, Codex cloud, plugins and analytics. Source: https://learn.chatgpt.com/docs/enterprise/admin-setup.md
- **ChatGPT Enterprise is sold through AWS Marketplace.** The rollout guide tells AWS Marketplace buyers to check the data residency and inference residency requirements first. Source: https://learn.chatgpt.com/docs/enterprise/admin-setup.md
- **ChatGPT admin console URL.** The ChatGPT workspace Admin console is `https://admin.openai.com`. Settings live under Permissions & roles (`https://chatgpt.com/admin/permissions`), Plugins, Access tokens (`https://chatgpt.com/admin/access-tokens`) and Service accounts (`https://chatgpt.com/admin/service-accounts`). Source: https://learn.chatgpt.com/docs/enterprise/apps-and-connectors.md ; https://learn.chatgpt.com/docs/enterprise/service-accounts.md
- **Day-one asks: API work.** For API work, ask the client for: the API organization ID; a dedicated project, created with the needed data-residency region (fixed at creation); a project service account, ideally with workload identity federation; the project's model allowlist and hosted-tool permissions; any project spend limit and IP allowlist; and the org's data-retention mode (default, ZDR or MAM). Source: https://developers.openai.com/api/docs/guides/api-keys.md ; https://developers.openai.com/api/docs/guides/data-residency
- **Day-one asks: ChatGPT and Codex work.** For ChatGPT or Codex work, ask for: a seat of the right type (ChatGPT or Codex); a custom role or group granting the features needed (for example Codex local, Codex cloud, plugins); plugin and app enablement; and, for automation, a ChatGPT service account or permission to create Codex access tokens. Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md
- **Alternative channels: Azure.** Azure sells OpenAI models as "Azure OpenAI in Microsoft Foundry Models", part of Foundry Models sold by Azure, under Azure's own identity, billing and compliance. This note covers it only as a pointer. Source: https://learn.microsoft.com/en-us/azure/ai-foundry/foundry-models/concepts/models-sold-directly-by-azure
- **Alternative channels: Amazon Bedrock.** Local Codex and ChatGPT Work clients can be configured to use OpenAI models available through Amazon Bedrock, including Bedrock in AWS GovCloud. Source: https://learn.chatgpt.com/docs/administration.md ; https://learn.chatgpt.com/docs/amazon-bedrock.md

## 2. Identity and authentication
- **Three API credential types.** OpenAI documents three: a user-owned project API key (acts with its owner's access; for personal development); a project service account and its API key (for deployed apps, jobs and CI); and an Admin API key (for organization management only). "Admin API keys cannot be used for non-administration endpoints." Source: https://developers.openai.com/api/docs/guides/api-keys.md ; https://developers.openai.com/api/docs/guides/admin-apis.md
- **Legacy user API keys still exist.** The API reference still mentions "a legacy user API key" (not project-scoped). Callers that use one, or that belong to several organizations, must pass organization and project headers. Source: https://developers.openai.com/api/llms-full.txt
- **Project service accounts belong to one project.** Create a service account through the Admin API under `/organization/projects/{project_id}/service_accounts`. The `create_service_account_only` option creates it with no default roles and no initial API key. Such an account cannot call models until it is given permissions. Source: https://developers.openai.com/api/docs/guides/api-keys.md
- **API key scopes can only narrow access.** "Key scopes can restrict what the key can do, but they don't grant permissions that the user or service account doesn't have." A request needs the permission on both the key and the owner's role. For example, `/v1/models` needs `api.model.read` on both. Source: https://developers.openai.com/api/docs/guides/api-keys.md ; https://developers.openai.com/api/docs/guides/rbac
- **API key governance settings.** Admins can set a maximum key lifetime at the organization or project level; a project limit cannot exceed the organization's. The API Key Governance setting can allow only service-account keys, allow only user-owned project keys, or disable new key creation. Organization rules override project rules and apply only to newly created keys. Source: https://developers.openai.com/api/docs/guides/production-best-practices
- **Workload identity federation for the OpenAI API.** Workload identity federation replaces stored API keys. A workload exchanges a short-lived OIDC JWT, SPIFFE JWT-SVID or X.509 certificate for a short-lived OpenAI access token. The token is mapped to a Platform project service account through a "service account mapping". Configure it at Organization Settings > Security > Workload Identity Provider. Source: https://developers.openai.com/api/docs/guides/workload-identity-federation.md
- **Supported workload identity providers.** Documented providers are Kubernetes, AWS (outbound identity federation or EKS), Microsoft Azure (managed identity or AKS), Google Cloud (metadata server or GKE), Oracle Cloud Infrastructure instance principals, GitHub Actions OIDC, SPIFFE, Idira, and X.509 certificates. For an unlisted OIDC provider, contact OpenAI support. Source: https://developers.openai.com/api/docs/guides/workload-identity-federation.md ; https://developers.openai.com/api/docs/guides/workload-identity-federation/github-actions.md
- **Workload identity token behavior.** The token exchange returns `access_token`, `expires_at` (Unix UTC) and `expires_in` (seconds), and no refresh token. To renew, repeat the exchange. "Token exchange never creates a principal, project, or workspace membership." Source: https://developers.openai.com/api/docs/guides/workload-identity-federation.md
- **Workload identity federation for Codex is in beta.** It maps to a ChatGPT user or service account through a "federation rule" set up in the OpenAI Admin Portal (a Custom OIDC option is available). It must be enabled for the workspace. Source: https://developers.openai.com/api/docs/guides/workload-identity-federation.md
- **Mutual TLS for the OpenAI API.** After a trusted certificate is activated for an organization or project, requests in that scope must present an accepted client certificate in addition to the bearer credential. mTLS is managed with the `api.mtls.read` and `api.mtls.write` permissions. Source: https://developers.openai.com/api/docs/guides/mutual-tls.md
- **SSO and SCIM for the API Platform.** API Platform groups can be synced from an identity provider via SCIM. OpenAI's single sign-on (SSO) setup article covers "OpenAI products". Daybreak Red (cyber) organizations must require SSO for the API organization and enforce MFA through their IdP. Source: https://developers.openai.com/api/docs/guides/rbac ; https://developers.openai.com/api/llms-full.txt
- **ChatGPT human SSO by plan.** The ChatGPT Business plan includes SAML SSO and MFA. Enterprise and Edu add SCIM, EKM, user analytics, domain verification and RBAC. Source: https://learn.chatgpt.com/docs/pricing.md
- **ChatGPT group sources.** Workspace groups are manually managed, IdP-managed through SCIM, or dynamic (rules on SCIM user attributes). For SCIM-managed members, remove access in the IdP; "a later sync can restore access" if removed only in the workspace. Source: https://learn.chatgpt.com/docs/enterprise/groups-and-provisioning.md
- **Codex sign-in methods.** Codex supports "Sign in with ChatGPT" (subscription; follows workspace RBAC, retention and residency) and API key sign-in (usage-based; follows the API organization's retention settings). Sign in with `codex login`, or `printenv OPENAI_API_KEY | codex login --with-api-key`. Codex cloud requires ChatGPT sign-in. Source: https://learn.chatgpt.com/docs/auth.md
- **Codex access tokens.** Codex access tokens are personal access tokens for ChatGPT Business and Enterprise workspaces. Each token represents the member who created it and works for non-interactive `codex exec` and app-server automation. Scopes are **Codex** and **Workspace Agents**. The shortest validity is 1 day, and scoped tokens must expire. A workspace owner sets the **Access token expiration limit**. Source: https://learn.chatgpt.com/docs/enterprise/access-tokens.md
- **ChatGPT service accounts.** ChatGPT workspace service accounts are non-human workspace identities for Codex automation, available "only on pay-as-you-go plans". Only workspace owners and admins can create them. Run with `CODEX_ACCESS_TOKEN` and `codex exec` (requires Codex CLI `0.142.0` or later). They can be provisioned through SCIM with `userType: ServiceAccount`. Source: https://learn.chatgpt.com/docs/enterprise/service-accounts.md
- **Agent identity offerings.** OpenAI describes Codex access tokens as acting "as agent identities for programmatic local workflows". ChatGPT service accounts are the non-human variant. On the API side, the agent's identity is a project service account. Source: https://learn.chatgpt.com/docs/enterprise/access-tokens.md ; https://developers.openai.com/api/docs/guides/api-keys.md

## 3. Roles and permissions
- **API Platform preset roles.** The preset roles are Org owner, Org reader, Project owner, Project member and Project viewer. Users and groups can hold several roles, and effective access is the union of them. Source: https://developers.openai.com/api/docs/guides/rbac
- **API Platform custom roles.** Custom roles can be created at org or project level from eligible permissions: List models, Usage (org only), Model capabilities, Assistants, Threads, Evals, Fine-tuning, Files, Vector Stores, Responses API, Prompts, Webhooks, Datasets, Apps (org only), Tunnels (org only), Project API Keys and Agent Builder. Groups, Roles, Organization Admin, Batch, Service Accounts, Project Administration and Voices are preset-only. Source: https://developers.openai.com/api/docs/guides/rbac
- **Who grants what on the API Platform.** Service Accounts and Project Administration are limited to Org owner and Project owner. Organization Admin, which covers Admin API keys, is Org owner only. The IP allowlist needs Org owner (Read and Write). Role changes and group sync take up to 30 minutes to propagate. Source: https://developers.openai.com/api/docs/guides/rbac ; https://developers.openai.com/api/docs/guides/ip-allowlist.md
- **Permission strings seen in the API docs.** Examples include `api.model.request`, `api.model.read`, `api.responses.write`, `api.files.read`, `api.files.write`, `api.vector_store.read`, `api.batch.read`, `api.batch.write`, `api.usage.read`, `api.mtls.read` and `api.mtls.write`. Batch Write also implies Files Read and Write and Model capabilities Request. Source: https://developers.openai.com/api/llms-full.txt ; https://developers.openai.com/api/docs/guides/rbac
- **Least-privilege API agent setup.** 1) A dedicated project per app or environment. 2) A project service account created with `create_service_account_only` and given a custom role with only Model capabilities (Request) plus the resources it uses, such as Responses API or Files. 3) Scoped, expiring keys, or workload identity federation instead. 4) A project model allowlist. 5) Hosted-tool permissions. 6) A project hard spend limit. 7) Optionally an IP allowlist or mTLS. An Org owner or Project owner grants these. Source: https://developers.openai.com/api/docs/guides/api-keys.md ; https://developers.openai.com/api/docs/guides/admin-apis.md
- **Allowed models per project.** Project model permissions take `mode` `allow_list` or `deny_list` and `model_ids`, set through the Admin API (`client.admin.organization.projects.model_permissions.update`) or Terraform `openai_project_model_permissions`. Source: https://developers.openai.com/api/docs/guides/admin-apis.md ; https://developers.openai.com/api/docs/guides/terraform/project-controls.md
- **Hosted-tool permissions per project.** Terraform `openai_project_hosted_tool_permissions` controls file search, web search, image generation, remote MCP servers and Code Interpreter per project. The organization policy is allow all, deny all, or allow selected projects. A project cannot disable a tool the organization enables for every project. Source: https://developers.openai.com/api/docs/guides/terraform/project-controls.md
- **Admin API scope.** The Admin API automates invitations, users, groups, roles, projects, service accounts, API keys, spend limits and alerts, data retention, rate limits and audit logs. Set the Admin API key as `OPENAI_ADMIN_KEY`. Minimum SDK versions are Node `6.36.0`, Python `2.34.0`, Go `3.34.0`, Ruby `0.61.0` and Java `4.34.0`. The Terraform provider is `openai/openai` and reads `OPENAI_ADMIN_KEY`. Source: https://developers.openai.com/api/docs/guides/admin-apis.md ; https://developers.openai.com/api/docs/guides/terraform.md
- **ChatGPT workspace built-in roles.** The built-in roles are **Owner** (workspace-wide settings), **Admin** (supported operations and groups), **Member** (no admin rights) and **Analytics Viewer**. A seat type (ChatGPT or Codex) decides which product surfaces a member can use. Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md
- **ChatGPT custom roles combine additively.** Workspace owners create custom roles and assign them to groups or members. Each permission is **Default** (inherit), **On** or **Off**, and **On** in any role wins over **Off** in another. Lockdown Mode and seat or plan eligibility still apply. Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md
- **Codex workspace permissions.** Named permissions include **Allow members to use Codex locally** (or **Allow members to use Codex and Work Locally**), **Use Codex in the cloud**, **Manage workspace environments** (off by default) and **Allow users to create personal access tokens**. Source: https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions.md ; https://learn.chatgpt.com/docs/enterprise/access-tokens.md
- **ChatGPT service-account sharing roles.** **User** can create tokens only. **Configure** can configure the account and its plugins only. **Manager** can do both. In the Admin API these are `user`, `configurer` and `manager`. The Admin API scopes are `chatgpt.enterprise.service_account.read` and `chatgpt.enterprise.service_account.write`, with path `POST /v1/manage/workspaces/{workspace_id}/service-accounts`. Source: https://learn.chatgpt.com/docs/enterprise/service-accounts.md
- **Codex local runtime policy.** Admins constrain local Codex and ChatGPT desktop runs with `requirements.toml`, which covers permission profiles such as `:read-only` and `:workspace`, and feature flags such as `computer_use = false`. This policy is separate from workspace RBAC. Source: https://learn.chatgpt.com/docs/enterprise/admin-setup.md

## 4. Governance, security and compliance
- **API data is not used for training by default.** "Data sent to the OpenAI API is not used to train or improve OpenAI models" unless the customer explicitly opts in. Source: https://developers.openai.com/api/docs/guides/your-data
- **Abuse-monitoring retention.** Abuse-monitoring logs are kept "for up to 30 days" by default, unless law or harm prevention requires longer. Source: https://developers.openai.com/api/docs/guides/your-data
- **Zero Data Retention and Modified Abuse Monitoring.** Both need prior approval from OpenAI (contact sales) and can be set per organization or project. Modified Abuse Monitoring excludes customer content from abuse logs, except rare image and file inputs. ZDR does the same and also changes endpoint behavior. Under ZDR, `store` "will always be treated as `false`". Source: https://developers.openai.com/api/docs/guides/your-data
- **Project data-retention modes.** The Terraform provider exposes these modes: `none`, `zero_data_retention`, `modified_abuse_monitoring`, `enhanced_zero_data_retention` and `enhanced_modified_abuse_monitoring`. Source: https://developers.openai.com/api/docs/guides/terraform/project-controls.md
- **ZDR with Private Safety Processing.** Safety records are stored in customer-controlled storage and decrypted only in a hardware-attested runtime with no human access. The customer authorizes decryption through customer-managed EKM. Source: https://developers.openai.com/api/docs/guides/private-safety-processing.md
- **Responses `store` parameter.** When `store` is omitted or `true`, Responses data is kept for at least 30 days. On `/v1/chat/completions`, `store=true` cannot be set in non-US residency regions. Source: https://developers.openai.com/api/docs/guides/your-data ; https://developers.openai.com/api/docs/guides/data-residency
- **ZDR-eligible endpoints.** Eligible: `/v1/chat/completions`, `/v1/responses` and `/v1/decisions` (with limitations); `/v1/images/*` (specific models); `/v1/embeddings`; `/v1/audio/*`; `/v1/moderations`; `/v1/completions`; `/v1/live/sessions`; `/v1/realtime`. Source: https://developers.openai.com/api/docs/guides/your-data
- **Endpoints that are not ZDR-eligible.** Not eligible: `/v1/conversations`, `/v1/chatkit/threads`, `/v1/agents`, `/v1/assistants`, `/v1/threads`, `/v1/vector_stores`, `/v1/files`, `/v1/fine_tuning/jobs`, `/v1/evals` and `/v1/batches`. Source: https://developers.openai.com/api/docs/guides/your-data
- **API data residency regions.** Each region has a domain prefix: US `us.api.openai.com`, Europe (EEA + Switzerland) `eu.api.openai.com`, Australia `au.`, Canada `ca.`, Japan `jp.`, India `in.` (contact sales), Singapore `sg.`, South Korea `kr.`, United Kingdom `gb.` and UAE `ae.` (contact sales). Canada, Singapore, South Korea and the UK have regional storage but no regional processing. Source: https://developers.openai.com/api/docs/guides/data-residency
- **Regional processing coverage by endpoint.** Responses and Chat Completions are processed regionally in the US, EU, UAE, Australia, India and Japan. In Australia, India and Japan this applies only to `gpt-6-luna`, with Standard tier only and no hosted tools. Batches, audio, images, moderations, fine-tuning and evals are processed in the US and EU only. `/v1/files` and `/v1/vector_stores` are storage-only. Source: https://developers.openai.com/api/docs/guides/data-residency
- **Residency is fixed per project.** Choose the region under "Data and inference residency" when creating a project; it "can't be changed after creation". As an alternative, a Global project can have "Enable per-request data residency" and use regional prefixes on each request. Source: https://developers.openai.com/api/docs/guides/data-residency
- **ChatGPT data and inference residency.** Residency for ChatGPT Enterprise and Edu is documented in Help Center article 9903489, which this research could not fetch. Docs state that residency covers "only eligible content and supported workloads", that ChatGPT Work is not supported with UAE inference residency, and that `enforce_residency` for Codex currently accepts only `us`. (unverified: full region list) Source: https://learn.chatgpt.com/docs/enterprise/admin-setup.md ; https://learn.chatgpt.com/docs/llms-full.txt
- **Enterprise Key Management for ChatGPT.** Eligible Enterprise and Edu workspaces can use EKM for supported stored content, including hosted execution snapshots. Coverage varies by data category. Source: https://learn.chatgpt.com/docs/llms-full.txt
- **ChatGPT retention behavior.** Work conversations follow the workspace conversation-retention setting. Deleted chats are generally permanently deleted within 30 days. Eligible temporary Enterprise uploads outside Library can expire after 48 hours. Business ChatGPT data is not used for training by default. Source: https://learn.chatgpt.com/docs/llms-full.txt ; https://learn.chatgpt.com/docs/pricing.md
- **API IP allowlist.** Configure it at Settings > Security > IP allowlist, with up to 50 IPs or CIDR ranges per organization or project. A project allowlist replaces, and does not merge with, the organization's. Changes take up to 15 minutes. A blocked request returns `401` `ip_not_authorized`. The allowlist covers API requests only, not platform sign-in. Source: https://developers.openai.com/api/docs/guides/ip-allowlist.md
- **API organization blocking.** A proxy or SASE service sends the header `OpenAI-Allowed-Organization-Ids` (comma-separated `org-…` IDs) on traffic to `https://api.openai.com/*`. Access to organizations not on the list returns `403`. Source: https://developers.openai.com/api/docs/guides/organization-blocking.md
- **Private Link (Azure).** OpenAI Private Link reaches regional OpenAI API endpoints from Azure VNets. Regional hosts are `southcentralus.`, `westus.`, `eastus2.` and `spaincentral.privatelink.api.openai.com`. It is not self-service (contact sales) and is "not compatible with IP allowlist controls or mutual TLS". Source: https://developers.openai.com/api/docs/guides/private-link.md
- **Plugin and connector controls in ChatGPT.** In Admin console > Plugins, admins choose, per plugin: Available for installation, Installed for workspace, Customize by role, or Disable. Per app they set App access, Tools/Actions (read vs write), New tools, and Permissions (when ChatGPT asks first). Connected-service permissions still apply. Source: https://learn.chatgpt.com/docs/enterprise/apps-and-connectors.md
- **Custom MCP connectors in ChatGPT.** Separate member permissions control **Use plugins**, **Upload plugins**, **Upload plugins with custom MCP servers**, **Share plugins**, **Publish plugins to workspace** and **Create plugins with MCPs** ("Use developer mode to create custom app connections"). ChatGPT web uses remote MCP tools through plugins. Source: https://learn.chatgpt.com/docs/enterprise/apps-and-connectors.md ; https://learn.chatgpt.com/docs/extend/mcp.md
- **Custom GPTs are being retired.** OpenAI is "transitioning custom GPTs to plugins". Migrated GPTs become read-only. At retirement, custom GPTs "stop running and leave the GPT directory". Custom actions must be rebuilt. The migration guide gives no exact retirement date. Source: https://learn.chatgpt.com/docs/migrate-custom-gpts.md
- **ChatGPT Compliance API.** Enterprise and Edu workspaces use it to export audit records, such as `AUTH_LOG`, `conversation_message` and `codex_log`, from an append-only log stream with an Enterprise Compliance API key (`COMPLIANCE_API_KEY`). It takes a workspace ID or an API Platform organization ID. The reference is at https://chatgpt.com/public/admin/api-reference. Source: https://learn.chatgpt.com/docs/enterprise/compliance-api.md
- **ChatGPT analytics surfaces.** Workspace analytics, Usage Insights and the Analytics API cover adoption reporting. The Compliance API is for audit and investigation, not productivity measurement. Source: https://learn.chatgpt.com/docs/enterprise/governance.md ; https://learn.chatgpt.com/docs/enterprise/compliance-api.md
- **API audit logs.** The Admin API includes Organization Audit Logs (`/v1/organization/audit_logs`) and organization usage and cost endpoints. Source: https://developers.openai.com/api/reference/resources/organization/subresources/audit_logs.md
- **Safety controls on the API.** Safety controls include safety classifiers with safety identifiers, cybersecurity checks, misalignment monitoring, organization-level safety enforcement webhooks, and the moderation endpoint. Source: https://developers.openai.com/api/docs/guides/safety-checks.md ; https://developers.openai.com/api/docs/guides/safety-enforcement.md
- **Compliance attestations listed on trust.openai.com.** SOC 2 Type 2, SOC 3, PCI DSS v4.0.1, ISO/IEC 27001:2022, ISO/IEC 27017:2015, ISO/IEC 27018:2019, ISO/IEC 27701:2019, ISO/IEC 42001:2023, CSA STAR, GDPR, CCPA, TX-RAMP and FedRAMP 20x. HIPAA is supported through a BAA; the Fast mode guide calls it BAA-compatible. Source: https://trust.openai.com/ ; https://developers.openai.com/api/docs/guides/fast-mode.md

## 5. Commercial model
- **API billing is per token.** The API bills per 1M tokens (input, cached input, output; newer models also bill cache writes and long-context rates). Prices are on the pricing page. Example shown 2026-11-14: `gpt-6.1-sol` Standard costs $2.00 input and $10.00 output per 1M tokens. Source: https://developers.openai.com/api/docs/pricing
- **Batch API pricing.** The Batch API costs 50% less than synchronous calls, has a separate higher rate-limit pool, and completes within 24 hours (completion window `24h` only). Source: https://developers.openai.com/api/docs/guides/batch.md
- **Flex processing.** Flex (`service_tier: "flex"`) is priced at Batch rates, with slower responses and occasional resource-unavailable errors. It is in beta with limited model support. Source: https://developers.openai.com/api/docs/guides/flex-processing.md
- **Fast mode replaced Priority processing.** Priority processing was renamed Fast mode on 2026-07-30. Use `service_tier: "fast"` (`"priority"` still works) or a project-level **Project Service Tier** setting. Fast mode is billed separately from Scale Tier TPM bundles. Ultrafast mode exists for GPT-6 Astra and GPT-6.1 Sol. Source: https://developers.openai.com/api/docs/guides/fast-mode.md
- **Regional and FedRAMP uplifts.** Regional processing (data residency) endpoints cost 10% more for models released on or after 2026-03-05. FedRAMP endpoints also cost 10% more. Source: https://developers.openai.com/api/docs/pricing
- **API usage tiers.** Tiers as shown 2026-11-14: Free (allowed geography only; $100 per month usage limit), Build ($5 in credit purchases; $500 per month), Launch ($100; $5,000 per month) and Grow ($500; $200,000 per month). Source: https://developers.openai.com/api/docs/guides/rate-limits
- **API spend controls.** Spend alerts only notify. Hard spend limits at org or project level return `429` with `organization_spend_limit_exceeded` or `project_spend_limit_exceeded`. Exhausted prepaid credits return `credit_balance_exhausted`, and the tier usage limit returns `organization_usage_limit_exceeded`. Source: https://developers.openai.com/api/docs/guides/spend-limits.md
- **ChatGPT plan prices.** Prices shown 2026-11-14: Free $0, Go $8 per month, Plus $20 per month, Pro from $100 per month ($100, $200 or $500 tiers), Business $20 per user per month billed annually (2+ users; $25 billed monthly), and Enterprise and Edu through sales. Source: https://learn.chatgpt.com/docs/pricing.md
- **ChatGPT credits.** Credit-based Business, Edu and Enterprise agreements draw ChatGPT Work and eligible Codex usage from a shared pool of workspace credits. Token rates are quoted in credits per 1M tokens, and desktop voice costs 1.25 credits per minute. Enterprise and Edu with flexible pricing have "no fixed rate limits".
