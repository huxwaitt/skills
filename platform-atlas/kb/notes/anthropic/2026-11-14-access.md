# Anthropic Claude: access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Two separate Anthropic tenancy models exist: Claude Console organizations and claude.ai (Team/Enterprise) organizations.** Claude Console organizations are managed at `platform.claude.com` and hold API workloads; Claude Enterprise organizations are managed at `claude.ai`; a company using both creates admin keys in each. Source: https://platform.claude.com/docs/en/manage-claude/admin-api-keys
- **Claude Enterprise tenants have a parent organization with linked organizations.** A Claude Enterprise tenant has one parent organization that centralizes identity, with linked claude.ai organizations (chat and content) and linked Claude Console organizations (API workloads); a standalone Console organization has no parent. Source: https://platform.claude.com/docs/en/manage-claude/compliance-api
- **Claude Console hierarchy is organization > workspaces.** Every Claude Console organization has a Default Workspace that cannot be renamed, archived or deleted; additional workspaces (IDs prefixed `wrkspc_`) hold members, service accounts, API keys and limits; the default cap is 100 workspaces per organization (archived ones excluded), raisable via the account team. Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **Only Claude Console organization admins can create workspaces.** Organization users and developers must be added to workspaces by an admin; workspaces can be created in the Console (`platform.claude.com/settings/workspaces`) or via the Admin API (`/v1/organizations/workspaces`). Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **Claude Code auto-creates a dedicated "Claude Code" workspace.** When a member first signs in to Claude Code with a Console account, Anthropic creates a Claude Code workspace, mints a per-user key there (keys cannot be created manually in it), rate-limits it separately, and it is the only workspace supporting per-user monthly spend limits; archiving it disables Claude Code sign-in through Console billing. Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **Individual Console accounts must create an organization before using the Admin API.** The Admin API is available to Claude Console and Claude Enterprise organizations but not to claude.ai Team plan organizations or individual Console accounts; individuals set up an organization at `platform.claude.com/settings/organization`. Source: https://platform.claude.com/docs/en/manage-claude/admin-api
- **Claude Platform on AWS provisions a new Anthropic organization tied to the AWS account.** Signing up via the AWS Console creates a new Anthropic organization bound to the AWS account; existing first-party organizations cannot be converted and their keys and settings do not carry over; the AWS Console checks for and prompts acceptance of any private offer. Launched 2026-05-11. Source: https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws ; https://platform.claude.com/docs/en/about-claude/pricing ; https://platform.claude.com/docs/en/release-notes/overview
- **Claude Models on Google Cloud (Anthropic managed) provisions a new Anthropic organization per Google Cloud project.** Setup requires Google Cloud Marketplace purchase permission, permission to enable `claude.googleapis.com` and `anthropic-managed-claude.cloudpartnerservices.goog`, and creates an organization separate from any existing Anthropic or Claude Enterprise organization. Launched 2026-10-22. Source: https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/anthropic-managed ; https://platform.claude.com/docs/en/release-notes/overview
- **Claude in Microsoft Foundry is provisioned as Foundry resources and deployments in an Azure subscription.** A Foundry resource holds security and billing configuration and Claude deployments inside it are the callable model instances; the first deployment requires accepting Azure Marketplace terms. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry
- **Amazon Bedrock access requires a one-time Anthropic use case form per AWS account.** Submit the use case form from the Bedrock Model catalog (access granted immediately) or once from the AWS Organizations management account via `PutUseCaseForModelAccess` (`bedrock:PutUseCaseForModelAccess`), which extends to child accounts. Source: https://code.claude.com/docs/en/amazon-bedrock
- **Bedrock sets access criteria per Claude model.** On the `bedrock-mantle` endpoint, Claude Fable 5.1, Fable 5, Opus 4.8, Sonnet 5, Opus 4.7 and Haiku 4.5 are open to all Bedrock customers; Mythos models require verification; other models' criteria are shown in Bedrock model access. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock
- **Claude Enterprise is sales-contracted; Team is self-serve.** Team is a self-service plan (2 to 150 seats); Enterprise is obtained via Anthropic sales. Source: https://claude.com/pricing ; https://code.claude.com/docs/en/iam
- **Day-one asks for an engineer joining a client engagement.** Ask for: which surface the client uses (Claude API direct, Claude Platform on AWS, Bedrock, Google Cloud Anthropic-managed or Google-managed, Foundry) since each has a different identity and billing model; the organization ID and target `wrkspc_` workspace ID; a service account (`svac_...`) or federation rule (`fdrl_...`) created by an org admin, or a workspace-scoped personal key; workspace rate and spend limits; whether ZDR, HIPAA readiness or IP allowlisting are enabled (these change which features and call patterns work). (secondary: synthesis of cited docs) Source: https://platform.claude.com/docs/en/manage-claude/authentication ; https://platform.claude.com/docs/en/manage-claude/workload-identity-federation

## 2. Identity and authentication
- **Claude API supports three authentication methods.** Static API keys (`sk-ant-api...`, sent as `Authorization: Bearer` or legacy `x-api-key`), Workload Identity Federation (short-lived tokens exchanged from an IdP token), and App Attest (for iOS/macOS apps; 1-hour tokens scoped to a workspace, Messages API only). Source: https://platform.claude.com/docs/en/manage-claude/authentication
- **Claude API key types: personal key, service account key, workspace key (legacy).** A personal key acts as the user and stops working when the user leaves; a service account key acts as a service account (`svac_...`) and stops working when the service account is archived; a workspace key belongs to no identity and is legacy. Anthropic recommends identity-backed keys or WIF for new integrations. Personal and service account keys available since 2026-08-27. Source: https://platform.claude.com/docs/en/manage-claude/authentication ; https://platform.claude.com/docs/en/release-notes/overview
- **Personal and service account keys can be scoped to one workspace or to all workspaces the identity can access.** A key not scoped to a workspace must send the `anthropic-workspace-id` header on every request, otherwise the API returns 400 `invalid_request_error`; an inaccessible workspace returns 404. Source: https://platform.claude.com/docs/en/manage-claude/authentication
- **API keys are created only in the Console, not via the Admin API.** The Admin API can only list, rename and change the status of keys; each key reports `expires_at`, `principal` (`user_actor`, `service_account_actor` or `null` for workspace keys) and `scope` (`workspace` or `organization`). Source: https://platform.claude.com/docs/en/manage-claude/admin-api
- **API key expiration is set at creation and cannot be changed.** Presets are 3 hours, 1 day, 7 days, 30 days, custom, or Never; an organization maximum-expiration policy removes Never; expired keys return `401 authentication_error` and cannot be reactivated. Available since 2026-07-08. Source: https://platform.claude.com/docs/en/manage-claude/authentication ; https://platform.claude.com/docs/en/release-notes/overview
- **Workload Identity Federation (WIF) is the keyless option for workloads.** Workloads exchange an IdP-issued JWT at `POST /v1/oauth/token` (RFC 7523 `jwt-bearer` grant) for a short-lived `sk-ant-oat01-...` token acting as a service account; supported IdPs include AWS IAM, Google Cloud, Microsoft Entra ID, GitHub Actions, Kubernetes, SPIFFE, Okta and any OIDC issuer. Launched 2026-05-04. Source: https://platform.claude.com/docs/en/manage-claude/workload-identity-federation ; https://platform.claude.com/docs/en/release-notes/overview
- **WIF uses three resources: service account, federation issuer, federation rule.** Federation issuers (`fdis_...`) register an OIDC provider; federation rules (`fdrl_...`) match JWT claims (`subject_prefix`, `audience`, claims map, or CEL `condition`) to a target service account and an OAuth `scope` (default `workspace:developer`). Setup requires the admin, owner or primary owner role, via the Console Connect workload wizard at `platform.claude.com/settings/workload-identity-federation`. Source: https://platform.claude.com/docs/en/manage-claude/workload-identity-federation
- **WIF token lifetime is 60 to 86,400 seconds, default 3,600.** Minted token lifetime is the lesser of the rule's `token_lifetime_seconds` and twice the IdP JWT's remaining lifetime (minimum 60 s); the Console wizard prefills 600 s; JWTs with a `jti` are single-use by default. Source: https://platform.claude.com/docs/en/manage-claude/workload-identity-federation
- **WIF SDK environment variables.** Set `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_SERVICE_ACCOUNT_ID`, `ANTHROPIC_WORKSPACE_ID` and `ANTHROPIC_IDENTITY_TOKEN_FILE`; a leftover `ANTHROPIC_API_KEY` outranks federation in SDK credential precedence and silently overrides it; `ant auth status` reports which credential won. Source: https://platform.claude.com/docs/en/manage-claude/workload-identity-federation
- **Service accounts are the closest thing to an agent identity.** A Claude service account (`svac_...`) is a non-human identity with no email, password or Console login, implicitly a member of the Default Workspace and added to other workspaces explicitly; no separate "agent identity" type was found in the docs. Source: https://platform.claude.com/docs/en/manage-claude/workload-identity-federation
- **Admin API accepts three credential types.** An Admin API key (`sk-ant-admin...`, created only by organization admins), an OAuth bearer token with `org:admin` scope (admin, owner or primary owner; obtained with `ant auth login --profile admin --scope "org:admin"`), or a personal/service account key that is not workspace-scoped; service-account, federation-issuer and federation-rule endpoints accept only `org:admin` OAuth tokens. Source: https://platform.claude.com/docs/en/manage-claude/admin-api
- **Claude Enterprise Admin API keys are scoped and created in claude.ai.** Created at claude.ai > Organization settings > API with prefix `sk-ant-api01-`; the primary owner can grant any scope, organization owners only Compliance API scopes; scopes include `read:members`, `write:members`, `read:rbac_groups`, `write:rbac_groups`, `read:plugins`, `write:plugins`, `read:claude_tag`, `write:claude_tag`, `read:spend_limits`, `write:spend_limits`, `read:analytics`, `read:compliance_activities`, `read:compliance_user_data`, `delete:compliance_user_data`, `read:compliance_org_data`, `read:org_audit`. Source: https://platform.claude.com/docs/en/manage-claude/admin-api-keys
- **Human SSO supports SAML and OIDC for Team, Enterprise and Console organizations.** Domains are verified with a DNS TXT record (all from one IdP); setup guides cover Okta, Entra ID, Google Workspace, OneLogin, JumpCloud, Duo and Ping; admins can toggle "Require SSO for Claude" and "Require SSO for Console"; JIT users get the User role by default and group mappings can assign roles or seat tiers. Article updated 2026-10-13. Source: https://support.claude.com/en/articles/13132885-setting-up-single-sign-on-sso
- **SCIM provisioning exists and makes IdP-managed members read-only via API.** Groups with `source_type: scim` are read-only through the Admin API; organizations with JIT or SCIM provisioning cannot create invites via the API and role updates/removals for IdP-managed users return 400. Plan-level SCIM availability (Team vs Enterprise) was not stated. Source: https://platform.claude.com/docs/en/manage-claude/user-management ; https://support.claude.com/en/articles/13132885-setting-up-single-sign-on-sso
- **Domain capture is an Enterprise feature.** Claude for Enterprise adds domain capture, role-based permissions and the Compliance API over Claude for Teams. Source: https://code.claude.com/docs/en/iam
- **Claude Code authentication options.** Claude Pro/Max/Ultra subscription, Claude for Teams or Enterprise account, Claude Console (with or without creating an API key, keyless since v2.1.242), Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, Claude Platform on AWS, a self-hosted Claude apps gateway (corporate SSO), Anthropic profiles and WIF credentials. Source: https://code.claude.com/docs/en/iam
- **Claude Code credential precedence.** Order: cloud provider (`CLAUDE_CODE_USE_BEDROCK` / `CLAUDE_CODE_USE_VERTEX` / `CLAUDE_CODE_USE_FOUNDRY`), `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `apiKeyHelper` output, `CLAUDE_CODE_OAUTH_TOKEN` (one-year token from `claude setup-token`), Anthropic profile/federation credentials, then subscription OAuth from `/login`. Source: https://code.claude.com/docs/en/iam
- **Claude Code credential storage.** macOS Keychain; Linux `~/.claude/.credentials.json` (mode 0600); Windows `%USERPROFILE%\.claude\.credentials.json`; Anthropic profiles live in `~/.config/anthropic` or `%APPDATA%\Anthropic`. Source: https://code.claude.com/docs/en/iam
- **Admins can force Claude Code login method and organization.** Managed settings `forceLoginMethod` (`claudeai`, `console`, `gateway`) and `forceLoginOrgUUID` restrict logins; `allowedProviders` (v2.1.285+) restricts which providers a machine may use (e.g. `anthropic`, `bedrock`, `customEndpoint`). Source: https://code.claude.com/docs/en/iam
- **Amazon Bedrock authentication paths.** Bedrock service role (recommended, `iam:PassRole`), IAM assumed roles via SAML/OIDC/IAM Identity Center (12-hour max session), or Bedrock bearer tokens/API keys (`AWS_BEARER_TOKEN_BEDROCK`; short-term keys up to 12 hours; admins can deny long-term keys with a `bedrock:BearerTokenType` condition on `bedrock:CallWithBearerToken`). Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock ; https://code.claude.com/docs/en/amazon-bedrock
- **Claude Platform on AWS authenticates with SigV4 or AWS-issued API keys.** SigV4 uses service name `aws-external-anthropic`; API keys are created in the AWS Console (Claude Console keys do not work); outbound web identity federation must be enabled once per account with `aws iam enable-outbound-web-identity-federation`; OAuth authentication is not available. Source: https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws
- **Claude Models on Google Cloud (Anthropic managed) uses Google credentials only, no API keys.** Application Default Credentials authenticate calls through the `claude.googleapis.com` gateway; API keys cannot be created in that organization's Console; Console sign-in is via the Google Cloud console (no email sign-in). Source: https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/anthropic-managed
- **Microsoft Foundry supports API keys and Microsoft Entra ID tokens.** Keys are sent in `api-key` or `x-api-key`; Entra tokens use scope `https://ai.azure.com/.default` in `Authorization: Bearer`; Claude Mythos models require Entra ID; SDK env vars `ANTHROPIC_FOUNDRY_API_KEY`, `ANTHROPIC_FOUNDRY_RESOURCE`, `ANTHROPIC_FOUNDRY_BASE_URL`. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry
- **MFA enforcement for Claude accounts was not documented on the pages reviewed.** MFA is delegated to the customer IdP when SSO is required. (unverified) Source: https://support.claude.com/en/articles/13132885-setting-up-single-sign-on-sso

## 3. Roles and permissions
- **Claude Console organization roles (API values).** `user` (playground), `claude_code_user` (playground and Claude Code), `developer` (playground and manage API keys), `billing` (playground and billing), `admin` (all of the above plus manage users); owners and primary owners have all admin permissions and can manage admins. Source: https://platform.claude.com/docs/en/manage-claude/admin-api
- **Support article lists six Console roles including Limited Developer.** User, Claude Code User, Limited Developer (manage API keys and webhook endpoints, view usage/cost, manage vaults and credentials), Developer (adds view session traces and download files), Billing, Admin (adds manage users, send events to sessions, create MCP tunnels); the Admin API doc table lists five roles, so the support article appears newer. Source: https://support.claude.com/en/articles/10186004-api-console-roles-and-permissions ; https://platform.claude.com/docs/en/manage-claude/admin-api
- **Claude Console workspace roles.** `workspace_user` (playground), Workspace Limited Developer (keys and API; Console-only limits on Managed Agents sessions, memory stores, deployments and file download), `workspace_developer` (keys and API), Workspace Admin (full workspace control), Workspace Billing (inherited from org `billing`, not assignable). Org admins automatically get Workspace Admin in all workspaces; org users and developers must be added explicitly. Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **Least-privilege runtime identity for an agent calling the Claude API.** Create a dedicated workspace for the agent, have an org admin create a service account added only to that workspace, and either issue a service account key scoped to that single workspace with a short expiration or (preferred) bind a WIF federation rule with scope `workspace:developer` to that workspace; set workspace RPM/ITPM/OTPM and monthly spend limits below the org limits. (secondary: synthesis of cited docs) Source: https://platform.claude.com/docs/en/manage-claude/authentication ; https://platform.claude.com/docs/en/manage-claude/workload-identity-federation ; https://platform.claude.com/docs/en/manage-claude/workspaces
- **Resources isolated per workspace.** Files, Message Batches, Skills and prompt caches are isolated per workspace on the Claude API, Claude Platform on AWS and Foundry; on Bedrock and Google-managed Google Cloud prompt caches are isolated per organization. Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **MCP tunnels use a separate OAuth scope.** MCP tunnels are managed with a `workspace:manage_tunnels` OAuth token from WIF, capped at 10 active tunnels per organization; organization developers can view but not change them. Source: https://platform.claude.com/docs/en/manage-claude/workspaces
- **Claude Enterprise organization roles (API values).** `user`, `managed` (permissions from custom roles attached via groups), `owner`, `membership_admin`, `primary_owner`; the API can assign only `user` and `managed`; administrative roles are set in claude.ai settings. Source: https://platform.claude.com/docs/en/manage-claude/user-management
- **claude.ai Team/Enterprise UI roles include Primary Owner, Owner, Admin and User, plus Enterprise custom roles.** Owners and Primary Owners manage Plugins & skills, connectors and server-managed settings; the role labeled Admin does not include the Plugins & skills page; Enterprise custom roles (Organization settings > Roles) grant rows such as Libraries and Identity & Access. Source: https://claude.com/docs/plugins/admin.md ; https://code.claude.com/docs/en/server-managed-settings
- **Claude for Government uses only User, Owner and Primary Owner roles.** Up to three active Primary Owners; tenant administrator is a separate tenant-level membership; no Billing or Developer roles. Source: https://claude.com/docs/government/org-admin/users.md
- **Who grants what on the Claude API side.** Workspaces, service accounts, federation issuers/rules and Admin API keys are created by Claude Console org admins (or owners/primary owners); Claude Enterprise scoped admin keys are created by the primary owner (any scope) or owners (Compliance scopes only). Source: https://platform.claude.com/docs/en/manage-claude/workspaces ; https://platform.claude.com/docs/en/manage-claude/admin-api-keys
- **Claude Platform on AWS IAM actions.** `aws-external-anthropic:CreateInference` (API calls), `aws-external-anthropic:CallWithBearerToken` (API key use), `aws-external-anthropic:AssumeConsole` (Console access), plus `sts:GetWebIdentityToken` and `sts:TagGetWebIdentityToken`; workspaces are IAM resources with ARNs like `arn:aws:aws-external-anthropic:<region>:<account>:workspace/wrkspc_...`; Console roles are Admin and Developer; membership is managed via AWS IAM. Source: https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws
- **Amazon Bedrock IAM for Claude.** `bedrock-mantle:CreateInference` (and `bedrock-mantle:CountTokens`) for the `bedrock-mantle` Messages endpoint; `bedrock:InvokeModel`, `bedrock:InvokeModelWithResponseStream`, `bedrock:ListInferenceProfiles`, `bedrock:GetInferenceProfile` plus `aws-marketplace:ViewSubscriptions`/`Subscribe` (conditioned on `aws:CalledViaLast = bedrock.amazonaws.com`) for `bedrock-runtime`; scope Resource to specific model or inference-profile ARNs for least privilege. Source: https://code.claude.com/docs/en/amazon-bedrock ; https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock
- **Google Cloud IAM roles for Claude Models on Google Cloud (Anthropic managed).** `roles/claude.viewer` (read-only), `roles/claude.user` (send messages, count tokens, manage batches, files, skills and Managed Agents resources), `roles/claude.admin` (adds organization-level routes and is the only role that can open the Claude Console); roles are granted per project and apply to every workspace in it. Source: https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/anthropic-managed
- **Google Cloud IAM for Claude Models on Google Cloud (Google managed).** Caller needs `aiplatform.endpoints.predict`, e.g. Agent Platform User `roles/aiplatform.user`. Source: https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed
- **Azure RBAC for Claude in Microsoft Foundry.** Callers need an Azure RBAC role such as Foundry User or Cognitive Services User on the Foundry resource; 403 indicates a missing role. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry

## 4. Governance, security and compliance
- **IP allowlisting is in beta for Console and Enterprise organizations.** Org admins/owners (Console) or owners/primary owners (Enterprise) set up to 1,000 public IPv4/IPv6 entries (no broader than /8 or /32); blocked API calls get 403 `permission_error`; covers Messages, Batches, Token Counting, Models, Files, Skills, Managed Agents endpoints, Admin API and Compliance API; changes take up to 15 minutes; does not apply to Bedrock, Claude Platform on AWS, Google Cloud or Foundry. Launched in beta 2026-11-05. Source: https://platform.claude.com/docs/en/manage-claude/ip-allowlist ; https://platform.claude.com/docs/en/release-notes/overview
- **Private network connectivity for the direct Claude API was not found.** No PrivateLink or private endpoint offering for `api.anthropic.com` appeared in the docs reviewed; private networking is available through the cloud platforms, e.g. Foundry resources can be added to an Azure Virtual Network (Private Link). (unverified for direct API) Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry
- **Data residency uses two settings: inference geo and workspace geo.** `inference_geo` per request is `"global"` (default) or `"us"`; workspaces can set `allowed_inference_geos` and `default_inference_geo` (Console or Admin API `data_residency` field); workspace geo (storage at rest and endpoint processing) is fixed at workspace creation and only `"us"` is available. Supported on Claude 4.6 and later models; earlier models return 400. Source: https://platform.claude.com/docs/en/manage-claude/data-residency
- **US-only inference costs 1.1x.** `inference_geo: "us"` applies a 1.1x multiplier to all token categories on Claude 4.6+ models on the Claude API, Claude Platform on AWS and Google Cloud (Anthropic managed); Foundry US Data Zone Standard deployments apply the same 1.1x; rate limits are shared across geos. Source: https://platform.claude.com/docs/en/manage-claude/data-residency ; https://platform.claude.com/docs/en/about-claude/pricing
- **Legacy US-only opt-outs were migrated automatically.** Organizations that previously opted out of global routing were configured with `allowed_inference_geos: ["us"]` and `default_inference_geo: "us"`. Source: https://platform.claude.com/docs/en/manage-claude/data-residency
- **Bedrock and Google-managed Google Cloud set residency by endpoint, not `inference_geo`.** Bedrock offers global and regional endpoints plus US/EU/JP/AU inference profiles; Google-managed offers global, `us`/`eu` multi-region and regional endpoints; regional and multi-region endpoints carry a 10% premium for Claude 4.5+ models; Google-managed regional endpoints serve only Claude Sonnet 4.6 and earlier. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock ; https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed ; https://platform.claude.com/docs/en/about-claude/pricing
- **Commercial Terms prohibit training on customer content.** Section B of the Anthropic Commercial Terms of Service states "Anthropic may not train models on Customer Content from Services" (terms version effective 2025-06-17). Source: https://www.anthropic.com/legal/commercial-terms
- **Commercial products are not used for training by default, with feedback and opt-in exceptions.** Inputs and outputs from Claude for Work and the API are not used for training by default; submitted feedback (thumbs up/down) may be used and is kept up to 5 years; Team/Enterprise Primary Owners and Owners can disable member feedback via the "Rate chats" setting. Article updated 2026-08-18. Source: https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training
- **Default API retention is 30 days per the privacy center.** Anthropic automatically deletes API inputs and outputs on its backend within 30 days of receipt or generation, except for user-controlled storage (e.g. Files API), ZDR agreements, Usage Policy enforcement and legal requirements; flagged content is kept up to 2 years and classifier scores up to 7 years. Article updated 2026-07-01. Source: https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data
- **The API data retention doc states conversation content is not retained by default.** It says prompts and outputs are not retained by default except for Covered Models (30-day retention) and that retained data is never used for training without express permission; this wording differs from the privacy center's "within 30 days" statement and its date is not shown. Source: https://platform.claude.com/docs/en/manage-claude/api-and-data-retention
- **Zero data retention (ZDR) is a per-organization arrangement obtained through sales.** Under ZDR Anthropic does not store prompts or responses at rest after the response; it covers the Messages and Token Counting APIs for eligible features and Claude Code with Commercial-organization API keys; each new organization must be enabled separately; ZDR organizations cannot call the API from a browser (CORS rejected). Source: https://platform.claude.com/docs/en/manage-claude/api-and-data-retention
- **ZDR does not cover several products.** Not covered: Claude Console/playground, Claude Managed Agents (except self-hosted), consumer plans, Team and Enterprise product interfaces (except Claude Code on Enterprise's separate ZDR offering), Claude for Excel, Covered Models, third-party integrations; stateful features such as Agent Skills and code execution are "No" for ZDR but are not blocked. Source: https://platform.claude.com/docs/en/manage-claude/api-and-data-retention
- **Covered Models require 30-day retention.** Claude Fable 5.2, Mythos 5.2, Fable 5.1, Mythos 5.1, Fable 5 and Mythos 5 require 30-day retention and are not available under ZDR unless Anthropic authorizes it; ZDR organizations can enable "Standard data retention" for a non-default workspace to use them. Fable 5 rule since 2026-06-09; 5.2 models since 2026-11-09. Source: https://platform.claude.com/docs/en/manage-claude/api-and-data-retention ; https://platform.claude.com/docs/en/release-notes/overview

## 5. Commercial model
- **Claude API is billed per token (USD per million tokens).** Pricing page URLs: https://claude.com/pricing (www.anthropic.com/pricing redirects there) and https://platform.claude.com/docs/en/about-claude/pricing. Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Per-model prices shown 2026-11-14 (input/output per MTok).** Claude Fable 5.2 $8/$40; Fable 5.1 and Fable 5 $10/$50; Opus 5.5 $4/$20; Opus 5 and Opus 4.5 to 4.8 $5/$25; Sonnet 5.5 and Sonnet 5 $2/$10; Sonnet 4.5/4.6 $3/$15; Haiku 5.5 $0.10/$0.50 (prompts up to 100k tokens) and $0.50/$2.50 (over 100k); Haiku 4.5 $1/$5. Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Prompt caching multipliers shown 2026-11-14.** 5-minute cache write 1.25x base input, 1-hour cache write 2x, cache read 0.1x on most models, 0.05x on Opus 5.5 and Sonnet 5.5, 0.025x on Fable/Mythos 5.1 and 5.2; multipliers stack with batch and data residency. Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Batch API discount is 50% on input and output.** Shown 2026-11-14 (e.g. Opus 5.5 batch $2/$10 per MTok); fast mode is not available with Batch. Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Fast mode is a premium speed tier.** Up to 2.5x output tokens/second; shown 2026-11-14: Fable 5.2 and Mythos 5.2 $16/$80, Opus 5.5 $8/$40, Opus 5/4.8 $10/$50 per MTok. Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Long context is billed at standard rates on Claude 4.6+ models.** The 1M-token context window is included at standard pricing (except Haiku 5.5, which has a 100k-token price threshold). Source: https://platform.claude.com/docs/en/about-claude/pricing
- **Priority Tier is legacy and no longer sold.** Priority Tier capacity commitments (input/output TPM, 1/3/6/12 months, specific model, 99.5% uptime target) are no longer available for purchase; existing commitments run to contract end; `service_tier` accepts `"auto"` or `"standard_only"`; not supported on Claude 5.x models. Source: https://platform.claude.com/docs/en/api/service-tiers
- **Usage tiers carry monthly spend caps.** Start $500, Build $1,000, Scale $200,000 per month; Custom tier has no cap; new organizations may start in an Evaluation tier; at the cap requests return 429 `rate_limit_error` with `error_code: enforced_spend_limit_reached` and no `retry-after`. Source: https://platform.claude.com/docs/en/api/rate-limits
- **Org and workspace spend limits.** Org admins set a monthly spend limit at `platform.claude.com/settings/spend-limits` up to the tier cap; workspace monthly spend limits are set on the Workspaces page (not on the Default Workspace); hitting a self-set limit returns 400 `invalid_request_error`. Source: https://platform.claude.com/docs/en/api/rate-limits ; https://platform.claude.com/docs/en/manage-claude/workspaces
- **Workspace rate limits are set per model and limiter.** RPM, ITPM and OTPM per workspace, below org limits, via Console Rate limits page or the Rate Limits API (released 2026-04-24); ITPM counts only uncached input plus cache writes. Source: https://platform.claude.com/docs/en/api/rate-limits ; https://platform.claude.com/docs/en/release-notes/overview
- **Claude plans shown 2026-11-14.** Free $0; Pro $17/month billed annually or $20 monthly; Max $100/month; Ultra $200/month; Team (2 to 150 seats) Standard $20/seat/month annual ($25 monthly) and Premium $100/seat/month annual ($125 monthly) with 5x Standard usage; Enterprise $20/seat/month billed annually, 20-seat minimum, plus usage at API rates. - **Claude Enterprise per-user spend limits are managed via the Spend Limits API.** Requires `read:spend_limits` / `write:spend_limits` scopes on an Enterprise admin key. Source: https://platform.claude.com/docs/en/manage-claude/admin-api-keys
- **Claude Platform on AWS and Foundry bill in Claude Consumption Units (CCUs).** Usage is rated at standard per-model rates, discounted, converted at $0.01 per CCU, metered hourly to AWS Marketplace or Azure Marketplace, and invoiced monthly in arrears (no prepaid credits). Source: https://platform.claude.com/docs/en/about-claude/pricing

### Feature parity across surfaces
- **Bedrock (`bedrock-mantle`) feature gaps.** Not supported: URL image/document sources, Files API, code execution, web search, web fetch, advisor, Agent Skills, MCP connector, programmatic tool calling, Message Batches, Models, Admin, Compliance and Usage/Cost APIs, Claude Managed Agents, server-side fallback; Fable 5.2 and Mythos 5.2 are served only on `bedrock-runtime`; default quota 2M input TPM. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock
- **Google Cloud (Google managed) feature gaps.** Not supported: URL sources and Files API, code execution, web fetch, advisor, Agent Skills, MCP connector, programmatic tool calling, Batches, Models, Admin, Compliance, Usage/Cost APIs, Managed Agents, server-side fallback; 30 MB payload limit. Source: https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed
- **Microsoft Foundry feature gaps.** Not supported: Admin API, advisor tool, Managed Agents, Compliance API, Models API, Message Batches, server-side fallback, user profile endpoints; Hosted on Azure additionally lacks code execution, newer web search/fetch versions, Agent Skills, programmatic tool calling and Files API; no Anthropic rate-limit headers. Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry
- **Claude Platform on AWS feature gaps.** Not available: HIPAA readiness, OAuth, fast mode, OpenAI-compatible endpoints, Claude Code workspace and analytics API, workspace member management, per-workspace rate limits; the Admin API is limited to workspaces, external keys, telemetry destinations and analytics. Source: https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws ; https://platform.claude.com/docs/en/api/rate-limits ; https://platform.claude.com/docs/en/manage-claude/admin-api
