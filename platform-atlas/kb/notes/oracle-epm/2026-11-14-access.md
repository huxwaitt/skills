# Oracle Fusion Cloud EPM: access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Ordering goes through Oracle Sales; activation is by email.** Oracle Fusion Cloud EPM subscriptions are bought by contacting Oracle Sales (web chat or "Contact sales"), and after the order Oracle emails the designated initial contact with activation and provisioning instructions; the docs offer a "Request a Demo" path but describe no self-service trial. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/idcs_buy_epm_cloud.html
- **Hierarchy is cloud account (tenancy) > subscription > environments, with identity in an identity domain.** The Cloud Account Name is the tenancy, cannot be changed and appears in login URLs; several subscriptions can be activated into one cloud account; environments are created in the Oracle Cloud Console; an identity domain is where Identity Domain Administrators manage users, and several subscriptions can share one identity domain. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/idcs_opc_key_concepts.html
- **Each subscription gives exactly two environments: one test, one production.** A Cloud EPM subscription includes one test and one production environment, designated at creation; more stages (for example dev, test, acceptance, production) require buying another subscription for the extra two environments. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/creating_an_epm_cloud_environment.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/tsepm/7_tips_and_tricks_application_maintenance_mode.html
- **Creating an environment needs the OCI Account Administrator role, and the name is permanent.** The environment name becomes part of the URL and cannot be changed; defaults place it in the home region, default compartment and default identity domain, and test and production can sit in different regions, compartments and identity domains. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/creating_an_epm_cloud_environment.html
- **Administrator onboarding starts with delegation from the Cloud Account Owner.** The Cloud Account Owner (Tenancy Administrator) delegates the administrator role, and the delegate gets an email from `oraclecloudadmin_ww@oracle.com` titled "Action Required: Please Activate Your Services". Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html
- **OCI (Gen 2) URL pattern.** Production is `https://<instance>-<cloudaccount>.epm.<region>.ocs.oraclecloud.com/epmcloud` (for example `https://acme-epmidm.epm.us-phoenix-1.ocs.oraclecloud.com/epmcloud`), and test adds `-test` after the instance name (`https://acme-test-epmidm.epm.us-phoenix-1.ocs.oraclecloud.com/epmcloud`); the Cloud Account Name segment was formerly called the Identity Domain Name. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsus/1_user_epm_cloud_accessing_sample_urls_gen2.html
- **New subscriptions run on OCI; Classic is legacy.** New EPM and EDM subscriptions run on Oracle Cloud Infrastructure using OCI IAM ("OCI (Gen 2)" or "Cloud EPM Gen 2"); some customers remain on Oracle Cloud Classic and use the separate Classic URL format. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsus/1_user_epm_cloud_accessing_sample_urls.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/1_epm_cloud_accessing_sample_urls_classic.html
- **Day-one asks for an engineer on a client engagement.** From the Oracle setup docs, ask for: the test and production environment URLs; a user in the EPM identity domain with the right application role (normally Service Administrator for automation); an OAuth 2 client ID registered by the Identity Domain Administrator (public client with Device Code and Refresh Token grants) plus the environment's scope; any Network Perimeter IP ranges that must include your runner's egress IP; and the environment's daily maintenance start time. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html

## 2. Identity and authentication
- **Identity is OCI IAM identity domains (successor to Oracle Identity Cloud Service, IDCS).** Users, groups, sign-on policies, MFA, SSO federation and OAuth clients for Cloud EPM are managed in the identity domain tied to the environment; Oracle EPM docs still often say "Oracle Identity Cloud" or "IDCS" for this layer. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/idcs_opc_key_concepts.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html
- **Two auth methods for REST and EPM Automate: Basic and OAuth 2; Oracle recommends OAuth 2.** Oracle states it supports OAuth 2 and Basic Authentication for Cloud EPM REST APIs and recommends OAuth 2 as more secure. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmai/published_apis_through_external_ai_tools.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_automate_oauth.html
- **REST Basic Auth uses the `Authorization: Basic` header.** The username can be `identitydomain.username` or just `username`; the identity domain name appears in the Activity Report and in the URL between `epm-` (or `epm-test-`) and the next dot. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/authentication_overview.html
- **Classic used `identitydomain.username` for Basic Auth; OCI uses the plain `username`.** Oracle's Classic-vs-OCI comparison table says this; the page could not be fetched today, so the claim comes from a search snippet and the sister Narrative Reporting REST guide. (unverified) Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/idcs_oci_classic_diffs.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-reporting-cloud/raepr/eprcs_security.html
- **Basic Auth and EPM Automate do not work with SSO credentials or with MFA-enabled basic users.** EPM Automate and EPM Agent use basic authentication, which does not accept SSO credentials, so these users must keep identity domain (traditional) credentials; `epmautomate login` is not supported for basic-auth users with MFA; and REST APIs cannot be run by users configured for Basic Authentication with MFA. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/3_sso_config_chap_enable_idm_credentials.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_login.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmai/published_apis_through_external_ai_tools.html
- **OAuth 2 for Cloud EPM REST is a user-context public client, not client credentials.** The Identity Domain Administrator registers a "Mobile Application" (public client) integrated app, adds the EPM resources, sets each EPM base URL (without `/epmcloud`) as a secondary audience, enables "Allow token refresh", and selects only the Refresh Token and Device Code grants (not Implicit); other grants (Authorization Code, Resource Owner Password, Assertion) are allowed only if the token is in an end-user context. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **OAuth scope format is per environment.** The scope is `urn:opc:serviceInstanceID=<SERVICE_INSTANCE_ID>urn:opc:resource:consumer::all`, with ` offline_access` appended when requesting the first refresh token; you cannot request scopes for more than one EPM environment in one request, and a token works only for the environment it was issued for. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **Bootstrap with the device-code flow, then rotate refresh tokens.** `POST https://idcs-<id>.identity.oraclecloud.com/oauth2/v1/device` with `response_type=device_code`; a human signs in at `verification_uri` as the user who will invoke the APIs and enters the `user_code` (it expires in 300 s); `POST .../oauth2/v1/token` with `grant_type=urn:ietf:params:oauth:grant-type:device_code` returns the first refresh token; later calls use `grant_type=refresh_token`, and the API is called with `Authorization: Bearer <access token>`. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **Token lifetimes: access token 1 hour, refresh token 7 days, single use.** Sample responses show `expires_in: 3600`; refresh tokens expire after 7 days and are single use, and each refresh returns a new one that must replace the old one; Oracle advises refreshing at least every 6 days for unattended jobs; Service Administrators can change expiry on the service's OAuth configuration page. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **Use one refresh token per script.** Scripts that share a refresh token fail at random with `invalid_grant` "The token has already been consumed"; run the device-code bootstrap once per script, and all scripts can share one `client_id`. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **The access log records the user, not the OAuth client.** With OAuth, the EPM access log shows the user name (as with basic auth) but not the client ID or token, so an automation account's actions are attributed to the user who completed the device-code sign-in. Source: https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html
- **EPM Automate OAuth: encrypt refresh token and client ID into an `.epw` file.** Run `epmautomate encrypt REFRESH_TOKEN ENCRYPTION_KEY PASSWORD_FILE.epw ClientID=CLIENT_ID`, then `epmautomate login <ignoredUsername> OAuth2.epw <URL>`; with OAuth the USERNAME argument is ignored and taken from the token; OAuth is enforced per application, and basic auth still works when OAuth is enabled. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_automate_oauth.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_login.html
- **The Login username-ignored behaviour was documented in October 2025.** The 25.10 readiness note "Login EPM Automate Command Documentation Clarification When Using oAuth2 Token" documents that the username is ignored when an OAuth 2 token file is used. Source: https://docs.oracle.com/en/cloud/saas/readiness/epm/2025/epm-oct25/25oct-epm-wn-f41517.htm
- **Some EPM Automate user commands do not accept OAuth.** `addUsers`, `removeUsers`, `assignRole` and `unassignRole` require basic authentication; all other EPM Automate commands work with OAuth 2.0. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_login.html
- **The REST user and role APIs show both Basic and Bearer samples.** The REST pages for Add Users to an Identity Domain (v2, `POST /interop/rest/security/v2/users/add`) and Assign Role (v1, `PUT /interop/rest/security/v1/users` with `jobtype=ASSIGN_ROLE`) include both `-u user:password` and `Authorization: Bearer` cURL samples, unlike the EPM Automate equivalents. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/lcm_add_user_to_identity_domain_v2.html ; https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/lcm_assign_role.html
- **EPM Automate password files use AES-256 and the `.epw` extension.** `epmautomate encrypt PASSWORD|REFRESH_TOKEN KEY PASSWORD_FILE [ClientID=...] [ProxyServerPassword=...]` encrypts with AES/CBC/PKCS5Padding(256); the default location is `ProgramData\Oracle\EPM Automate` on Windows and the current directory on Linux; corporate (SSO) credentials cannot be encrypted or used; any application role can run it. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_encrypt.html
- **`epmautomate login` syntax and proxy support.** `epmautomate login USERNAME PASSWORD|PASSWORD_FILE URL [IDENTITYDOMAIN] [ProxyServerUserName=...] [ProxyServerPassword=...] [ProxyServerDomain=...] [KeystorePassword=...]`; IDENTITYDOMAIN is derived from the URL and ignored; vanity and API gateway URLs (for example Apigee) are supported; proxy auth supports Basic, Digest, Kerberos, Negotiate and NTLM but not SOCKS. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_login.html
- **The AI Agent Studio integration uses a Trusted confidential app with client credentials and JWT assertion.** To connect Fusion AI Agent Studio to Cloud EPM or EDM REST, an Identity Domain Administrator of the EPM domain creates a confidential application, enables Client Credentials and JWT assertion, changes the client type to Trusted, imports a public certificate (the private key stays in AI Agent Studio), and sets the Token Issuance Policy to Specific with EPM service resources and scopes. This is the only documented confidential-client pattern for EPM. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/create_a_confidential_application_for_epm_integration_with_fusion_ai_agent_studio.html
- **Human SSO is SAML 2.0 federation in the identity domain.** Supported SAML 2.0 IdPs include Microsoft Entra ID, Oracle Identity Federation, Okta, Ping Identity PingFederate and Shibboleth. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/3_sso_config_chap_idcs_oci_azure.html
- **Entra ID SAML values point at the identity domain.** In Entra, use the "Oracle Cloud Infrastructure Console" gallery app with Identifier `https://idcs-<id>.identity.oraclecloud.com:443/fed`, Reply URL `https://idcs-<id>.identity.oraclecloud.com:443/fed/v1/sp/sso`, Logout `.../fed/v1/sp/slo`, and Name ID (for example `user.mail`) matching the domain's requested NameID format. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/3_sso_config_chap_idcs_oci_azure_config.html
- **SSO-enabled environments show two sign-in options by default.** Users see "Company Sign-In" and "Traditional Cloud Account Sign-In"; an Identity Domain Administrator can hide traditional sign-in for browser users by removing "Username-Password" from the default IdP policy rule, but integration accounts still need identity domain credentials. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/3_sso_config_chap_enable_idm_credentials.html
- **SCIM user and group sync is supported.** You can optionally use SCIM to sync users and groups into the identity domain from systems such as Microsoft Entra ID; bulk creation also works via `epmautomate addUsers` or the REST API Add Users to an Identity Domain. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/iam_chapter_intro.html
- **MFA lives in the identity domain.** The Identity Domain Administrator and Security Administrator configure MFA and authentication factors in OCI IAM; users enroll an authenticator app (Oracle Mobile Authenticator, Google Authenticator) via "Enable Secure Verification". Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/appman_access_rerequisites.html
- **No dedicated agent identity type, and no keyless or workload identity federation for EPM.** Cloud EPM documents no identity type made for AI agents and no federation from GitHub Actions or other clouds. Automation runs as an identity domain user via Basic Auth or user-context OAuth refresh tokens; Oracle's EPM Agent Skills Shared Authentication skill documents only Basic Auth from a private config file (URL, name, username, password). Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmai/shared_authentication.html ; https://docs.oracle.com/en/cloud/saas/epm-cloud/prest/authentication_oath.html

## 3. Roles and permissions
- **Terminology changed in 2026: "Application Role" now means the four domain-level roles; business-process roles are "granular roles".** From the May 2026 (26.05) update, Cloud EPM labels Service Administrator, Power User, User and Viewer "Application Role" (previously "Predefined Roles"), and business-process-specific roles (previously "application roles") are "granular roles"; in June 2026 (26.06) the Access Control tab "Manage Application Roles" became "Manage Granular Roles". Older docs and scripts use the old names. Source: https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-may26/26may-epm-wn-f47257.htm ; https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-apr26/26apr-epm-wn-f40977.htm ; https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-jun26/26jun-epm-wn-f49898.htm
- **The four Cloud EPM application roles form a hierarchy.** Service Administrator > Power User > User > Viewer, and each higher role inherits the lower roles' access; what each role grants varies by business process; non-Service Administrator access also depends on each dimension's "Apply Security" setting, which Oracle recommends enabling. Source: https://docs.oracle.com/cloud/latest/epm-common/CGSAD/4_managing_epm_cloud_users_roles_predefined_roles.htm
- **Enterprise Data Management uses only Service Administrator and User.** Assigning Power User or Viewer in EDM grants no privileges. Source: https://docs.oracle.com/cloud/latest/epm-common/CGSAD/4_managing_epm_cloud_users_roles_predefined_roles.htm
- **A user with no application role cannot see the environment.** Users without an application role do not appear in EPM or EDM environments, and EPM Automate login then fails with "User does not exist for this application". Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/tsepm/7_tips_and_tricks_troubleshoot_access_issues_epm_automate_insufficient_priv.html
- **Most EPM Automate commands need Service Administrator.** Error `EPMAT-9: Insufficient Privileges To Perform the Operation` means the user's role does not permit the command (for example a User running `downloadFile`); Oracle notes most commands are restricted to Service Administrators. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/tsepm/7_tips_and_tricks_troubleshoot_access_issues_epm_automate_insufficient_priv.html
- **Data and metadata jobs need Service Administrator.** `epmautomate importData JOB_NAME [FILE] errorFile=...` and `epmautomate importMetadata JOB_NAME [FILE] errorFile=...` list Service Administrator as the required role, and the job must already be defined in the Jobs console. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_import_data.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_import_metadata.html
- **Data load rules and business rules can run as Power User.** `runDataRule` requires Service Administrator or Power User; `runBusinessRule` requires Service Administrator or Power User (only when Launch access to the rule is granted). Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_run_data_rule.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_run_business_rule.html
- **Snapshot, clone and maintenance-time commands accept a non-admin with the "Migrations - Administer" granular role.** `exportSnapshot`, `importSnapshot`, `copySnapshotFromInstance`, `cloneEnvironment` and `setDailyMaintenanceStartTime` each list "Service Administrator" or "Any application role and the Migrations - Administer granular role". Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_export_snapshot.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_import_snapshot.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_copy_snapshot_from_instance.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_clone_environment.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_set_daily_maint_start.html
- **Importing users from a snapshot or cloning users requires Identity Domain Administrator.** `importSnapshot ... importUsers=true` needs the Identity Domain Administrator role, otherwise the Migration Status Report shows "User ... is not authorized"; `cloneEnvironment UsersAndApplicationRoles=true` needs a target Service Administrator who also holds Identity Domain Administrator, and the Identity Domain Administrator assignment itself is not cloned. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_import_snapshot.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_clone_environment.html
- **User provisioning needs Identity Domain Administrator plus an application role.** `epmautomate addUsers FILE.csv [userPassword=...] [resetPassword=true|false]` requires "Identity Domain Administrator and any application role"; the users are created in the identity domain and can reach every environment that shares it. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_add_users.html
- **Role assignment: Service Administrator can assign application roles without being a domain admin.** `epmautomate assignRole FILE.csv ROLE` requires Service Administrator, or Identity Domain Administrator plus any application role (for application roles); for granular roles it requires Service Administrator, or any application role plus the "Access Control - Manage" granular role. Customers can ask Oracle to restrict application-role assignment to Identity Domain Administrators. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_assign_roles.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html
- **Seven OCI IAM domain-level admin roles, each with EPM command limits.** Identity Domain Administrator (can run `addUsers`, `removeUsers`, `updateUsers`, `assignRole`, `unassignRole`, `roleAssignmentAuditReport`, `invalidLoginReport` only if also given an application role); Security Administrator; Application Administrator (cannot run `assignRole` or `unassignRole`); User Administrator (cannot run `addUsers`, `removeUsers` or `updateUsers`); User Manager (cannot run `removeUsers` or `updateUsers`); Help Desk Administrator; Audit Administrator (cannot run `roleAssignmentAuditReport` or `invalidLoginReport`). Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html
- **Least-privilege pattern for an automation identity.** From the role tables above, a pipeline that only runs data rules and business rules can use Power User (with rule Launch access); one that runs `importData`, `importMetadata` or most file operations needs Service Administrator; snapshot work can use any application role plus "Migrations - Administer"; user provisioning additionally needs Identity Domain Administrator and, in EPM Automate, basic auth rather than OAuth. This is a synthesis of the per-command role lists. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_run_data_rule.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_import_data.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_login.html
- **Who grants what on the client side.** The Account Administrator creates environments; the Identity Domain Administrator creates users, OAuth clients, SSO federation, sign-on policies and the Network Perimeter; the Service Administrator assigns application and granular roles and manages Access Control groups in the environment. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/creating_an_epm_cloud_environment.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmck/epm_cloud_checklist_id_domain_admin.html
- **Power User folder permission change is coming.** A future update (date not given in the 26.04 notes) will require Power Users to have write access, not just read access, to a folder before creating forms, dashboards or subfolders in it (EPCM, FCCS, FreeForm, Planning, Tax Reporting). Source: https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-apr26/26apr-epm-wn-t74023.htm
- **Compliance document access is an OCI IAM policy.** By default only Service Administrators can download EPM compliance reports; others need policies such as `Allow group G to {EPM_COMPLIANCEDOC_INSPECT, EPM_COMPLIANCEDOC_READ} in tenancy`. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/accessing_soc_compliance_reps.html

## 4. Governance, security and compliance
- **Per-environment IP allowlist commands were removed in May 2026 (26.05); use Network Perimeter.** Oracle removed `setIPAllowList`, `getIPAllowList` and the IPAllowList REST APIs (deprecated earlier) and replaced them with the identity-domain Network Perimeter, which applies allowed or blocked IPs and CIDRs domain-wide and also protects Cloud Console; older EPM Automate versions that run these commands are ignored. Source: https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-apr26/26apr-epm-wn-f46471.htm ; https://docs.oracle.com/en/cloud/saas/readiness/epm/2026/epm-may26/26may-epm-wn-f46472.htm ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/epm_auto_set_ip_allowlist.html
- **Migration path from per-environment allowlists to Network Perimeter.** Oracle's guide says to export each environment's list with `getIPAllowlist` (before removal), merge the unique IPs and CIDRs, and add them to the identity domain's Network Perimeter in Oracle Cloud Console; while both existed, a source IP had to be in both lists. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/migrating_from_ip_allowlist_per_environment_to_network_perimeter_for_an_identity_domain.html ; https://docs.oracle.com/en/cloud/saas/readiness/epm/2024/epm-aug24/24aug-epm-wn-f34558.htm
- **The Network Perimeter covers every EPM and EDM environment in the identity domain.** It restricts sign-in to listed IPs and ranges for all EPM and EDM environments in the designated identity domain. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/setting_up_network_perimeter_for_oci_gen_2_epm_cloud.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/tsepm/ipallowlist_considerations.html
- **Cross-environment calls need Oracle's outbound IPs in the perimeter.** With a Network Perimeter, inbound calls from other EPM environments (`copySnapshotFromInstance`, `cloneEnvironment`, Copy Application Snapshot REST, Navigation Flows) are blocked unless you add the source region's outbound IP (for example us-ashburn-1 = `130.35.200.71`); within one region, add `240.0.0.0/4`. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/tsepm/outbound_ip_address_cloud_dc.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/ability_to_allowlist_ip_addresses_for_connections.html
- **Sign-on policies can limit who signs in.** The default sign-on policy lets any user with an application role sign in with a username and password; an Identity Domain Administrator can add a custom policy (for example, only Service Administrators). ## 5. Commercial model
- **Two current subscription tiers: EPM Standard and EPM Enterprise.** EPM Standard is aimed at small and mid-sized businesses (Planning modules only, one ASO and one BSO cube, no custom Groovy, no Custom Planning, FreeForm, Sales Planning, Strategic Workforce Planning or Predictive Cash Forecasting); EPM Enterprise includes the full suite (multiple cubes, Groovy, Enterprise Journals, Transaction Matching, Tax Provisions, CbCR, Pillar Two, EPCM and PCM, Narrative Reporting Report Notes), all AI and GenAI features, and IPM (except AutoPredict, which Standard Planning also gets). Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/1_about_epm_cloud_new_sku_changes.html
- **Licensed users are those with an application role; domain-admin-only users are free.** Users assigned only a domain-level administrator role do not count toward the Named Users license; only users with application roles (Service Administrator, Power User, User, Viewer) are counted, so every automation or integration account with an application role consumes a named-user seat. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html
- **Oracle provides a script to count licensed users.** The script counts licensed users from `epmautomate roleAssignmentReport` output (one count per user login). Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cepma/sample_script_5_license.html
- **Two licensing metrics: Hosted Named User and Hosted Employee.** Third-party licensing advisers report that EPM Enterprise is sold per Hosted Named User per month or per Hosted Employee (headcount) per month; the Oracle subscriptions page also references hosted-employee and hosted-record limits for EDM. (secondary) Source: https://redresscompliance.com/oracle-epm-cloud-licensing-modules-pricing.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/1_about_epm_cloud_new_sku_changes.html
- **Reported list prices, viewed 2026-11-14.** Advisers cite about USD 250 per named user per month for EPM Standard (10-user minimum) and about USD 500 per named user per month for EPM Enterprise (25-user minimum), and about USD 40 per hosted employee per month for large organisations; Oracle's own price list returned HTTP 403 today. (secondary) (unverified) Source: https://redresscompliance.com/oracle-epm-cloud-licensing-modules-pricing.html ; https://www.oracle.com/performance-management/pricing/
- **What this means for automation accounts.** Under Hosted Named User, every service or integration user with an application role is a billable named user. Under Hosted Employee, seats are headcount-based (secondary). Agent use through EPM Agent Skills or REST adds no separate per-token EPM charge that Oracle documents, but AI features require EPM Enterprise, and EPM Assistants require a separate AI Agent Studio for Fusion Cloud Applications entitlement. Source: https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/administrator_roles_defined_at_the_domain_level.html ; https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/using_ai_agents_for_cloud_epm.html
