# Microsoft 365 Copilot and Power Platform: access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Tenant model: everything hangs off one Microsoft Entra tenant.** Microsoft 365 Copilot, Copilot Chat, Microsoft Agent 365 and Copilot Studio subscriptions are hosted in a Microsoft Entra tenant; agent management happens in the Microsoft 365 admin center (`admin.microsoft.com` / `admin.cloud.microsoft`) under **Agents**. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-365-overview
- **Power Platform hierarchy is tenant > environment group > environment > (optional) Dataverse database.** An environment can have zero or one Dataverse database, and the roles you assign differ depending on whether it has one. Source: https://learn.microsoft.com/power-platform/admin/database-security
- **Environment groups are folders of Managed Environments only.** Each environment belongs to at most one group, groups can't be nested, and group rules lock the matching settings in member environments. Source: https://learn.microsoft.com/power-platform/admin/environment-groups
- **Microsoft 365 Copilot is an add-on that needs a qualifying base license, except in E7.** Eligible commercial bases include Microsoft 365 E3/E5/F1/F3, Business Basic/Standard/Premium, Office 365 E1/E3/E5/F3, plus some Teams, Exchange and SharePoint plans. Microsoft 365 E7 includes Copilot. Source: https://learn.microsoft.com/copilot/plan/copilot-license-options
- **Microsoft Copilot Business is the SMB variant, capped at 300 users per tenant.** It is an annual-commitment add-on for eligible Microsoft 365 Business plans and has the same Copilot capabilities. Source: https://learn.microsoft.com/copilot/plan/copilot-license-options
- **Copilot is also available in US Government clouds.** It is an add-on in GCC, GCC High and DoD for G5/G3/F1 and related plans. Source: https://learn.microsoft.com/copilot/plan/copilot-license-options
- **Copilot Studio needs a tenant license plus per-user licenses.** The tenant license is listed as "Copilot Studio" (a prepaid Copilot Credit pack) and the maker license as "Copilot Studio User License" (free, assignable only after a tenant pack exists). Both are bought in Microsoft 365 admin center > Billing > Purchase services, or both through the same volume-licensing channel. Source: https://learn.microsoft.com/microsoft-copilot-studio/requirements-licensing
- **Other ways to get Copilot Studio maker access.** A maker can also get in through the Power Platform admin center **Copilot Studio authors** security-group setting, a Microsoft 365 Copilot license (Microsoft Copilot harness agents), or a trial license. Trial users can build and test agents but can't publish them. Source: https://learn.microsoft.com/microsoft-copilot-studio/billing-licensing
- **Guest users can't access Copilot Studio.** Users of a published agent need no special license to chat with it. Source: https://learn.microsoft.com/microsoft-copilot-studio/requirements-licensing
- **Admins can block self-service trials.** Set the Entra `AllowAdHocSubscriptions` flag to stop users signing up for Copilot Studio trials themselves. Source: https://learn.microsoft.com/microsoft-copilot-studio/requirements-licensing
- **Agent 365 needs at least one licensed user, and E5 is the recommended prerequisite.** Agent 365 is GA for the Commercial segment and licensed per user. Source: https://learn.microsoft.com/microsoft-agent-365/overview
- **Day-one asks for an engineer joining a client.** (1) A licensed work account in the client tenant: a Microsoft 365 Copilot license, plus a Copilot Studio User License or **Copilot Studio authors** membership. (2) The **Environment Maker** Dataverse role, or **System Customizer** if you must create tables, in a non-default dev environment. (3) An Entra app registration, or permission to request admin consent, for Graph access. (4) Confirmation of who holds **AI Administrator** (agent approval), **Power Platform Administrator** (environments, data policies, capacity) and **Billing Administrator** (Copilot Credits). (secondary: synthesis of the cited pages) Source: https://learn.microsoft.com/microsoft-copilot-studio/admin-share-bots ; https://learn.microsoft.com/microsoft-agent-365/admin/agent-roles-perms
- **Copilot extensibility docs entry point resolves, but the landing now covers "plugins".** https://learn.microsoft.com/microsoft-365-copilot/extensibility/ is titled "Extending Microsoft 365 Copilot with plugins" (updated 2026-11-05) and centres on Work IQ Dev Tools (`wiqd`). Source: https://learn.microsoft.com/microsoft-365-copilot/extensibility/
- **Copilot Studio docs root resolves and is organised by harness.** https://learn.microsoft.com/microsoft-copilot-studio/ (updated 2026-11-12) groups content under Microsoft Copilot harness, Customer Conversation harness (preview) and standard harness. Source: https://learn.microsoft.com/microsoft-copilot-studio/
- **Power Platform and Graph docs roots resolve.** https://learn.microsoft.com/power-platform/ (updated 2026-10-26) and https://learn.microsoft.com/graph/ both load; the Graph hub links to the Microsoft MCP Server for Enterprise and the API changelog (`https://developer.microsoft.com/en-us/graph/changelog`). Source: https://learn.microsoft.com/power-platform/ ; https://learn.microsoft.com/graph/
- **Agent 365 docs root.** https://learn.microsoft.com/microsoft-agent-365/overview, updated 2026-11-11. Source: https://learn.microsoft.com/microsoft-agent-365/overview

## 2. Identity and authentication
- **Microsoft Entra Agent ID is a dedicated identity type for AI agents, available to all Entra customers.** It has four objects: `agentIdentityBlueprint` (template that holds credentials), `agentIdentityBlueprintPrincipal` (the blueprint's record in a tenant), `agentIdentity` (primary runtime identity, no credentials of its own) and the optional `agentUser` (1:1 user account for systems that require a user object). Source: https://learn.microsoft.com/entra/agent-id/key-concepts ; https://learn.microsoft.com/graph/api/resources/agentid-platform-overview?view=graph-rest-beta
- **Agent identities get tokens through their blueprint.** The blueprint holds the credentials and acquires tokens for every agent identity created from it. Conditional Access applied to a blueprint applies to all its agent identities. Source: https://learn.microsoft.com/entra/agent-id/key-concepts
- **Interactive and autonomous agents use different auth flows.** Interactive agents act for a signed-in user with delegated permissions through the on-behalf-of (OBO) flow. Autonomous agents use their own agent identity with the client credentials flow. Source: https://learn.microsoft.com/entra/agent-id/key-concepts
- **Microsoft advises against service principals and user accounts for AI agents.** Its stated reasons are that traditional service principals lack enforced sponsorship, agent-aware audit entries and blueprint-managed lifecycle, and that human user accounts break Conditional Access and ID Protection. Source: https://learn.microsoft.com/entra/agent-id/key-concepts
- **Copilot Studio agents get an Entra agent identity on creation.** The creating user is recorded as sponsor, and the agent's sign-ins are logged in Entra as AI-agent activity. Source: https://learn.microsoft.com/entra/agent-id/what-are-agent-identities
- **Extending Entra security features to agents requires Agent 365.** Agent 365 is included in Microsoft 365 E7, or is an add-on to E5, A5, Business Premium, or Defender Suite plus Purview Suite. Source: https://learn.microsoft.com/entra/agent-id/what-are-agent-identities
- **Agent identities carry owners, sponsors and managers.** Owners are technical admins, sponsors hold business accountability and managers apply to `agentUser`. Entitlement management, access reviews and lifecycle workflows extend to agent identities. Source: https://learn.microsoft.com/graph/api/resources/agentid-platform-overview?view=graph-rest-beta
- **Agent identities can't be granted many high-risk Graph permissions.** Blocked application permissions include `Files.Read.All`, `Sites.Read.All`, `Sites.ReadWrite.All`, `Chat.Read.All`, `Calendars.Read`, `Application.ReadWrite.All`, `Directory.ReadWrite.All`, `User.ReadWrite.All` and `RoleManagement.ReadWrite.Directory`. Requesting one returns HTTP `400 Bad Request`. Source: https://learn.microsoft.com/graph/api/resources/agentid-platform-overview?view=graph-rest-beta ; https://learn.microsoft.com/graph/permissions-overview
- **Old Entra Agent Registry Graph APIs are deprecated.** `agentRegistry`, `agentCardManifest`, `agentInstance` and `agentCollection` are being replaced, starting May 2026, by Agent Registry APIs powered by Microsoft Agent 365. Source: https://learn.microsoft.com/graph/api/resources/agentid-platform-overview?view=graph-rest-beta
- **Copilot Studio end-user authentication has three options.** They are `No authentication`, `Authenticate with Microsoft` (automatic Entra SSO in Teams, SharePoint, Power Apps and Microsoft Copilot; no `User.AccessToken`) and `Authenticate manually`. The manual providers are Entra ID V2 with federated credentials, with certificates (Key Vault URL), or with client secrets, Entra ID, and generic OAuth 2. Source: https://learn.microsoft.com/microsoft-copilot-studio/configuration-end-user-authentication
- **The built-in "Teams + Microsoft 365" channel requires `Authenticate with Microsoft`.** Manual authentication in Teams needs separate SSO and app manifest configuration. Source: https://learn.microsoft.com/microsoft-copilot-studio/configuration-end-user-authentication
- **Dataverse application users are the machine identity for Power Platform data access.** An application user is an unlicensed Dataverse user bound to one Entra app registration, or to an Azure Managed Identity application ID. It is created in Power Platform admin center > Environment > Settings > Users + permissions > Application users and given Dataverse security roles. The limit is one application user per Entra app per environment. Source: https://learn.microsoft.com/power-platform/admin/manage-application-users
- **Application users aren't blocked by environment security groups.** They can run in environments secured with a security group without being a member. Source: https://learn.microsoft.com/power-platform/admin/manage-application-users
- **Power Platform API service principals have tenant-admin-level power.** `pac admin create-service-principal --environment <id>` creates the Entra app and registers it with Power Platform. A service principal can't register itself; an admin with user context must do it through `PUT https://api.bap.microsoft.com/providers/Microsoft.BusinessAppPlatform/adminApplications/{clientId}`. The SPN is then treated like a user with the Power Platform Administrator role, and granular roles can't be applied. Source: https://learn.microsoft.com/power-platform/admin/powerplatform-api-create-service-principal
- **Shared Copilot Studio agents with user-scoped connections need a strategy.** Connections are tied to each agent user's identity. Microsoft recommends a service principal where supported, environment-level connections, or per-user OAuth sign-in. Source: https://learn.microsoft.com/microsoft-copilot-studio/admin-share-bots
- **Graph delegated vs application permissions.** Delegated permissions (scopes) are bounded by the signed-in user's own access. Application permissions (app roles) reach all data the permission covers and need admin consent. Only **Privileged Role Administrator** and **Global Administrator** can consent to application permissions. Source: https://learn.microsoft.com/graph/permissions-overview
- **Graph connector agents need application permissions with tenant-wide admin consent.** Delegated permissions aren't supported for connector agent registration. Source: https://learn.microsoft.com/graph/permissions-overview
- **Copilot data access follows the user's permissions.** Microsoft 365 Copilot surfaces only data the individual user can at least view, and Semantic Index honours the user-identity access boundary. Source: https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy

## 3. Roles and permissions
- **AI Administrator is the main Entra role for Copilot and agent governance.** Template ID `d2562ede-74db-457e-a7b6-544e236ebb61`, privileged. It manages all aspects of Microsoft Copilot, Integrated apps and Copilot agents, admin consent request policies and approving/publishing line-of-business agents. It also covers the full lifecycle of agent identities, blueprints and agent users. Source: https://learn.microsoft.com/entra/identity/role-based-access-control/permissions-reference
- **Agent ID Administrator manages agent identity objects tenant-wide.** Template ID `db506228-d27e-4b7d-95e5-295956d6615f`, privileged. It covers lifecycle operations for blueprints, blueprint principals, agent identities and agent users. Source: https://learn.microsoft.com/entra/identity/role-based-access-control/permissions-reference
- **Agent ID Developer creates blueprints and becomes their owner.** Template ID `adb2368d-a9be-41b5-8667-d96778e081b0`. Creating an agent identity blueprint and its principal adds the user as owner of both. Source: https://learn.microsoft.com/entra/identity/role-based-access-control/permissions-reference
- **Only Global Administrator and AI Administrator can act on agents in the Microsoft 365 admin center.** Approving requests, assigning owners, installing and modifying agents need one of these two. Global Reader and AI Reader are read-only; Security Administrator/Reader, Reports Reader and User Experience Success Manager can only view. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-roles-perms
- **Product admin roles only govern inside their own product.** Power Platform Administrator and Fabric Administrator are scoped to their products, while AI Administrator and Global Administrator have tenant-wide agent authority. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-roles-perms
- **Pinning agents for users requires the AI Administrator role.** Admins can pin up to three agents per user in Microsoft Copilot; pins can take up to six hours to appear. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-registry-overview
- **Power Platform Administrator.** Template ID `11648597-926c-4cf3-9c36-bcebb0ba8dcc`. Manages all environments, ignores environment security groups, and can view and manage tenant and environment data policies. It can't create users or assign licenses. Source: https://learn.microsoft.com/power-platform/admin/use-service-admin-role-manage-tenant ; https://learn.microsoft.com/entra/identity/role-based-access-control/permissions-reference
- **Dynamics 365 Administrator is bound by environment security groups.** Unlike Power Platform Administrator, it must be a member of an environment's security group to manage that environment. Source: https://learn.microsoft.com/power-platform/admin/use-service-admin-role-manage-tenant
- **Tenant admin roles must be assigned directly and don't grant Dataverse data access.** Global Administrator, Power Platform Administrator and Dynamics 365 Administrator can't be inherited through security groups, and no longer auto-receive System Administrator in environments. Admins self-elevate, or use Entra PIM, to get the Dataverse System Administrator role. Source: https://learn.microsoft.com/power-platform/admin/use-service-admin-role-manage-tenant ; https://learn.microsoft.com/power-platform/admin/database-security
- **Environments without Dataverse have only two predefined roles.** **Environment Admin** handles all admin actions, adding users, provisioning Dataverse and creating data policies. **Environment Maker** creates apps, connections, custom APIs and flows, with no data access. Source: https://learn.microsoft.com/power-platform/admin/database-security
- **Predefined Dataverse security roles can't be edited.** They include App Opener, Basic User, Delegate, Environment Maker, Service Reader, Service Writer, Support User, System Administrator and System Customizer. Makers who create or modify Dataverse tables need **System Customizer** in addition to **Environment Maker**. Source: https://learn.microsoft.com/power-platform/admin/database-security
- **Desktop flows and AI Builder need System Customizer or System Administrator.** Environment Maker can't author them. Source: https://learn.microsoft.com/power-platform/admin/database-security
- **Copilot Studio co-authors need the Environment Maker Dataverse role.** If they lack it, the sharer must be a **System Administrator** so Copilot Studio can assign it. Chatting requires the `ChatBotReaders` privilege, which Environment Maker includes. Source: https://learn.microsoft.com/microsoft-copilot-studio/admin-share-bots
- **Transcript access needs the Bot Transcript Viewer Dataverse role.** Only admins have it by default, and it grants transcripts for all agents a user creates or is shared in that environment. The per-agent sharing roles are **Analytics Viewer** and **Agent viewer**. Source: https://learn.microsoft.com/microsoft-copilot-studio/admin-share-bots
- **Copilot Studio chat sharing requires Entra sign-in.** Sharing with users or security groups works only when the agent uses `Authenticate manually` with Entra ID and **Require users to sign in** is on. Microsoft 365 groups with `SecurityEnabled=false` can't be targets. Source: https://learn.microsoft.com/microsoft-copilot-studio/admin-share-bots
- **Power Platform tenant isolation is set by a Power Platform Administrator.** Source: https://learn.microsoft.com/power-platform/admin/cross-tenant-restrictions
- **Copilot Credits roles: Global and Billing Administrator set billing methods.** They can add and change billing methods in the Microsoft 365 admin center Copilot > Cost Management. AI Administrator and License Administrator can edit spending policies, limits and alerts but can't create policies. AI Reader and Global Reader are view-only. Source: https://learn.microsoft.com/copilot/implement/usage-based-billing-copilot-credits-setup
- **Least-privilege runtime identity for an agent calling Graph.** Prefer delegated (OBO) permissions with the narrowest scope (for example `User.Read`, `Calendars.ReadWrite` only if writing). Use application permissions only for background agents, with a constraint such as `Selected` or `OwnedBy`. For Entra agent identities, broad permissions like `Sites.Read.All` and `Files.Read.All` are blocked. (secondary: synthesis) Source: https://learn.microsoft.com/graph/permissions-overview ; https://learn.microsoft.com/graph/api/resources/agentid-platform-overview?view=graph-rest-beta

## 4. Governance, security and compliance
- **Agent Registry is the tenant-wide agent inventory.** It is at Microsoft 365 admin center > Agents > All agents > Registry. Publisher types are Microsoft agents, External partner-built agents, Published by your org (LOB) and Shared by creator, and the same Copilot Studio agent can appear under several. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-registry-overview
- **Org-wide agents require admin approval in Microsoft 365 admin center > Agents > All agents > Requests.** Agents from Copilot Studio, Microsoft Foundry or Microsoft 365 Agents Toolkit are submitted as Pending review, Pending update or Pending activate. Admins choose **Publish to store** (pick users or groups, policy template, grant admin consent for requested permissions) or **Reject submission**. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-requests
- **Admins control which agents users can reach.** Admins can enable, block, remove and assign agents; users only see agents the admin allows and they've installed or been assigned. The Integrated apps view shows each agent's permissions, terms and privacy statement. Source: https://learn.microsoft.com/microsoft-agent-365/admin/manage-copilot-agents-integrated-apps ; https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy
- **Microsoft 365 and Teams admin center settings stay in sync.** With unified agent and app management, org-wide agent and app settings sync between the two. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-registry-overview
- **Agent Registry is programmable through Graph (preview).** Endpoints: `GET https://graph.microsoft.com/v1.0/copilot/admin/catalog/packages` and package details, with permission `CopilotPackages.Read.All` and the AI Administrator role. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-registry-overview
- **Agent risk signals require an E7 or Agent 365 license.** They aggregate Defender, Entra and Purview signals and can lag the security portals by up to an hour. Opening Purview IRM alerts needs the IRM Analyst or IRM Investigator role; Global Administrator alone isn't enough. Source: https://learn.microsoft.com/microsoft-agent-365/admin/agent-registry-overview
- **Agent 365 GA scope (2026-05-01).** Observability, governance and security for delegated and own-credential agents, plus Entra network controls for Copilot Studio agents and endpoint agents. Still in preview: registry sync with AWS Bedrock and Google Cloud, Windows 365 for Agents (US only) and Defender/Intune local agent discovery (planned June 2026). Source: https://www.microsoft.com/security/blog/2026/05/01/microsoft-agent-365-now-generally-available-expands-capabilities-and-integrations/
- **Power Platform data policies are the connector guardrail ("data loss prevention" policies, now titled "Data policies").** They govern Power Apps, Power Automate and Copilot Studio connectors at tenant or environment scope. Enforcement can take up to 24 hours, usually within an hour. Violating apps, flows and agents are suspended and their connections disabled. Source: https://learn.microsoft.com/power-platform/admin/wp-data-loss-prevention
- **Copilot Studio features are governed by virtual connectors in data policies.** They cover maker and user auth, knowledge sources, actions, HTTP, channels, Application Insights and triggers. Advanced connector policies (ACP) don't support virtual connectors. Copilot Studio virtual connectors are becoming dedicated governance rules, and Desktop Flow virtual connectors are becoming certified connectors. Source: https://learn.microsoft.com/power-platform/admin/wp-data-loss-prevention ; https://learn.microsoft.com/microsoft-copilot-studio/security-and-governance
- **MCP servers can be restricted through advanced connector policies.** MCP connectors expose MCP tools from connectors, and blocked MCP servers fail at runtime. Source: https://learn.microsoft.com/power-platform/admin/wp-data-loss-prevention
- **Managed Environments unlock the premium governance set.** It includes environment groups, sharing limits, usage insights, desktop-flow data policies, IP Firewall, IP cookie binding, customer-managed key, Lockbox, extended backup, pipelines, default environment routing, VNet support and masking rules. Source: https://learn.microsoft.com/power-platform/admin/managed-environment-overview
- **Managed Environments are licensed through standalone product licenses.** The entitlement comes with standalone Power Apps, Power Automate, Copilot Studio, Power Pages and Dynamics 365 licenses, but not with the Developer Plan. Source: https://learn.microsoft.com/power-platform/admin/managed-environment-overview
- **Unmanaged developer environments are deprecated.** Creation ends 2026-11-15, suspension 2026-12-15 and deletion 2027-01-15. Enable Managed Environments before 2026-12-15 to keep one. Source: https://learn.microsoft.com/power-platform/important-changes-coming ; https://learn.microsoft.com/power-platform/admin/managed-environment-overview
- **Dataverse for Teams environments are being retired.** Creation ends 2026-11-15, suspension 2027-09-15 and decommission 2027-10-30 unless upgraded. Source: https://learn.microsoft.com/power-platform/important-changes-coming
- **Power Platform tenant isolation blocks cross-tenant connections.** It blocks inbound and outbound cross-tenant connections for Entra-authenticated connectors in canvas apps and Power Automate flows. Configure it at Power Platform admin center > Security > Identity and access > Tenant isolation, with allowlist rules by tenant ID or domain (max 500, `*` wildcard). Changes take about an hour to apply. The Azure DevOps connector isn't enforced. Source: https://learn.microsoft.com/power-platform/admin/cross-tenant-restrictions
- **Power Platform VNet support uses Azure subnet delegation for private outbound calls.** It is GA for Dataverse plug-ins and for SQL Server, Azure Key Vault, Blob, Files, Queues, custom connectors, HTTP with Entra ID, Snowflake, Databricks and Azure AI Search. It requires a Managed Environment, a linked Azure subscription and VNets in both paired Azure regions. Trial and Dataverse for Teams environments aren't supported. Source: https://learn.microsoft.com/power-platform/admin/vnet-support-overview
- **Copilot Studio governance controls.** They include customer-managed keys, Customer Lockbox (which doesn't cover Purview audit telemetry or Agent 365 governance events), environment routing, maker welcome message, an automatic security scan before publishing and a tenant switch to disable publishing of generative-AI agents. Source: https://learn.microsoft.com/microsoft-copilot-studio/security-and-governance
- **Copilot Studio agents can be governed as Entra identities through Agent 365.** Conditional Access, RBAC/ABAC and access governance apply; Entra network egress and ingress controls for these agents are GA. Source: https://learn.microsoft.com/microsoft-copilot-studio/security-and-governance
- **Copilot Studio content moderation isn't admin-configurable by topic.** It covers predefined harmful-content categories, and there's no tenant-configurable policy to block arbitrary admin-defined topics. Source: https://learn.microsoft.com/microsoft-copilot-studio/security-and-governance
- **Customer data doesn't train foundation models.** Prompts, responses and data accessed through Microsoft Graph aren't used to train foundation LLMs. Copilot services opted out of Azure OpenAI abuse-monitoring human review. Use is covered by the Microsoft DPA and Product Terms with Microsoft as processor ("enterprise data protection"). Source: https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy ; https://learn.microsoft.com/copilot/plan/enterprise-data-protection
- **Web grounding queries leave the Microsoft 365 boundary.** Bing web queries strip user and tenant IDs and fall under the Microsoft Services Agreement, with Microsoft as an independent controller. They are outside the EU Data Boundary and outside HIPAA/BAA coverage. Source: https://learn.microsoft.com/copilot/plan/enterprise-data-protection
- **EU Data Boundary: Copilot is an EUDB service, with exceptions.** EU traffic stays in the EUDB, but Anthropic Claude models used as a subprocessor are excluded from the EUDB and in-country processing commitments. OpenAI models are also offered as a subprocessor, and admins decide whether to enable third-party models. Source: https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy ; https://learn.microsoft.com/copilot/plan/enterprise-data-protection
- **Copilot data residency is covered by ADR and Multi-Geo.** Microsoft 365 Copilot became a covered workload in the Product Terms data residency commitments, Advanced Data Residency and Multi-Geo on 2024-03-01. Non-EU customers' queries can be processed in the US, EU or other regions. Source: https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy
- **Copilot Studio EUDB scope depends on billing address and environment regions.** A tenant with an EU or EFTA billing address is in scope only if all its environments are in EUDB regions. Generative AI features can be configured to move data across regions, for example when capacity is constrained. Source: https://learn.microsoft.com/microsoft-copilot-studio/geo-data-residency
- **Copilot audit events are on by default in Purview Audit (Standard).** RecordType `CopilotInteraction` covers Microsoft Copilots, Cowork and Copilot Studio apps (AppIdentity `Copilot.Studio.<appId>`). Records include `AgentId` (for example `CopilotStudio.Declarative.<guid>`), `AccessedResources` with sensitivity labels, `XPIADetected`, `JailbreakDetected` and model provider/name. Source: https://learn.microsoft.com/purview/audit-copilot
- **Non-Microsoft AI audit uses Purview pay-as-you-go.** `AIAppInteraction`, and some `ConnectedAIAppInteraction` records, need pay-as-you-go enabled and are kept 180 days. Copilot Studio agents on non-Microsoft channels also need Purview pay-as-you-go. Source: https://learn.microsoft.com/purview/audit-copilot ; https://learn.microsoft.com/purview/ai-copilot-studio
- **DSPM for AI (classic) has been replaced by a new Purview DSPM.** The classic version is no longer enhanced. It provides one-click policies, weekly oversharing assessments of the top 100 SharePoint sites and activity explorer for Copilot and agent prompts. It needs a role such as Entra Compliance Administrator, plus Content Explorer Content Viewer to read prompt text. Source: https://learn.microsoft.com/purview/dspm-for-ai
- **Sensitivity labels and Purview DLP apply to Copilot and Copilot Studio agents.** Encrypted labels require the `EXTRACT` and `VIEW` usage rights. A DLP policy scoped to the Microsoft 365 Copilot location can stop Copilot and SharePoint-grounded Copilot Studio agents processing labelled content. Retention uses the "Microsoft Copilot Experiences" location. Source: https://learn.microsoft.com/purview/ai-copilot-studio ; https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy
- **Compliance attestations (names only).** GDPR, EU Data Boundary, ISO/IEC 27001, ISO/IEC 27018, HIPAA (properly configured, excluding web queries) and ISO/IEC 42001. Source: https://learn.microsoft.com/copilot/plan/microsoft-365-copilot-privacy

## 5. Commercial model
- **Copilot Chat has no extra cost; Microsoft 365 Copilot is $30/user/month paid yearly (shown 2026-11-14).** Copilot Chat comes with eligible Microsoft 365 subscriptions, but agents and connectors to work data are metered. The $30 add-on includes Work IQ grounding, Copilot in the Office apps and Teams, prebuilt agents (Researcher, Analyst, Facilitator) and SharePoint Advanced Management. Source: https://www.microsoft.com/microsoft-365-copilot/pricing/enterprise
- **Copilot Business pricing is unconfirmed.** Third-party sources cite $21/user/month list price and an $18 promo with conflicting end dates; this wasn't confirmed on a Microsoft page. (secondary) Source: https://techcommunity.microsoft.com/t5/microsoft-365-copilot-blog/act-now-lock-in-current-pricing-on-microsoft-365-copilot/ba-p/4502628
- **Microsoft 365 E7 "Frontier Suite" is $99/user/month, annual commitment (shown 2026-11-14), GA since 2026-05-01.** E7 (No Teams) is $90.45. E7 bundles Microsoft 365 E5, Microsoft Copilot, Microsoft Entra Suite and Microsoft Agent 365. Source: https://www.microsoft.com/microsoft-agent-365 ; https://techcommunity.microsoft.com/blog/microsoft_365blog/microsoft-365-e7-and-agent-365-are-now-generally-available/4516295
- **Microsoft Agent 365 is $15/user/month standalone, annual commitment (shown 2026-11-14), GA since 2026-05-01.** It is licensed per human user who interacts with, owns, manages or sponsors agents, not per agent, and isn't included in E3 or E5. Source: https://www.microsoft.com/microsoft-agent-365 ; https://learn.microsoft.com/microsoft-agent-365/overview
- **Copilot Credits are the common consumption unit.** They replaced "messages" on 2025-09-01 with no change to pack quantity or pay-as-you-go rate. Credits cover Copilot Studio agents, Copilot Chat agents for unlicensed users, Copilot Cowork and the Work IQ API. Source: https://learn.microsoft.com/microsoft-copilot-studio/billing-licensing ; https://learn.microsoft.com/microsoft-365-copilot/extensibility/cost-considerations
- **Copilot Credit prices (shown 2026-11-14).** A prepaid Copilot Credit pack is $200/month for 25,000 credits, billed annually, with no rollover. Source: https://learn.microsoft.com/microsoft-copilot-studio/requirements-messages-management

- **Prepaid capacity enforcement blocks agents at 125%.** Copilot Studio blocks an environment's agents, including mid-conversation, when the tenant reaches 125% of prepaid capacity, unless the environment has its own remaining allocation or a pay-as-you-go billing plan. Agent flows are blocked separately once no credits remain. Source: https://learn.microsoft.com/microsoft-copilot-studio/requirements-messages-management
- **Agents for Copilot Chat users without a Copilot license.** Instruction-only and public-web-grounded agents are free.
