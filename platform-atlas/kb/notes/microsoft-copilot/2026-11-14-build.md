# Microsoft 365 Copilot and Power Platform: capabilities, connectivity, CLIs, docs, limits (as of 2026-11-14)

## 6. AI and agent capabilities

### Microsoft 365 Copilot extensibility
- **The M365 Copilot extensibility docs now centre on "plugins" as the installable package.** A Microsoft 365 Copilot plugin is an installable package that can contain declarative agents, skills, Copilot connector configuration and references to remote MCP servers. The package holds connection information for an MCP server, but the server runs separately (overview page dated 2026-11-02). Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/plugins-overview
- **"Plugin" has two meanings in Microsoft's docs.** The customer-facing plugin package is one thing. "MCP and API plugins" are the technical custom actions inside a declarative agent, and they aren't enabled as standalone experiences in Microsoft 365 Copilot. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-plugins
- **Declarative agents can call remote MCP servers and OpenAPI-described REST APIs as actions.** For MCP plugins, Copilot discovers tools dynamically at runtime by default. A developer can instead pin a fixed tool set in the plugin manifest. REST API plugins always use the tools defined in the manifest (page dated 2026-11-06). Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-plugins
- **Dynamic tool discovery for an MCP server declared through `agentConnectors` has two requirements.** It needs Microsoft 365 app manifest version 1.29 or later, and a host that permits it. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-plugins
- **MCP plugins can return interactive UI widgets ("MCP apps"), built with the OpenAI Apps SDK.** The widgets render inline or full-screen in Microsoft 365 Copilot (announced March 2026). API plugins use Adaptive Card templates instead. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new ; https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-plugins
- **Declarative agent manifest schema 1.9 was released in October 2026.** It adds a top-level `agent_skills` property (skill directories that follow the Agent Skills standard) and a `Fabric` capability, and it makes `instructions` optional. Version 1.8 (July 2026) added the `EmailActions` and `MeetingActions` capabilities. Version 1.7 (May 2026) added `editorial_answers` and `default_response_mode`. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new
- **Skills in Microsoft 365 Copilot Chat have been GA since November 2026.** A skill is a set of reusable task instructions with optional resources and scripts, usable in Chat without a declarative agent. Skills can be distributed through plugin packages. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new
- **Custom engine agents bring their own orchestrator and model.** They can be built with Copilot Studio, the Microsoft 365 Agents SDK, the Teams SDK or Microsoft Foundry, and they require Microsoft 365 app manifest version 1.21 or later. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-custom-engine-agent
- **Pro-code custom engine agents reach M365 data through Microsoft Graph and the Copilot Retrieval API.** Copilot Studio agents have native access to Microsoft 365 and Copilot connector content. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-custom-engine-agent
- **Agent evaluation tooling for M365 agents has existed since May 2026.** It consists of the Microsoft 365 Copilot Evaluations CLI and an evaluation framework. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new

### Microsoft 365 Copilot APIs (Graph namespace)
- **The Copilot APIs are REST APIs under the Microsoft Graph `copilot` namespace.** They sit at `graph.microsoft.com/v1.0/copilot` and `graph.microsoft.com/beta/copilot`, use the same Entra authentication as other Graph APIs, and require a Microsoft 365 Copilot license for each calling user. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/copilot-apis-overview
- **The Copilot API list as of 2026-11-02 has nine entries.** It includes the Retrieval API (no preview label), the Search API (preview), the Chat API (preview) and the Interaction Export API. Also listed are AI Interactions Change Notifications (preview), the Meeting Insights API, Copilot usage reports, the Package Management API and the Cost Management API (preview). Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/copilot-apis-overview
- **The Retrieval API returns text chunks for RAG from the M365 Copilot hybrid index.** Sources are SharePoint, OneDrive and Copilot connectors, with KQL filtering through `filterExpression`. It was announced GA on 2025-11-20. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/retrieval/overview ; https://devblogs.microsoft.com/microsoft365dev/microsoft-365-copilot-apis-whats-new-and-whats-next/
- **The Retrieval API is also sold pay-as-you-go to users without a Copilot license, in preview since January 2026.** This option covers tenant-level sources only (SharePoint and Copilot connectors), not OneDrive. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/retrieval/overview
- **The Chat API (preview) runs multi-turn conversations with M365 Copilot.** Answers are grounded in enterprise search and web search. It has a synchronous `chat` endpoint and an SSE `chatOverStream` endpoint, returns text only and doesn't perform actions. It requires a Copilot add-on license. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/chat/overview

### Work IQ
- **Work IQ is Microsoft's workplace intelligence layer for agents.** It offers chat, context, tools and workspaces over A2A, remote MCP, local MCP and REST. Usage is billed per use in Copilot Credits and is independent of Microsoft 365 Copilot licensing; Copilot-licensed users are still billed per use when custom or third-party agents call it. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/ ; https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview
- **Work IQ context also includes Dynamics 365 and Power Platform business data, not just M365 productivity data.** Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/
- **Work IQ GA date: 2026-06-16.** Preview builds of the Work IQ CLI published before that date (for example 0.4.x and 0.5.x) are no longer supported. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/cli
- **Work IQ Workspaces gives agents persistent working storage for long-running workflows.** The storage is SharePoint Embedded inside the tenant boundary. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/

### Copilot Studio
- **Copilot Studio agents now run on one of three "harnesses".** The Microsoft Copilot harness is for reasoning-heavy, multistep work and has skills, memory, file creation and a sandbox. The Customer Conversation harness is for voice and chat customer service with human escalation. The standard harness covers classic topics, rule-based agents and agent flows. The harness determines features and billing (page dated 2026-10-19). Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/harnesses-overview
- **Harness timeline.** The Microsoft Copilot harness became a "production-ready preview" in June 2026. The Customer Conversation harness went into preview in October 2026. Since October 2026 (preview), Copilot Studio can upgrade an agent from the standard harness to the Microsoft Copilot harness, rebuilding topics as skills or workflows. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Model choices in Copilot Studio as of October 2026.** GPT-5.5 Chat is the default model on the standard harness. Claude Opus 4.8 is GA and GPT-5.3 Chat is in preview. Claude Sonnet 5 and GPT-5.5 Chat became GA as primary models in June 2026, and Mistral Medium 3.5 is an experimental option (May 2026). Some external models process data outside the tenant geography, and an admin must allow external models. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Agents keep their current model for up to 30 days after Copilot Studio moves the default (since October 2026).** Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Multi-agent support.** Connected agents went GA over A2A in April 2026. Since October 2026 they can also target Microsoft Foundry agents and Microsoft 365 Agents SDK agents, and adding an external A2A agent as a connected agent is in preview. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Autonomous triggers for Microsoft Copilot harness agents went into preview in October 2026.** Triggers include a new SharePoint item, an incoming email or a schedule, and the agent can be shared so others run it with their own credentials. Separately, the preview "agent account" gives an agent its own Entra ID, mailbox and Teams presence. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Copilot Studio creates a Microsoft Entra Agent ID for every new agent, with no environment-level opt-out, starting July 2026.** Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Computer use has been GA since May 2026.** Agents operate Windows web and desktop apps with a virtual mouse and keyboard. It requires generative orchestration and is billed per step: 5 Copilot Credits on standard models, 15 on premium models. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use ; https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Computer use model list.** GA models are OpenAI Computer-Using Agent (CUA), OpenAI GPT-6 Sol and Anthropic Claude Sonnet 4.5. Claude Sonnet 4.6 and Claude Opus 4.6 (premium) are experimental. Anthropic models need the admin setting that allows external models. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use
- **The Windows 365 for Agents MCP server has been GA since June 2026.** It gives agents control of a Windows 365 Cloud PC: desktop interaction, browser automation and UI inspection. Cloud PC pooling for computer use went into preview in January 2026. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Agent flows (standard harness) are workflows billed in Copilot Credits, not Power Platform requests.** Asynchronous responses (May 2026) let a long-running flow exceed the two-minute limit and return results later. There are also an agent node (March 2026), a prompt node and a Microsoft 365 Copilot node. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new ; https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Agent evaluations have been GA since March 2026, with multi-turn tests.** Running evaluations through the Power Platform API REST surface went into preview in April 2026. A content-safety test method was added in September 2026. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Agent observability options.** Environment-level agent telemetry export to Azure Application Insights went into preview in July 2026. Agents can also onboard to Microsoft Agent 365 for centralized observability and governance (August 2026). Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Memory and skills.** Both have been available for Microsoft Copilot harness agents since June 2026. Memory stores preferences per user, and skills can be exported as Markdown. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Knowledge sources.** Dataverse tables became a knowledge source in September 2026, with unstructured reasoning over text and file columns in preview. Azure SQL tables were added in August 2026 and OneDrive for Business in October 2026. Fabric IQ and Foundry IQ grounding are in preview. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new

### Power Platform
- **Power Apps code apps are code-first web apps (React, Vue and others) hosted on Power Platform.** They can call 1,500+ connectors from JavaScript. An admin must enable them per environment, and end users need Power Apps Premium, pay-as-you-go, an App Pass or auto-claim. Source: https://learn.microsoft.com/en-us/power-apps/developer/code-apps/overview
- **Code apps limitations.** They don't support Power Platform Git integration, Power Apps for Windows, SAS IP binding or SharePoint forms integration. Source: https://learn.microsoft.com/en-us/power-apps/developer/code-apps/overview
- **Desktop flow executions don't consume Power Platform requests.** Cloud flow triggers and actions do, at one request each. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations

## 7. Connectivity

### How an external agent (Claude, OpenAI and others) reaches M365 and Power Platform data
- **Work IQ remote MCP endpoint.** The URL is `https://workiq.svc.cloud.microsoft/mcp`. MCP clients discover its Entra auth through `/.well-known/oauth-protected-resource`, and it works with GitHub Copilot CLI and Foundry, which have Microsoft quickstarts. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview ; https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/quickstart/github-copilot-cli
- **Work IQ MCP has 10 generic tools that act on Graph-style resource paths.** The tools are `fetch`, `fetch_blob`, `create_entity`, `update_entity`, `delete_entity`, `do_action`, `call_function`, `ask`, `retrieve` and `list_agents`. Schema discovery uses `get_schema` and `search_paths`. The `retrieve` tool is in public preview. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview
- **Tool-count discrepancy.** The Work IQ MCP overview lists 12 tool names across its categories, while the Agent 365 and Work IQ overview pages say "10 generic tools". The overview page is the newer of the two (2026-11-10). Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview ; https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview
- **Work IQ MCP is GA as part of the Work IQ API.** Work IQ inside Copilot Studio is the part still in preview, and it needs the Microsoft Copilot harness. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview
- **Work IQ OAuth.** The application ID URI is `api://workiq.svc.cloud.microsoft`. There are three delegated scopes, all requiring admin consent: `WorkIQAgent.Ask`, `WorkIQ.Act` and `WorkIQ.Read`. Application-only (app-only) auth isn't supported, while on-behalf-of (OBO) is. An administrator must enable Work IQ in the tenant first. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/permissions ; https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview
- **Work IQ A2A endpoint.** It accepts JSON-RPC `POST https://workiq.svc.cloud.microsoft/a2a/` and supports A2A v1.0 (header `A2A-Version: 1.0`, method `SendMessage`) and v0.3 (the default). Multi-turn conversations use `contextId`. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview
- **Work IQ local MCP server.** It ships in the npm package `@microsoft/workiq` (latest 1.0.1) and runs with `npx -y @microsoft/workiq mcp` (stdio). There is also a GitHub Copilot CLI plugin, installed with `/plugin install workiq@work-iq`. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/cli ; https://registry.npmjs.org/@microsoft/workiq/latest
- **The legacy per-workload Microsoft-hosted MCP servers are kept for backward compatibility only.** These are Copilot, Calendar, Mail, SharePoint, OneDrive, Teams, User and Word (formerly the "Agent 365 tooling servers"). Microsoft says not to use them in production or new projects and to use Work IQ MCP instead. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview
- **Dataverse MCP server URL: `https://{org}.crm.dynamics.com/api/mcp` (GA).** A preview endpoint, `/api/mcp_preview`, must be enabled per environment. Microsoft documents connecting Claude Desktop, Claude Code, GitHub Copilot and Copilot Studio. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp ; https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp-other-clients
- **Dataverse MCP tools (renamed set).** The tools are `search_data`, `search` (now metadata search), `describe`, `read_query` (Dataverse SQL `SELECT`), `create_record`, `update_record`, `delete_record`, `create_table`, `update_table`, `delete_table`, `upsert_skill`, `delete_skill`, `init_file_upload`, `commit_file_upload`, `file_download` and `invoke_api`. The older `list_tables`, `describe_table` and `fetch` were removed. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp
- **Dataverse MCP from Claude through the local proxy.** Use the npm package `@microsoft/dataverse` (latest 1.0.88), for example `claude mcp add dataverse -t stdio -- npx -y @microsoft/dataverse mcp https://yourorg.crm.dynamics.com`. First a tenant admin grants consent to the Dataverse CLI app `0c412cc3-0dd6-449b-987f-05b053db9457`, and that client is enabled in the Power Platform admin center. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp-other-clients ; https://registry.npmjs.org/@microsoft/dataverse/latest
- **Dataverse MCP through the remote endpoint with your own Entra app.** Register an app, grant it the Dynamics CRM `mcp.tools` delegated permission, and add its client ID under Power Platform admin center > Environment > Settings > Product > Features > Dataverse Model Context Protocol > Advanced Settings. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp-other-clients
- **Only the Copilot Studio client is enabled for the Dataverse MCP server by default.** Every non-Microsoft client must be allow-listed per environment by a Power Platform administrator. The allow list covers only `/api/mcp`; MCP-named custom APIs are not restricted. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp-disable
- **Dataverse Web API.** It implements OData v4.0. Besides raw HTTP, Microsoft provides the Dataverse SDK for .NET (`ServiceClient`) and a Dataverse SDK for Python. Source: https://learn.microsoft.com/en-us/power-apps/developer/data-platform/webapi/overview ; https://learn.microsoft.com/en-us/power-apps/developer/data-platform/sdk-python/
- **Microsoft MCP Server for Enterprise (Graph-based) is in preview.** The URL is `https://mcp.svc.cloud.microsoft/enterprise`. It is read-only over Microsoft Entra directory data, with tools `microsoft_graph_suggest_queries`, `microsoft_graph_get` and `microsoft_graph_list_properties`. It costs nothing extra, is limited to 100 calls per minute per user, and runs in the global cloud only. Source: https://learn.microsoft.com/en-us/graph/mcp-server/overview
- **Microsoft Graph SDKs exist for C#, PowerShell, TypeScript/JavaScript, Java, Go, PHP and Python.** There is also a Graph CLI repo. Kiota can generate smaller clients. Microsoft support (CSS) doesn't officially support the SDKs, only the underlying HTTP calls. Source: https://learn.microsoft.com/en-us/graph/sdks/sdks-overview

### Copilot Studio as MCP/A2A client and server
- **Copilot Studio agents can call external MCP servers as tools.** The only transport supported is Streamable HTTP; SSE has not been supported since August 2025. Auth can be none, API key (header or query), or OAuth 2.0 (dynamic discovery with DCR, dynamic, or manual). Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent
- **An MCP server can also be added as a Power Apps custom connector.** Import an OpenAPI 2.0 file whose operation carries `x-ms-agentic-protocol: mcp-streamable-1.0`. MCP access goes through Power Platform connectors, so DLP data policies govern it. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent
- **Copilot Studio agents can be published as a remote MCP server or an A2A agent (preview, early-release environments only).** The channels are named "MCP client" and "A2A client". Clients authenticate with Entra delegated scopes `https://api.powerplatform.com/copilotstudio-mcp/MCS.InvokeAsMCP` or `https://api.powerplatform.com/copilotstudio-a2a/MCS.InvokeAsA2A` through an app registration against API app ID `6f46e6ed-07bf-4616-80f0-47546850f654`. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent
- **Copilot Studio MCP lets IDE and CLI clients author and manage agents.** It is the npm package `@microsoft/copilot-studio-mcp` (latest 1.0.4), launched with `npx -y @microsoft/copilot-studio-mcp@latest` over stdio. Tools are `discover_resources`, `get_consumption`, `manage_agents`, `manage_workflows` and `get_copilot_studio_skills` (announced October 2026). Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/copilot-studio-mcp ; https://registry.npmjs.org/@microsoft/copilot-studio-mcp/latest
- **Direct Line for standard-harness agents.** A custom app sends GET to the agent's Copilot Studio token endpoint (from Channels > Mobile app) to get a Direct Line token with `expires_in`, then uses the Bot Framework Direct Line 3.0 API. Microsoft warns never to put the Direct Line secret in client code. The Microsoft 365 Agents SDK is the alternative SDK path. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-connect-bot-to-custom-application
- **Since October 2026 Copilot Studio no longer allows new WhatsApp connections through the Azure Communication Services channel.** Existing connections keep working. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new

### SDKs and agent protocols
- **Microsoft 365 Agents SDK.** It is a multichannel conversational-agent framework that works with any AI service, in C# (.NET 8), JavaScript (Node 18+) and Python. Repos are `microsoft/Agents-for-net`, `Agents-for-js` and `Agents-for-python`. The npm `@microsoft/agents-hosting` package is at 1.10.1. Source: https://learn.microsoft.com/en-us/microsoft-365/agents-sdk/agents-sdk-overview ; https://github.com/microsoft/Agents ; https://registry.npmjs.org/@microsoft/agents-hosting/latest
- **Agents SDK Python packages.** They include `microsoft-agents-hosting-core`, `microsoft-agents-hosting-aiohttp`, `microsoft-agents-hosting-fastapi`, `microsoft-agents-hosting-msteams`, `microsoft-agents-authentication-msal` and `microsoft-agents-copilotstudio-client` (a client for Copilot Studio agents). The repo targets Python 3.10+, which conflicts with Learn's stated 3.9–3.11. Source: https://github.com/microsoft/Agents-for-python
- **The Microsoft Agent 365 SDK is separate from the Microsoft 365 Agents SDK and doesn't build or host agents.** It adds Entra agent identity, governed Work IQ MCP tooling and notifications to agents built on any framework, including the Claude Agent SDK, OpenAI Agents SDK and LangChain. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/developer/agent-365-sdk
- **Agent 365 SDK packages.** Packages include `@microsoft/agents-a365-tooling-extensions-claude`, `@microsoft/agents-a365-tooling`, `microsoft-agents-a365-tooling-extensions-openai` and `Microsoft.Agents.A365.Tooling`. The Agent 365 Observability SDK packages are deprecated in favour of the Microsoft OpenTelemetry Distro. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/developer/agent-365-sdk
- **Agent 365 notifications and agent user accounts (own mailbox) are limited to tenants in the Frontier preview program.** Source: https://learn.microsoft.com/en-us/microsoft-agent-365/developer/agent-365-sdk
- **Agent 365 BYO MCP servers.** Custom MCP servers can be registered through the "bring your own" (BYO) process and governed in the Microsoft 365 admin center Agents > Tools registry. The registry is the source of truth for which MCP servers a tenant can use. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview

### Connectors
- **Copilot connectors come as synced or federated.** Synced connectors index content into Microsoft Graph through the Graph connectors API, configured by tenant admins or self-serve by users. Federated connectors fetch live through MCP without indexing and are read-only, with write actions announced for early October 2026. There are 100+ prebuilt connectors. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/overview
- **Power Platform custom connectors accept OpenAPI 2.0 only (no OpenAPI 3.0) or a Postman collection.** The definition file must be under 1 MB. Auth can be OAuth 2.0, API key or Basic; the client-credentials grant isn't supported. Source: https://learn.microsoft.com/en-us/connectors/custom-connectors/faq
- **Since February 2024, OAuth custom connectors use a per-connector redirect URI.** Older connectors that used the global redirect URI must be updated. Source: https://learn.microsoft.com/en-us/connectors/custom-connectors/
- **The connector reference lists the certified MCP servers alongside the standard connectors.** Source: https://learn.microsoft.com/en-us/connectors/connector-reference/ ; https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview
- **Events and webhooks.** Graph change notifications and delta queries are Microsoft's recommended alternative to polling. The AI Interactions and AI Insights change-notification APIs (preview) stream Copilot interaction events. Source: https://learn.microsoft.com/en-us/graph/throttling ; https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/copilot-apis-overview
- **JDBC/ODBC drivers aren't the main access path for these products.** Dataverse is reached through the OData Web API, the SDKs and MCP `read_query` (Dataverse SQL `SELECT`). This note didn't research the Dataverse TDS endpoint. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp

## 8. CLIs and infrastructure as code

### Power Platform CLI (`pac`)
- **Three ways to install `pac` on Windows.** You can use the VS Code extension, the Windows MSI, or the .NET tool: `dotnet tool install --global Microsoft.PowerApps.CLI.Tool` (.NET 10 recommended). With only the .NET tool, `pac data`, `pac package deploy` and `pac package show` are unavailable even on Windows. Source: https://learn.microsoft.com/en-us/power-platform/developer/cli/introduction ; https://learn.microsoft.com/en-us/power-platform/developer/howto/install-cli-net-tool
- **Current `pac` version: 2.15.1 (NuGet `Microsoft.PowerApps.CLI.Tool`, published 2026-11-12).** The .NET tool installs to `%USERPROFILE%\.dotnet\tools`. Source: https://www.nuget.org/packages/Microsoft.PowerApps.CLI.Tool ; https://learn.microsoft.com/en-us/power-platform/developer/howto/install-cli-net-tool
- **`pac auth create` creates an authentication profile stored on the machine.** The basic form is interactive. `--environment` picks the target, `--deviceCode` works in headless shells, WSL2 and Codespaces, `--applicationId`/`--clientSecret`/`--tenant` sign in as a service principal, and `--managedIdentity` uses DefaultAzureCredential. `--githubFederated` and `--azureDevOpsFederated` enable OIDC. `--cloud` accepts `UsGov`, `UsGovHigh` and other sovereign clouds. Manage profiles with `pac auth list`, `pac auth select --index N`, `pac auth who` and `pac auth token`. Source: https://learn.microsoft.com/en-us/power-platform/developer/cli/reference/auth
- **`pac copilot` covers file-based Copilot Studio agent ALM.** `pac copilot init`, `clone`, `pull`, `push` and `pack` keep an agent as local files with three-way merge, and `pack` builds a solution zip for `pac solution import`. Other subcommands are `list`, `publish`, `status`, `extract-template`, `create`, `quarantine` and `mcp`. Source: https://learn.microsoft.com/en-us/power-platform/developer/cli/reference/copilot
- **`pac` has a built-in local MCP server.** Start it with `pac copilot mcp --run`, or without installing via `dnx Microsoft.PowerApps.CLI.Tool --yes copilot mcp --run`. Register it in Claude Code with `claude mcp add-json pac-cli '{"type":"stdio","command":"dnx","args":["Microsoft.PowerApps.CLI.Tool","--yes","copilot","mcp","--run"]}'`. ## 10. Limits and gotchas

### Request limits and entitlements
- **Power Platform request limits per paid licence per 24 hours.** Power Apps Premium, Power Automate Premium and Dynamics 365 Enterprise licences get 40,000 requests. Power Apps per app, pay-as-you-go, Microsoft 365-seeded licences and D365 Team Member get 6,000. A Power Automate per-flow or Process licence gets 250,000 per flow. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Non-licensed identities share a tenant-level pool per 24 hours.** Application users, non-interactive users and SYSTEM all draw from it. The pool is 25,000 base for Power Apps or Power Automate tenants, or 500,000 plus 5,000 per D365 USL (up to 10,000,000) for Dynamics 365 Enterprise or Professional tenants. Each application user doesn't get its own pool. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Copilot Studio-triggered cloud flows share 250,000 Power Platform requests per tenant per 24 hours.** The cap is the same however many Copilot Studio packs the tenant owns. Agent flows use Copilot Credits instead and aren't subject to it. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **The Power Automate "transition period" applies higher limits per cloud flow rather than per user.** Premium licences get 200,000 per flow and Process licences 500,000. A phased rollout starting April 2027 switches to per-user limits, which can throttle flows that work today. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Separately, Power Automate caps every flow at 100,000 requests per five minutes, whatever the licence.** Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Dataverse service protection limits apply per user per web server.** The defaults are 6,000 requests and 1,200 seconds of execution time per 5-minute sliding window, plus 52 concurrent requests. Exceeding them returns HTTP 429 with `Retry-After` (error codes `0x80072322`, `0x80072321`, `0x80072326`). Batches hold up to 1,000 operations but don't get around entitlement limits. Source: https://learn.microsoft.com/en-us/power-apps/developer/data-platform/api-limits
- **Dataverse search (`api/search`) is throttled at one request per second per user.** Source: https://learn.microsoft.com/en-us/power-apps/developer/data-platform/api-limits
- **Power Automate cloud flow limits.** A run lasts at most 30 days. Synchronous outbound and inbound requests time out at 120 seconds, so use async patterns. Messages max out at 100 MB, or 1 GB with chunking. A flow with no trigger activity for 90 days might be turned off unless its owner has a premium or capacity licence. Source: https://learn.microsoft.com/en-us/power-automate/limits-and-config
- **Custom connector throttling.** In Power Automate and Power Apps, each connection gets 10,000 requests per minute, and a user can create up to 50 custom connectors on a per-user plan (1 on free or seeded plans). Logic Apps allows 500 requests per minute per connection. Source: https://learn.microsoft.com/en-us/connectors/custom-connectors/faq
- **Microsoft Graph throttling.** The global limit is 130,000 requests per 10 seconds per app across all tenants, and service-specific limits apply below it. Throttled requests get 429 with `Retry-After`. Throttled requests inside a JSON batch fail individually and aren't retried automatically by the SDKs. Source: https://learn.microsoft.com/en-us/graph/throttling-limits ; https://learn.microsoft.com/en-us/graph/throttling
- **Copilot Retrieval API limits.** A user can make up to 200 requests per hour, `queryString` holds at most 1,500 characters, and `maximumNumberOfResults` maxes out at 25. Each request reads one data source. Results are unordered. Malformed KQL in `filterExpression` silently runs unscoped. Permissions needed are `Files.Read.All` and `Sites.Read.All`, or `ExternalItem.Read.All` for connectors. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/retrieval/overview
- **Declarative agents always inject up to five plugins into the prompt.** With more than five, they match plugins semantically on plugin descriptions. Response quality may degrade above about 10 functions or tools, and large tool output is truncated. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-plugins

### Copilot Studio credit consumption
- **Standard-harness Copilot Studio billing rates in Copilot Credits.** Classic answer: 1. Generative answer: 2. Agent action, including triggers, topic transitions and each computer-use step: 5. Tenant graph grounding: 10. Agent flow actions: 13 per 100 actions. Basic AI tools: 1 per 10 responses. Standard AI tools: 15 per 10 responses. Premium (reasoning) tools: 10 per 1,000 tokens. Content processing: 8 per page. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management
- **Reasoning-model agents are billed per token.** They pay the feature rate plus 10 credits per 1,000 billed tokens. Every model call in a turn counts, and only tokens read from the prompt cache are free. Microsoft's own example: one follow-up question costs 141 credits, or about 461 credits in a new conversation. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management
- **No charge for Copilot-licensed employees, with exceptions.** Employee-facing agent usage by Microsoft 365 Copilot-licensed users isn't charged. Computer use is excluded, as are agent flows not started by the "When an agent calls the flow" trigger and flows called by autonomous agents. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management
- **Agents are blocked at 125% of prepaid capacity unless pay-as-you-go is linked.** Blocking happens mid-conversation, with the message "This agent is currently unavailable. It has reached its usage limit." Agent flow runs are blocked separately as soon as the environment has no credits. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management
- **Microsoft Copilot and Customer Conversation harness agents use a different usage-based billing model.** Their rates live on a separate page. Copilot Studio MCP and A2A channel use also consumes Copilot Credits. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/harnesses-overview ; https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent
- **Dataverse MCP billing.** `search_data` is billed per use in Copilot Credits. All other Dataverse MCP tools are billed at the basic text and generative AI rate per 10 responses. Source: https://learn.microsoft.com/en-us/power-apps/maker/data-platform/data-platform-mcp

### Common setup failures
- **Work IQ multitenant token issuer.** In parent/child tenants the token issuer must be the user's home tenant, otherwise calls fail with `400 AuthenticationError: "Error authenticating with resource"`. Register the app as `AzureADMultipleOrgs`. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview
- **Work IQ policy configuration can fail if the Work IQ service principal doesn't exist yet.** This happens when admins set it up before any MCP use in the tenant. A tenant admin provisions the principal through the "Enable your tenant for Work IQ" steps. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview
- **Copilot Studio MCP/A2A channel API not visible in Entra.** Search for the API app ID `6f46e6ed-07bf-4616-80f0-47546850f654`. If it's still missing, open the channel once in Copilot Studio, which provisions the enterprise app. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent
- **A first `pac copilot init --environment` against a brand-new environment can fail.** The error is "Async operations are currently disabled for this organization"; wait a minute or two and retry. Source: https://learn.microsoft.com/en-us/power-platform/developer/cli/reference/copilot
- **Agent 365 CLI device-code sign-in can be blocked by Conditional Access or Security Defaults (`AADSTS530035`).** Run it on native Windows to use WAM instead. Older CLI versions fail with `AADSTS70007`; update the CLI. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/developer/agent-365-cli
- **Region and cloud gaps.** The Microsoft MCP Server for Enterprise runs in the global cloud only. The Microsoft Copilot harness turns off at runtime for FedRAMP High. MCP and A2A channels are limited to early-release environments. Source: https://learn.microsoft.com/en-us/graph/mcp-server/overview ; https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/copilot-studio-mcp ; https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent

- **Teams Toolkit became Microsoft 365 Agents Toolkit.** The CLI changed from `teamsapp` to `atk`, though the npm package still ships a `teamsapp` alias. TeamsFx SDK is deprecated, with community-only support until September 2026; Microsoft now points to the Teams SDK (formerly Teams AI Library). Source: https://learn.microsoft.com/en-us/microsoftteams/platform/toolkit/overview-agents-toolkit ; https://learn.microsoft.com/en-us/microsoftteams/platform/toolkit/teams-toolkit-cli ; https://registry.npmjs.org/@microsoft/m365agentstoolkit-cli/latest
- **Microsoft Graph connectors became Microsoft 365 Copilot connectors.** The ingestion API is still called the Microsoft Graph connectors API. Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/overview
- **The workload-specific Agent 365 MCP servers are superseded by Work IQ MCP for new work.** Source: https://learn.microsoft.com/en-us/microsoft-agent-365/tooling-servers-overview
- **Agent flows can be converted from Power Automate cloud flows, and the conversion can't be undone.** The environment needs prepaid Copilot Credits or pay-as-you-go. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **Power Platform API calls for Copilot Studio moved to the new `copilotstudio` namespace in November 2025.** The old namespace works only temporarily. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new
- **Foundry's agent framework was renamed.** The Semantic Kernel-based framework is now the Microsoft Agent Framework SDK, and the platform is "Microsoft Foundry" (formerly Azure AI Foundry). Source: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/overview-custom-engine-agent
- **The Power Automate per-flow plan is legacy, replaced by the Process licence.** Process licences can be stacked up to 10 per flow, or assigned to a flow group of up to 25 flows. Source: https://learn.microsoft.com/en-us/power-platform/admin/api-request-limits-allocations
- **The Agent 365 Observability SDK is deprecated.** Use the Microsoft OpenTelemetry Distro instead. Source: https://learn.microsoft.com/en-us/microsoft-agent-365/developer/agent-365-sdk
