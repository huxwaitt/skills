# Google Cloud: capabilities, connectivity, CLIs, docs, limits (as of 2026-11-14)

## 6. AI and agent capabilities
- **Vertex AI was renamed Gemini Enterprise Agent Platform on 2026-04-22.** The release notes list these renames: Vertex AI to Agent Platform, Vertex AI Studio to Agent Studio, Vertex AI Search to Agent Search, Vertex AI Vector Search to Vector Search, Vertex AI Vector Search 2.0 to Agent Retrieval, Vertex AI RAG Engine to RAG Engine, Vertex AI Agent Engine to Agent Runtime, Agent Builder Sessions to Agent Platform Sessions, Memory Bank to Agent Platform Memory Bank, and Vertex AI Model Garden to Model Garden. Old bookmarked links redirect. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **The Agent Platform docs are organized into four pillars: Build, Scale, Govern and Optimize.** Build covers ADK, Agent Garden, Agent Studio, Skill Registry, RAG Engine, Vector Search and the Managed Agents API. Scale covers Agent Runtime, Sessions and Memory Bank. Govern covers Agent Gateway, semantic governance, content security, Identity and IAM. Optimize covers evaluation, observability, traces, topology, simulated evaluations, online monitoring and prompt optimization. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview ; https://docs.cloud.google.com/vertex-ai/docs
- **The underlying API host and resource names were kept through the rename.** The service is still `aiplatform.googleapis.com`, and Agent Runtime instances are still the `ReasoningEngine` API resource "for backward compatibility". Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime
- **Model Garden lists Gemini, Veo and Lyria, partner models (Claude, Grok, Mistral) and open models (Llama, DeepSeek, Mistral, Qwen, Gemma).** Source: https://docs.cloud.google.com/vertex-ai/docs
- **Open models can be served two ways: Model as a Service (MaaS) or self-deployment.** MaaS is a serverless managed API, and its model IDs end in `-maas`, for example `gemma-4-26b-a4b-it-maas`. Self-deployment uses one-click deploy or custom weights, runs in your own project and VPC, and uses vLLM, Hex-LLM or TGI containers. On Model Garden cards, the MaaS card name includes "API Service". Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/open-models/choose-serving-option ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/open-models/use-maas
- **Claude models available on Agent Platform as of 2026-11:** Claude Opus 5 (from 2026-07-24), Sonnet 5 (2026-06-30), Fable 5.1 (2026-09-01), Opus 5.5 (2026-09-22), Sonnet 5.5 (2026-09-28) and Haiku 5.5 (2026-10-07). Claude Fable 5.2 reached GA in Model Garden on 2026-11-09, with fast mode. A Cyber Verification Program for Claude entered Preview on 2026-09-14. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Several open-model MaaS endpoints were deprecated on 2026-07-21 and retired on 2026-10-21.** They include DeepSeek, GLM, Qwen and Llama variants. Grok 4.1 was deprecated on 2026-07-08 and shut down on 2026-08-20. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Recent Gemini retirements:** Gemini 2.0 Flash and 2.0 Flash-Lite were discontinued on 2026-06-01. The preview endpoints for 2.5 Flash-Lite, 2.5 Flash and 3.1 Flash-Lite were retired on 2026-07-09. Gemini 2.5 Flash Image retirement moved to 2027-03-15. Gemini 3.5 Flash went GA on 2026-05-19. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Agent Runtime (formerly Vertex AI Agent Engine) is a managed runtime for deploying, operating and scaling agents.** It supports any language or framework that can be containerized and follows the runtime contract. ADK has full integration (Python via the `adk` CLI, Go via the `adkgo` CLI). LangChain, LangGraph, AG2 and LlamaIndex get managed SDK templates. CrewAI and custom frameworks use a custom template. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime
- **Agent Runtime added long-running operations, faster starts and custom containers on 2026-04-22.** Long-running operations run up to 7 days. The notes cite sub-second cold starts, provisioning in under 1 minute, bring-your-own-container (BYOC) and custom session IDs. Agent revisions and traffic splitting entered preview on 2026-05-19. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Agent Runtime accepts three deployment inputs:** a prebuilt image in Artifact Registry, a Dockerfile plus source (Agent Runtime builds the image), or the legacy Python package spec (a pickled agent `agent.pkl` plus `requirements.txt` in Cloud Storage). Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/runtime/use-terraform ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime
- **Agent Platform Sessions and Memory Bank provide managed short-term and long-term agent memory.** Memory Bank `IngestEvents` went GA on 2026-07-08, memory profiles went GA on 2026-07-15, and Memory Bank got a console page on 2026-11-06. Gemini 3.5 Flash became the default Memory Bank generation model on 2026-06-29. Memory Bank and Sessions accept the `global`, `us` and `eu` locations. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/agent-locations
- **Agent Runtime includes a code-execution sandbox, reached through the SDK module `client.sandboxes`.** It has its own quotas, listed in section 10. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/agent-quotas
- **Agent Development Kit (ADK) is Google's open-source, code-first agent framework.** It is available in Python, Go, Java, TypeScript and Kotlin, and supports deployment to Agent Runtime, Cloud Run and GKE. The latest Python release is `google-adk` 2.14.1, published 2026-11-12. Source: https://adk.dev/llms.txt ; https://pypi.org/project/google-adk/
- **RAG Engine (formerly Vertex AI RAG Engine) is the managed RAG pipeline in Agent Platform.** It covers ingest, chunking, embedding, indexing into a corpus, retrieval and grounded generation. Data sources are local files, Cloud Storage and Google Drive. It supports VPC Service Controls and CMEK, but not data residency or AXT controls. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview
- **RAG Engine regions are restricted.** `us-central1`, `us-east4`, `us-east1` and `europe-west1` need an allowlist for new projects, and existing projects are unaffected. `europe-west3` and `europe-west4` are GA, and most other regions are Preview. The backing store is a RAG Engine-managed Spanner instance, billed in GA locations. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview
- **Agent Search (formerly Vertex AI Search) is the managed enterprise search and grounding product.** It runs on the Discovery Engine API (`discoveryengine.googleapis.com`). Data stores are structured or unstructured. Connectors either federate (query the source live) or ingest (copy into the index). Source: https://cloud.google.com/products/gemini-enterprise-agent-platform/agent-search ; https://docs.cloud.google.com/gemini/enterprise/docs/introduction-to-connectors-and-data-stores
- **The Gen AI evaluation service scores models and agents with adaptive rubrics.** Adaptive rubrics are per-prompt pass/fail tests. `GENERAL_QUALITY` is the recommended default metric. Agent metrics are `final_response_quality`, `final_response_reference_free`, `hallucination` and `tool_use_quality`. The SDK flow is `generate_rubrics()`, then `run_inference()`, then `evaluate()`, and the SDK interface is marked Preview in places. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/determine-eval
- **Observability is tied to OpenTelemetry and Cloud Monitoring.** OpenTelemetry tracing has been on by default for newly deployed ADK agents on Agent Runtime since 2026-06-18. Agents built with ADK 2.6.0 or later can emit `gen_ai` telemetry metrics to Cloud Monitoring (2026-08-13). Agent Observability, which includes MCP server health, went GA on 2026-06-18. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Agent Registry is a catalog of agents, MCP servers and tools, endpoints and skills.** It entered public preview on 2026-04-22 and went GA on 2026-06-18. It supports A2A protocol 1.0 (`supportedInterfaces`) alongside the 0.3 schema. Registration needs the Agent Registry API enabled in a governance project. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes ; https://docs.cloud.google.com/agent-registry/overview
- **Agent Gateway is the policy enforcement point for agent ingress (Client-to-Agent) and egress (Agent-to-Anywhere) traffic.** It covers LLM, MCP and A2A traffic and enforces IAM Unified Access Policies (deny by default), Model Armor and semantic governance policies. It is available for Agent Runtime and Gemini Enterprise, and cross-cloud Kubernetes support entered Limited Preview on 2026-11-11. GKE and Cloud Run support are in early preview. Each gateway can govern up to 5,000 registered resources. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Skill Registry and the Managed Agents API entered preview on 2026-05-19.** The Agent Identity API (`agentidentity.googleapis.com`) entered preview on 2026-06-18 and replaces the legacy IAM Connectors API during a migration period. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **BigQuery has managed AI functions and general-purpose AI functions, which call Agent Platform models and incur their charges.** The managed functions are `AI.IF`, `AI.CLASSIFY` and `AI.SCORE`, and BigQuery picks the model for them. The general-purpose functions are `AI.GENERATE` and `AI.GENERATE_TABLE`, which take a custom output schema. Source: https://docs.cloud.google.com/bigquery/docs/generative-ai-overview
- **BigQuery data agents run on the Conversational Analytics API (`geminidataanalytics.googleapis.com`).** The API went GA for BigQuery and Looker on 2026-06-23 and offers `v1` REST endpoints. BigQuery Graph data sources went GA on 2026-09-30. Deep Dive thinking mode entered Preview on 2026-09-03. AlloyDB, Cloud SQL and Spanner data sources entered Preview on 2026-03-30. Source: https://docs.cloud.google.com/gemini/data-agents/conversational-analytics-api/release-notes
- **Integration points that a separate note covers:** the Gemini API / AI Studio, Gemini Enterprise (agents publish to it, for example via `agents-cli publish gemini-enterprise`), Google Workspace and Gemini CLI. Source: https://google.github.io/agents-cli/guide/getting-started/index.md
- **Computer use and browser use:** this research found no dedicated Agent Platform computer-use or browser-use runtime, so the topic is not covered here. Source: https://docs.cloud.google.com/vertex-ai/docs

## 7. Connectivity
- **The Agent Platform REST API has three kinds of endpoint.** The global host is `https://aiplatform.googleapis.com`. Regional hosts follow `https://LOCATION-aiplatform.googleapis.com`. The multi-region jurisdictions are `us` and `eu`, and `eu` excludes the UK and Switzerland. Calls authenticate with an OAuth 2.0 bearer token (`gcloud auth print-access-token`) or, in express mode, an API key. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/use-claude
- **Claude is called through the `rawPredict` and `streamRawPredict` methods.** The URL is `POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/publishers/anthropic/models/MODEL:rawPredict`, with `"anthropic_version": "vertex-2023-10-16"` in the request body. Model IDs look like `claude-sonnet-4-6`. You must click Enable on each model's Model Garden card first. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/use-claude
- **The Anthropic SDK for Agent Platform is `anthropic[vertex]`, used through the `AnthropicVertex(project_id=..., region=...)` client.** Install it with `pip install -U 'anthropic[vertex]'`. Client tools (function calling) are supported, and the page says "Server tools are not supported". The `anthropic` package was at 2.8.0 on PyPI as of 2026-11-10. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/use-claude ; https://pypi.org/project/anthropic/
- **The Google Gen AI SDK is the model SDK for Gemini on Agent Platform.** Packages are Python `google-genai` (3.3.0 on 2026-11-12), JS/TS `@google/genai`, Go `google.golang.org/genai`, Java `com.google.genai:google-genai` and .NET `Google.GenAI`. Configure it with `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION=global` and `GOOGLE_GENAI_USE_ENTERPRISE=True`. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/sdks/overview ; https://pypi.org/project/google-genai/
- **`GOOGLE_GENAI_USE_ENTERPRISE` is the new name for `GOOGLE_GENAI_USE_VERTEXAI`, and the two are equivalent.** Older ADK versions recognize only the old name, so set `GOOGLE_GENAI_USE_VERTEXAI` or upgrade ADK if the new variable doesn't connect. Source: https://adk.dev/get-started/google-cloud/
- **The Agent Platform SDK for Python split in version 2.0.1 (2026-09-18), a breaking change.** Agent surfaces moved into a separate package, `google-cloud-agentplatform`, imported as `agentplatform`. Code uses `agentplatform.Client(project=..., location=...)` with `.runtimes`, `.sessions`, `.sandboxes` and `.memory_banks`. Generative modules moved to `google-genai`, and `vertexai.agent_engines` maps to `agentplatform.Client().runtimes`. Both `google-cloud-agentplatform` and `google-cloud-aiplatform` were at 2.9.0 on 2026-11-12. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime ; https://pypi.org/project/google-cloud-agentplatform/
- **A deployed Agent Runtime agent is queried over REST.** The URL is `https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/reasoningEngines/RESOURCE_ID:query`, with `:streamQuery` for streaming. Source: https://adk.dev/deploy/agent-runtime/deploy/
- **Google-managed remote MCP servers are HTTPS endpoints, mostly at `https://SERVICE.googleapis.com/mcp`.** They follow the MCP authorization spec and support MCP version 2026-07-28. Google Cloud MCP servers are governed by IAM allow and deny policies and need the MCP Tool User role (`roles/mcp.toolUser`, permission `mcp.tools.call`). Google (non-Cloud) and Workspace MCP servers don't use that role. Source: https://docs.cloud.google.com/mcp/overview ; https://docs.cloud.google.com/mcp/configure-mcp-ai-application
- **Remote MCP endpoints for core data and compute services include:** BigQuery `https://bigquery.googleapis.com/mcp`, Cloud Run `https://run.googleapis.com/mcp`, Cloud Storage `https://storage.googleapis.com/storage/mcp`, Cloud SQL `https://sqladmin.googleapis.com/mcp`, Spanner `https://spanner.googleapis.com/mcp`, AlloyDB `https://alloydb.googleapis.com/mcp`, Firestore `https://firestore.googleapis.com/mcp`, GKE `https://container.googleapis.com/mcp`, Compute Engine `https://compute.googleapis.com/mcp` and Pub/Sub `https://pubsub.googleapis.com/mcp`. Source: https://docs.cloud.google.com/mcp/supported-products
- **Remote MCP endpoints for operations and governance services include:** Cloud Logging `https://logging.googleapis.com/mcp`, Cloud Monitoring `https://monitoring.googleapis.com/mcp`, Cloud Trace `https://cloudtrace.googleapis.com/mcp`, IAM `https://iam.googleapis.com/mcp`, Resource Manager `https://cloudresourcemanager.googleapis.com/mcp` and Knowledge Catalog (formerly Dataplex) `https://dataplex.googleapis.com/mcp`. The supported-products page lists about 70 Google Cloud servers in total. Source: https://docs.cloud.google.com/mcp/supported-products
- **Agent Platform's own remote MCP server uses toolset paths.** Endpoints are `https://aiplatform.googleapis.com/mcp/TOOLSET` (global) and `https://LOCATION-aiplatform.googleapis.com/mcp/TOOLSET` (regional). The toolsets are generate, predict, notebook, endpoints, models, tuning, retrieval, evaluation and prompts. It went GA on 2026-04-22. Agent Search is at `https://discoveryengine.googleapis.com/mcp`, and Agent Retrieval (Preview) at `https://vectorsearch.googleapis.com/mcp`. Source: https://docs.cloud.google.com/mcp/supported-products ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Some remote MCP servers are labeled Preview, including the one that wraps the gcloud CLI.** Examples are Google Cloud CLI `https://cloudcli.googleapis.com/mcp`, Cloud Billing, Cloud Asset Inventory, BigQuery Data Transfer Service, Datastream, Database Migration Service, Developer Connect and Security Command Center. Most other entries carry no stage label on the page. Source: https://docs.cloud.google.com/mcp/supported-products
- **The BigQuery remote MCP server offers six tools over Streamable HTTP.** The tools are `list_dataset_ids`, `list_table_ids`, `get_dataset_info`, `get_table_info`, `execute_sql` and `execute_sql_readonly`. The OAuth scope is `https://www.googleapis.com/auth/bigquery`. It needs `roles/mcp.toolUser`, `roles/bigquery.jobUser` and `roles/bigquery.dataViewer`. Only `execute_sql` can write, and an IAM deny policy can block it. Source: https://docs.cloud.google.com/bigquery/docs/use-bigquery-mcp
- **A remote MCP server is used by enabling the product's API.** Run `gcloud services enable SERVICE_NAME`, which needs `roles/serviceusage.serviceUsageAdmin`. The BigQuery MCP server is enabled automatically with the BigQuery API. Clients authenticate with ADC, an OAuth client ID and secret, or an `Authorization: Bearer` header, plus the `x-goog-user-project: PROJECT_ID` header. Source: https://docs.cloud.google.com/mcp/enable-disable-mcp-servers ; https://docs.cloud.google.com/mcp/configure-mcp-ai-application ; https://docs.cloud.google.com/bigquery/docs/use-bigquery-mcp
- **Connecting Claude.ai, Claude Code or Claude Desktop to a Google Cloud MCP server takes an OAuth client.** Create a Web application OAuth client under Google Auth Platform > Clients, with redirect URI `https://claude.ai/api/mcp/auth_callback`. Then add a custom connector with the MCP URL and put the client ID and secret in Advanced settings. Source: https://docs.cloud.google.com/mcp/configure-mcp-ai-application
- **Workspace and other Google MCP servers exist as integration points.** Workspace servers are Developer Preview, for example Gmail `https://gmailmcp.googleapis.com/mcp/v1` and Drive `https://drivemcp.googleapis.com/mcp/v1`. Other Google servers include Maps Grounding Lite and the Developer Knowledge API. Source: https://docs.cloud.google.com/mcp/supported-products
- **MCP Toolbox for Databases (`googleapis/mcp-toolbox`, formerly `genai-toolbox`, Gen AI Toolbox for Databases) is Google's open-source MCP server for databases.** Latest release is v1.17.0 (2026-11-13). Sources include AlloyDB, BigQuery, Cloud SQL, Spanner, Firestore and Knowledge Catalog, plus PostgreSQL, MySQL, SQL Server, Oracle, MongoDB, Redis, Snowflake, Neo4j, ClickHouse, Trino and others. Docs are at https://mcp-toolbox.dev/. Source: https://github.com/googleapis/mcp-toolbox
- **MCP Toolbox runs from a binary, npx or Go, with stdio or HTTP transport.** The Windows binary is `https://storage.googleapis.com/mcp-toolbox-for-databases/v1.17.0/windows/amd64/toolbox.exe`. The npx form is `npx -y @toolbox-sdk/server --prebuilt=bigquery --stdio`. Custom tools go in `--config tools.yaml`. HTTP runs on default port 5000 at `/mcp` or `/mcp/{toolset}`. Source: https://github.com/googleapis/mcp-toolbox
- **MCP Toolbox has client SDKs in four languages.** Python: `toolbox-core` (1.4.0 on 2026-09-01), `toolbox-langchain` and `toolbox-llamaindex`. JS: `@toolbox-sdk/core` and `@toolbox-sdk/adk`. Go: `github.com/googleapis/mcp-toolbox-sdk-go`. Java: `com.google.cloud.mcp:mcp-toolbox-sdk-java`. Source: https://github.com/googleapis/mcp-toolbox ; https://pypi.org/project/toolbox-core/
- **ADK agents call external MCP servers through `McpToolset`.** Connection classes are `StdioConnectionParams`, `StreamableHTTPConnectionParams` and `SseConnectionParams`. MCP is supported in Python, TypeScript (`MCPToolset`), Go, Java and Kotlin. Production agents must define `McpToolset` synchronously in `agent.py`. Source: https://adk.dev/tools-custom/mcp-tools/
- **Cloud Run hosts custom MCP servers over Streamable HTTP but not stdio.** Clients authenticate with Cloud Run Invoker via `gcloud run services proxy NAME --region REGION --port=3000`, an OIDC ID token, or IAP. Deploying with `--functional-type=mcp-server` registers the server in Agent Registry automatically. Source: https://docs.cloud.google.com/run/docs/host-mcp-servers ; https://docs.cloud.google.com/agent-registry/register-mcp-servers
- **A2A is supported on Agent Runtime, Cloud Run and Agent Registry.** Agent Runtime lists A2A deployment as supported, with A2A multi-agent systems marked preview. A2A agents serve `/.well-known/agent-card.json`, which Agent Registry reads to extract skills. ADK consumes remote agents through `RemoteA2aAgent`. `adkgo deploy cloudrun` enables `--a2a` by default. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime ; https://docs.cloud.google.com/agent-registry/register-mcp-servers ; https://codelabs.developers.google.com/adk-a2a-agent-runtime ; https://adk.dev/deploy/cloud-run/
- **The A2A methods on Agent Runtime have their own quotas:** POST methods (`sendMessage`, `cancelTask`) at 60 per minute and GET methods (`getTask`, `getCard`) at 600 per minute. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/agent-quotas
- **Apigee hosts MCP servers for existing APIs through the MCP Discovery Proxy.** Each OpenAPI 3.0.0–3.0.3 operation becomes an MCP tool behind `ORG_NAME.mcp.apigee.internal`, using JSON-RPC `tools/list` and `tools/call` and authenticating with OAuth 2.1 or OIDC. It is available on Subscription, Pay-as-you-go, Evaluation and Data Residency organizations, and on Apigee hybrid 1.17.0 or later. Source: https://docs.cloud.google.com/apigee/docs/api-platform/apigee-mcp/apigee-mcp-overview
- **The Apigee API hub MCP server went GA on 2026-07-24.** Its endpoints are `https://apihub.googleapis.com/mcp` (global) and `https://apihub.REGION.rep.googleapis.com/mcp`, and it integrates with Model Armor. The `ConfigureAndDeployServer` RPC (2026-07-24) and `gcloud apihub locations configure-and-deploy-server` (2026-08-12) bundle API operations into MCP servers deployed on Apigee. API hub syncs MCP metadata to Agent Registry by default. Source: https://docs.cloud.google.com/apigee/docs/apihub/release-notes ; https://docs.cloud.google.com/apigee/docs/apihub/register-mcp-apis
- **ADK reaches Application Integration and Integration Connectors through `ApplicationIntegrationToolset`.** The Python class is `google.adk.tools.application_integration_tool.application_integration_toolset.ApplicationIntegrationToolset`, and there is a Java equivalent. It works in two modes: `connection=` with `entity_operations` and `actions` for Integration Connectors, or `integration=` with `triggers` for workflows. It needs `roles/integrations.integrationEditor`, `roles/connectors.invoker` and `roles/secretmanager.secretAccessor`. Source: https://adk.dev/integrations/application-integration/
- **Integration Connectors has 147 connectors: 35 for Google services and 112 for other applications.** GA connectors include Salesforce, ServiceNow, Snowflake, SharePoint, Workday, Microsoft Dynamics 365 and the SAP family (ERP, HANA, SuccessFactors, Ariba). Databricks was not listed. Source: https://docs.cloud.google.com/integration-connectors/docs/connector-reference-overview
- **Integration Connectors added an MCP connector (client side) in preview on 2025-12-16.** It has versions v1 and v2 for MCP API versions, is used from Application Integration via the Connectors task, and allocates 2 nodes per connection by default. Source: https://docs.cloud.google.com/integration-connectors/docs/release-notes ; https://docs.cloud.google.com/integration-connectors/docs/connectors/mcp/overview-mcp
- **The Conversational Analytics API has native SDKs in seven languages:** Python, Java, Go, Node.js, PHP, Ruby and .NET. Its global endpoint is `geminidataanalytics.googleapis.com`. Source: https://cloud.google.com/blog/products/data-analytics/build-data-agents-with-conversational-analytics-api ; https://docs.cloud.google.com/gemini/data-agents/conversational-analytics-api/data-residency
- **Cloud Run deploys from source or an image.** `gcloud run deploy --source .` builds from source, and `--image` deploys an existing image. Services are private by default unless `--allow-unauthenticated` is set. Authenticated calls use `Authorization: Bearer $(gcloud auth print-identity-token)`. Source: https://adk.dev/deploy/cloud-run/

## 8. CLIs and infrastructure as code
- **Install the gcloud CLI on Windows with winget or the official installer.** Winget: `winget install --id Google.CloudSDK` (version 593.0.0 on winget as of 2026-11-14). Installer: `https://dl.google.com/dl/cloudsdk/channels/rapid/GoogleCloudSDKInstaller.exe`. It needs Windows 8.1+ or Server 2012+, supports Python 3.10–3.15 and bundles Python by default. Source: https://docs.cloud.google.com/sdk/docs/install-sdk ; https://github.com/microsoft/winget-pkgs/tree/master/manifests/g/Google/CloudSDK
- **The current gcloud CLI is 593.0.0, released 2026-11-10.** In that release, bundled Python became a required component on Windows x86/x86_64. Release 591.0.0 updated bundled Python to 3.14.9. Source: https://docs.cloud.google.com/sdk/docs/release-notes
- **gcloud sign-in commands:** `gcloud init` authorizes and creates a default configuration (`--console-only` skips the browser). `gcloud auth login` signs in the CLI itself. `gcloud auth application-default login` creates the separate ADC file that client libraries, ADK and MCP clients use. Source: https://docs.cloud.google.com/sdk/docs/install-sdk ; https://docs.cloud.google.com/docs/authentication/application-default-credentials
- **ADC searches in a fixed order and writes a known file path.** The order is `GOOGLE_APPLICATION_CREDENTIALS`, then the gcloud ADC file, then the attached service account via the metadata server. The ADC file is `%APPDATA%\gcloud\application_default_credentials.json` on Windows and `$HOME/.config/gcloud/application_default_credentials.json` on Linux and macOS. ADC user tokens expire about every hour. Source: https://docs.cloud.google.com/docs/authentication/application-default-credentials ; https://docs.cloud.google.com/mcp/configure-mcp-ai-application
- **Service account impersonation can be set per command, for the whole CLI, or for ADC.** Per command: `--impersonate-service-account=SA_EMAIL`. Whole CLI: `gcloud config set auth/impersonate_service_account SA_EMAIL`. ADC: `gcloud auth application-default login --impersonate-service-account SA_EMAIL`. It needs `roles/iam.serviceAccountTokenCreator` on the target service account and `iamcredentials.googleapis.com` enabled. ## 10. Limits and gotchas
- **Standard PayGo replaced dynamic shared quota as the documented model for Gemini on Agent Platform.** The old `/vertex-ai/generative-ai/docs/dsq` URL now serves the Standard PayGo page. Gemini usage runs on shared capacity, with an organization-level usage tier set by eligible spend over a rolling 30 days. The tier's TPM threshold is the level below which traffic is prioritized, not a hard cap. Source: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/dsq ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/standard-paygo
- **Standard PayGo TPM thresholds per model, as shown 2026-11-14.** Pro, Carbon and Argon: Tier 1 ($10–$250) 500K, Tier 2 ($250–$2,000) 1M, Tier 3 ($2,000–$50,000) 2M, Tier 4 (above $50,000) 10M. Flash, Flash-Lite and Hydrogen: 2M, 4M, 10M and 50M. There is no separate RPM limit, and preview models are excluded. Tier 4 was added on 2026-09-10. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/standard-paygo ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **A 429 on Standard PayGo means temporary contention for shared capacity, not an exhausted fixed quota.** The fixes are exponential backoff, smoothing per-second spikes, and using the `global` endpoint. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/standard-paygo
- **Endpoint choice for Gemini trades capacity against data residency.** The `global` endpoint draws on a worldwide pool and gets the full tier threshold, but gives no data residency guarantee. Multi-region `us` and `eu` use separate pools. Single-region endpoints such as `us-central1` have the least headroom. Google recommends `global` unless residency requires otherwise. Org policy can block global endpoint traffic. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/standard-paygo ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency
- **Gemini models older than Gemini 3 are not served on the jurisdictional multi-region endpoints.** Those models stay on regional endpoints. Calling a model at an endpoint type it does not support returns a 404. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency ; https://www.braintrust.dev/docs/kb/vertex-ai-gemini-model-region-and-registry-issues.md (secondary)
- **Priority PayGo (preview) costs more per token than Standard PayGo but gives more consistent throughput, with no commitment.** Ramp limits were removed on 2026-09-10. Responses report `ON_DEMAND_PRIORITY` as the traffic type. Endpoint support (global, or global plus `us`/`eu`) differs between page versions. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/priority-paygo ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Flex PayGo (preview) is 50% off Standard PayGo, for latency-tolerant work.** It works only on the global endpoint, allows a 20 MB payload, and accepts request timeouts up to 30 minutes. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/flex-paygo
- **Provisioned Throughput is bought in GSUs (generative AI scale units) for terms of 1 week, 1 month, 3 months or 1 year.** Quota is GSUs times the model's per-GSU throughput, for example 2,690 tokens/s per GSU for `gemini-2.5-flash` and 685 tokens/s for Gemini 4 Hydrogen. It is enforced over a 1 to 120 second window depending on order size. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/provisioned-throughput/use-provisioned-throughput ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **By default, a request over the Provisioned Throughput quota spills over in full to pay-as-you-go billing.** Send header `X-Vertex-AI-LLM-Request-Type: dedicated` to get a 429 instead of overage charges, or `shared` to bypass Provisioned Throughput. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/provisioned-throughput/use-provisioned-throughput
- **Claude models launched after 2026-05-26 share one quota per lineage per location.** The lineages are `anthropic-claude-opus`, `-sonnet`, `-haiku`, `-fable` and `-fable-fast`. The `global`, `us` and `eu` endpoints are separate buckets, and fast-mode requests use a `*-fast` bucket. Older Claude models use per-model QPM/TPM by endpoint type. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas
- **Default Claude quotas, as shown 2026-11-14.** Opus 5.5: 2,000 QPM, 20M input TPM and 2M output TPM on global, half that on multi-region. Sonnet 5.5/5: 2,500 QPM, 25M and 2.5M on global. Haiku 5.5: 3,000 QPM, 30M and 3M on global. The Quota page's token usage can be inaccurate, so use the `token_count` metrics. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas
- **New projects can show Claude quota as "0 to 0" until model access eligibility is reviewed.** Source: https://discuss.google.dev/t/anthropic-claude-quota-stuck-at-0-to-0-on-new-paid-account-requesting-manual-model-access-eligibility-review-eu-multi-region/382201 (secondary)
- **Agent Runtime default quotas per project per region.** Query/StreamQuery: 90 per minute. BidiStreamQuery: 10 concurrent live connections. Resources: 100. Resource create, update or delete: 10 per minute. Session writes: 100 per minute. Session event appends: 300 per minute. Revisions: 950 per agent, a fixed system limit. Express mode allows only 10 query requests per minute and 10 resources. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/agent-quotas
- **Other Agent Platform quotas per project per region.** RAG Engine: data-management APIs 60 RPM, `RetrievalContexts` 600 RPM, `ImportRagFiles` 3 concurrent and 10,000 files per request. Gen AI evaluation service: 1,000 RPM and 20 concurrent runs. Online inference: 30,000 RPM. CRUD calls: 600 RPM. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/quotas
- **BigQuery MCP SQL tools stop long queries and cap results.** They cancel queries after 3 minutes by default, return at most 3,000 rows, and don't support Google Drive external tables. `execute_sql_readonly` rejects DML, DDL, Python UDFs and GQL. BigQuery API quotas still apply. Source: https://docs.cloud.google.com/bigquery/docs/use-bigquery-mcp
- **Cloud Run limits that affect agents.** A request can run up to 60 minutes. HTTP/1 requests and responses are capped at 32 MiB, except HTTP/2 and streamed responses. Each instance allows up to 1,000 concurrent requests, 32 GiB memory and 8 vCPU. The default regional cap is 100 instances per project, and the L4 GPU quota is 0 by default (3 is auto-granted to new projects). Source: https://docs.cloud.google.com/run/quotas
- **Apigee MCP has tool, region and SSE limits.** SaaS organizations are capped at 1,000 MCP tools. Provisioning may fail in `europe-central2`, `europe-southwest1`, `europe-west9` and `me-central2`. GET requests on MCP error responses return 405 because SSE is not supported. Apigee hybrid does not support the stateless MCP protocol `2026-07-28`, and toggling MCP there triggers a staged Message Processor restart. Source: https://docs.cloud.google.com/apigee/docs/api-platform/apigee-mcp/apigee-mcp-overview
- **Container-based Agent Runtime deploys need the Agent Runtime service agent to have Artifact Registry Reader.** Without it, pods fail with `IMAGE_PULL_BACKOFF`. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/runtime/use-terraform
- **Do not grant `roles/integrations.integrationInvoker` to ADK agents on Agent Runtime that use `ApplicationIntegrationToolset`.** The docs say it can cause 403 errors and list `roles/integrations.integrationEditor` instead. Source: https://adk.dev/integrations/application-integration/
- **Hand-pasted ADC bearer tokens in MCP client configs expire after about an hour.** For long-lived clients, use an OAuth client or `authProviderType: google_credentials`. Model Armor prompt-injection filters can produce false-positive 403s on the Developer Knowledge MCP server, and `HIGH_AND_ABOVE` confidence is recommended. Source: https://docs.cloud.google.com/mcp/configure-mcp-ai-application ; https://developers.google.com/knowledge/mcp
- **The SDK split in `google-cloud-aiplatform` 2.0.1 breaks code that imports `vertexai.agent_engines` or the `vertexai` generative modules.** Migrate to `google-cloud-agentplatform` and `google-genai`. Separately, a 2026-03-31 security fix requires `google-cloud-aiplatform` >= 1.165.1 or an explicit staging bucket. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes
- **Application Integration announced on 2026-08-28 a change to how identities are handled for integration runs, which may require customer action.** Source: https://docs.cloud.google.com/application-integration/docs/release-notes
- **Renames to know:** Vertex AI to Gemini Enterprise Agent Platform (2026-04-22), Agent Engine to Agent Runtime, Vertex AI Search to Agent Search, Vector Search 2.0 to Agent Retrieval, Dataplex to Knowledge Catalog, `genai-toolbox` to `mcp-toolbox`, `GOOGLE_GENAI_USE_VERTEXAI` to `GOOGLE_GENAI_USE_ENTERPRISE`, and the gcloud `api-registry mcp` commands to `gcloud agent-registry`. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes ; https://github.com/googleapis/mcp-toolbox ; https://adk.dev/get-started/google-cloud/ ; https://docs.cloud.google.com/sdk/docs/release-notes

## Open questions
- Stage labels for many Google Cloud remote MCP servers: the supported-products page leaves BigQuery, Cloud Run and many others unlabeled, so GA versus Preview could not be confirmed per server.
- Whether Provisioned Throughput covers the `global` endpoint: the examples use `global` but the text talks about regional consumption, so this is unclear.
- Whether Priority PayGo works on the global endpoint only or also on `us`/`eu`: the page versions disagree.
- The exact Agent Runtime per-request timeout and payload size limit: neither the agent quotas page nor the runtime overview states them.
- A dedicated official A2A-on-Agent-Runtime docs page: the guessed URL returned 404, so the A2A preview status relies on the runtime overview table and codelabs.
- Whether Integration Connectors can expose a connection as an MCP server: only the client-side MCP connector (preview since 2025-12-16) was found.
- The location of gcloud's own credential store on Windows (`%APPDATA%\gcloud`, `credentials.db`) is unverified. Only the ADC file path was confirmed.
- Whether Claude server tools (web search, code execution) are supported on Agent Platform: the use-claude page says server tools are not supported, and this was not cross-checked against Anthropic's documentation.
