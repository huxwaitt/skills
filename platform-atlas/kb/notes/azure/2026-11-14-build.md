# Microsoft Azure: capabilities, connectivity, CLIs, docs, limits (as of 2026-11-14)

## 6. AI and agent capabilities

- **Azure AI Foundry is now named Microsoft Foundry.** The rename was announced at Microsoft Ignite on 2025-11-18. The docs hub now lives at `https://learn.microsoft.com/azure/foundry/` (the old `/azure/ai-foundry/` path redirects there), and the older portal is documented separately as "Foundry (classic)". (secondary for the Ignite date) Source: https://learn.microsoft.com/azure/foundry/ ; https://www.directionsonmicrosoft.com/microsoft-ignite-2025-ten-things-you-need-to-know/
- **Azure AI Services were rebranded as "Foundry Tools".** The Foundry docs hub groups Speech, Translator, Language, Document Intelligence, Content Understanding and Face under "Foundry Tools", and Azure Updates item AZ526132 announced the rebrand as generally available. (secondary for the Azure Updates item) Source: https://learn.microsoft.com/azure/foundry/ ; https://mc.merill.net/message/AZ526132
- **Foundry RBAC roles were renamed.** `Foundry User`, `Foundry Owner`, `Foundry Account Owner` and `Foundry Project Manager` were previously `Azure AI User`, `Azure AI Owner`, `Azure AI Account Owner` and `Azure AI Project Manager`. Role IDs and permissions are unchanged, and the old names may still appear while the rename rolls out. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **Foundry Agent Service is GA and offers three agent types.** The types are prompt agents (configuration only), voice-based prompt agents (preview, run through Voice Live over WebSocket) and hosted agents (your own code in a container or .zip). Code you already run elsewhere can also call the Responses API directly as an "ephemeral agent". Source: https://learn.microsoft.com/azure/foundry/agents/overview ; https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions
- **Agent Service first reached GA in May 2025.** It was in preview from December 2024. MCP tool support was added in June 2025, and the Browser Automation tool (Aug 2025) and Computer Use tool (Sep 2025) arrived as previews. Source: https://learn.microsoft.com/azure/foundry-classic/agents/whats-new
- **Agents (classic) are deprecated and retire on 2027-03-31.** The classic model uses threads, runs and assistants. Microsoft's migration guide moves workloads to the new Responses-based agents (conversations instead of threads, responses instead of runs, versioned agents). Connected agents (classic) are not carried into the new service. Source: https://learn.microsoft.com/azure/foundry-classic/agents/whats-new
- **The Azure OpenAI Assistants API retired on 2026-08-26, per secondary sources.** Microsoft's replacement is Foundry Agent Service. (unverified) Source: https://endoflife.ai/article-azure-openai-assistants-retirement
- **Hosted agents run your agent code in per-session VM-isolated sandboxes.** Supported frameworks include Microsoft Agent Framework, LangGraph, the OpenAI Agents SDK, the Anthropic Agent SDK or custom code, in Python or C#. Each session gets a persistent `$HOME` and `/files`. Each agent gets a dedicated Microsoft Entra agent identity and its own endpoint. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents
- **Hosted-agent sizing and session lifecycle are fixed in each agent version.** Sandbox sizes are 0.5 vCPU/1 GiB, 1 vCPU/2 GiB or 2 vCPU/4 GiB. The idle timeout is configurable from 2 to 240 minutes (default 15), and sessions are deleted after 30 days of inactivity. Billing covers CPU and memory across active sessions. Versions are immutable, and an endpoint sends 100% of traffic to one version (no traffic splitting). Source: https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents
- **Hosted agents expose several protocols.** These are Responses (`{project_endpoint}/agents/{name}/endpoint/protocols/openai/responses`), Invocations (arbitrary JSON at `/protocols/invocations`), Invocations WebSocket (`/protocols/invocations_ws`), Activity (bridged automatically for Teams and Microsoft 365) and A2A. The container listens on port 8088. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents ; https://learn.microsoft.com/azure/foundry/agents/concepts/cli-agent-development
- **Toolboxes bundle Foundry tools behind one managed MCP-compatible endpoint.** The endpoint pattern is `{project_endpoint}/toolboxes/{name}/mcp?api-version=v1`. Toolboxes add versioning and promotion, centralized auth, `tool_search`/`call_tool` meta-tools for large tool sets, and Skills (preview). Any MCP client can use them, not only Foundry agents. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/toolbox-overview ; https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol
- **Foundry Agent Service ships many built-in tools.** They are MCP, web search, Azure AI Search, code interpreter, file search, OpenAPI, A2A, browser automation, Fabric IQ, Work IQ, function calling, Grounding with Bing, computer use, image generation, SharePoint, Fabric data agent and Azure Functions. Grounding with Bing, computer use, image generation, SharePoint, Fabric data agent and Azure Functions can't be placed in a toolbox. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/toolbox-overview
- **The Microsoft Copilot harness (preview) is an optional runtime for prompt agents.** It adds file read/write, shell, web and subagents for multi-step workflows. It is limited to a subset of regions and doesn't support BYOM, Foundry Memory, `store: false` or `previous_response_id`. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions
- **Long-running hosted agents are in preview.** The previews announced in August 2026 cover crash-resilient deployment, human-in-the-loop approval, steering an in-flight turn, stream-with-reconnect and task state management. "Routines" (triggers that invoke agents) and an agent optimizer (preview) are also documented. Source: https://learn.microsoft.com/azure/foundry/whats-new-foundry
- **Foundry Memory is a managed long-term memory store in preview.** It stores user profile, chat summary and procedural memory, and agents use it through a memory search tool or the Memory Store APIs. Quotas are 100 scopes per store, 10,000 memories per scope and 1,000 search or update requests per minute. VNet integration isn't supported. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/what-is-memory
- **The Foundry model catalog has two categories.** They are "Foundry Models sold by Azure" (including Azure OpenAI, MAI, Grok and DeepSeek) and "Foundry Models from partners and community" (Anthropic, Cohere, Meta, Mistral, NTT Data and others). Partner models are billed through Azure Marketplace, which requires `Microsoft.SaaS/register/action` and MarketplaceOrdering permissions (included in the Owner and Contributor roles). Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/models-from-partners
- **Claude models are in the Foundry catalog in two hosting versions.** One is hosted on Azure and the other on Anthropic infrastructure, and lifecycle status can differ between them. The catalog lists `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-2` and others. Global Standard is mostly in East US 2 and Sweden Central, plus several US regions. Data Zone Standard (US only) covers some models when hosted on Azure. Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/models-from-partners
- **Claude in Foundry rejects some subscription types.** CSP subscriptions, Enterprise Agreement accounts in South Korea, credit-only, sponsored and free-trial subscriptions are not supported. Several sampling parameters are rejected on newer Claude models (for example, `temperature` and `top_k`, and `top_p` must be at least 0.99). Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/models-from-partners
- **"Instant access (preview)" calls supported models by name without a deployment.** It is separate from the deployment types. Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/deployment-types
- **Foundry IQ is the managed knowledge layer for agents.** It is built on Azure AI Search knowledge bases and agentic retrieval. It supports Blob, SharePoint, OneLake and web sources, ACL sync, Purview labels and queries under the caller's Entra identity. Some features are GA and some are preview, depending on the Search REST API version. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/what-is-foundry-iq
- **Azure AI Search agentic retrieval has a GA API and a preview API.** Use REST API `2026-04-01` for GA features (GA knowledge source types, minimal extractive retrieval). Use `2026-08-01-preview` for LLM query planning, answer synthesis, low or medium reasoning effort and multi-turn messages. The Azure and Foundry portals expose preview schemas only. Source: https://learn.microsoft.com/azure/search/agentic-retrieval-overview
- **Agentic retrieval bills tokens on two services.** Azure AI Search charges for retrieval tokens (with a free monthly allowance, then pay-as-you-go), and Azure OpenAI charges for query-planning tokens. Knowledge bases can be queried through a retrieve action or an MCP endpoint. Source: https://learn.microsoft.com/azure/search/agentic-retrieval-overview
- **Foundry tracing uses OpenTelemetry GenAI semantic conventions and stores data in Application Insights.** It is GA for prompt and hosted agents and in preview for workflow and external agents. Integrations exist for Agent Framework, LangChain, LangGraph and the OpenAI Agents SDK. Viewing traces requires a Log Analytics reader role. Source: https://learn.microsoft.com/azure/foundry/observability/concepts/trace-agent-concept
- **Foundry evaluations run through the OpenAI-compatible `client.evals` API.** You get that client from `AIProjectClient.get_openai_client()` with `azure-ai-projects>=2.8.0`. Options include rubric evaluators generated from the agent's context, built-in evaluators (`builtin.violence`, `builtin.coherence` and others) and agent targets (`azure_ai_agent`). Continuous evaluation, GitHub Actions gates and an AI Red Teaming Agent (preview) are also available. Source: https://learn.microsoft.com/azure/foundry/observability/how-to/evaluate-agent ; https://learn.microsoft.com/azure/foundry/
- **Microsoft Agent Framework is the direct successor to Semantic Kernel and AutoGen.** It was built by the same teams, and Microsoft publishes migration guides from both. Version 1.0 (GA for .NET and Python) was announced on 2026-04-03. A Go version is in public preview. The PyPI package `agent-framework` was at 1.26.0 on 2026-11-12. Source: https://learn.microsoft.com/agent-framework/overview/ ; https://devblogs.microsoft.com/agent-framework/wp-json/wp/v2/posts/5212 ; https://pypi.org/project/agent-framework/
- **Agent Framework packages are `agent-framework` (pip) and `Microsoft.Agents.AI` (NuGet).** `Microsoft.Agents.AI.Foundry` adds Foundry support (prerelease). Go uses `github.com/microsoft/agent-framework-go`. The framework covers agents, a "Harness Agent", graph-based workflows, MCP clients and model providers including Foundry, Azure OpenAI, OpenAI, Anthropic and Ollama. Source: https://learn.microsoft.com/agent-framework/overview/ ; https://devblogs.microsoft.com/agent-framework/wp-json/wp/v2/posts/5212
- **Microsoft has not stated a Semantic Kernel or AutoGen end-of-life date in the pages checked.** The Semantic Kernel overview page doesn't mention Agent Framework, and secondary sources call both frameworks "maintenance mode". (secondary) Source: https://learn.microsoft.com/semantic-kernel/overview/ ; https://visualstudiomagazine.com/articles/2026/04/06/microsoft-ships-production-ready-agent-framework-1-0-for-net-and-python.aspx
- **Azure Logic Apps supports autonomous and conversational agentic workflows.** An "agent loop" action can use the 1,400+ connectors as tools. Agentic workflows are available in Standard; the Consumption version is in preview. Consumption uses Foundry models. Standard uses an Azure OpenAI resource, a Foundry project (preview) or an APIM LLM API (preview). Source: https://learn.microsoft.com/azure/logic-apps/agent-workflows-concepts
- **Logic Apps agentic workflows have limits and their own billing.** An agent can't be nested as a tool inside another agent. Production chat clients need Easy Auth (Standard) or OAuth 2.0 with Entra ID (Consumption), because the portal "developer key" is for testing only. Consumption agent loops bill tokens as Enterprise Units. Source: https://learn.microsoft.com/azure/logic-apps/agent-workflows-concepts
- **Microsoft Fabric data agents are GA.** They answer natural-language questions over lakehouses, warehouses, Power BI semantic models, KQL databases (Eventhouse), mirrored databases, ontologies and Microsoft Graph by generating NL2SQL, NL2DAX and NL2KQL queries. They need an F2+ or P1+ capacity, run read-only and use the requesting user's identity. Source: https://learn.microsoft.com/fabric/data-science/concept-data-agent
- **Fabric data agents have tight output and configuration limits.** They allow up to 5 data sources, return at most 25 rows by 25 columns per answer, are English-only and don't support unstructured files. The LLM can't be changed, and queries fail if the data source capacity is in a different region from the agent's capacity. Source: https://learn.microsoft.com/fabric/data-science/concept-data-agent
- **Computer use and browser automation are agent tools with gaps.** Computer Use is available only in some regions (for example East US 2, Sweden Central and West Europe; not East US). Browser Automation runs on your own Microsoft Playwright Workspaces. Neither works in network-isolated Foundry. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions ; https://learn.microsoft.com/azure/foundry/how-to/configure-private-link ; https://learn.microsoft.com/azure/foundry-classic/agents/whats-new

## 7. Connectivity

- **The Foundry project endpoint has a fixed URL pattern.** It is `https://<resource-name>.services.ai.azure.com/api/projects/<project-name>`. It is used by the Foundry SDK for agents, tools, evaluations and connections. Microsoft Entra tokens use scope `https://ai.azure.com/.default`. Source: https://learn.microsoft.com/azure/foundry/how-to/develop/sdk-overview
- **The OpenAI-compatible v1 endpoint is `https://<resource-name>.openai.azure.com/openai/v1/`.** It works with the standard OpenAI SDKs and accepts either API keys or Entra tokens (`https://ai.azure.com/.default`). An Azure OpenAI resource provides only this endpoint, while a Foundry resource provides all endpoints. Source: https://learn.microsoft.com/azure/foundry/how-to/develop/sdk-overview
- **Claude models in Foundry use an Anthropic-native endpoint.** It is `https://<resource-name>.services.ai.azure.com/anthropic` (Messages at `/anthropic/v1/messages`) and works with the Anthropic SDK. Source: https://learn.microsoft.com/azure/foundry/how-to/develop/sdk-overview
- **Foundry SDK packages exist for Python, JavaScript, .NET and Java.** Python: `azure-ai-projects` 2.x (docs require >=2.3.0; PyPI had 2.11.0 as of 2026-11-14) with `openai>=3.0.0`. JavaScript: `@azure/ai-projects` 2.8.0. .NET: `Azure.AI.Projects`, `Azure.AI.Projects.Agents` and `Azure.AI.Extensions.OpenAI` 2.0.0. Java: `com.azure:azure-ai-projects` and `azure-ai-agents` 2.3.0. The 1.x versions target Foundry (classic). Source: https://learn.microsoft.com/azure/foundry/how-to/develop/sdk-overview ; https://pypi.org/project/azure-ai-projects/
- **The control plane is Azure Resource Manager at `https://management.azure.com`.** Requests carry `api-version` query parameters. For example, Foundry project connections are created with `PUT .../providers/Microsoft.CognitiveServices/accounts/{account}/projects/{project}/connections/{name}?api-version=2025-04-01-preview`. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **The official Azure MCP Server is open source in `microsoft/mcp`.** It moved there from `Azure/azure-mcp`, and its source is under `servers/Azure.Mcp.Server`. Packages are npm `@azure/mcp`, NuGet `Azure.Mcp`, PyPI `msmcp-azure`, Docker `mcr.microsoft.com/azure-sdk/azure-mcp` and the VS Code extension `ms-azuretools.vscode-azure-mcp-server`. Source: https://github.com/microsoft/mcp ; https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/README.md
- **Azure MCP Server can be started several ways.** Commands include `npx -y @azure/mcp@latest server start`, `dotnet tool install Azure.Mcp`, `uvx --from msmcp-azure azmcp server start` and `docker run -i --rm --env-file <path> mcr.microsoft.com/azure-sdk/azure-mcp:latest`. In Claude Code, use `/plugin install azure@claude-plugins-official`. Source: https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/README.md
- **Azure MCP Server 2.0 went stable on 2026-04-10.** It added self-hosted remote (HTTP) mode with managed-identity or On-Behalf-Of auth, US Government and 21Vianet clouds, and 276 tools across 57 services. Source: https://devblogs.microsoft.com/azure-sdk/announcing-azure-mcp-server-2-0-stable-release
- **On npm, `@azure/mcp@latest` currently installs a beta.** The `latest` dist-tag points to `4.0.0-beta.7` (2026-11-11). The newest stable release is `3.0.0` (2026-10-12), so pin `@azure/mcp@3.0.0` if you need stable. Source: https://registry.npmjs.org/@azure/mcp ; https://github.com/microsoft/mcp/releases
- **Azure MCP Server tools cover 50+ service namespaces.** Examples include `foundry`, `search`, `speech`, `sreagent`, `storage`, `cosmos`, `sql`, `postgres`, `kusto`, `monitor`, `keyvault`, `role`, `policy`, `quota`, `pricing`, `functionapp`, `appservice`, `aks`, `acr`, `eventgrid`, `servicebus`, `bicepschema`, `azureterraform`, `deploy`, `extension` (az and azd) and `group`/`subscription`. Source: https://learn.microsoft.com/azure/developer/azure-mcp-server/tools/
- **Azure MCP Server has start options that limit what it exposes.** `--mode` takes `namespace` (default), `consolidated`, `all` or `single`. You can also set namespace filters, a `--read-only` flag, `--tool` to expose named tools, the transport (default `stdio`), and an option to disable elicitation, which isn't recommended. Elicitation prompts the user before tools return secrets such as Key Vault values. Source: https://learn.microsoft.com/azure/developer/azure-mcp-server/tools/
- **Azure MCP Server auth in local mode uses a custom credential chain.** The order is Environment, Visual Studio, VS Code, Azure CLI, Azure PowerShell, azd, then interactive browser. `AZURE_TOKEN_CREDENTIALS` pins one credential (or `prod` for non-interactive only). `AZURE_MCP_ONLY_USE_BROKER_CREDENTIAL=true` uses WAM on Windows. The server never stores tokens. Source: https://github.com/microsoft/mcp/blob/main/docs/Authentication.md
- **Azure MCP Server auth in remote mode is set with `--outgoing-auth-strategy`.** It takes `UseOnBehalfOf` (default) or `UseHostingEnvironmentIdentity`. The Entra app must expose scope `Mcp.Tools.ReadWrite` (delegated) or app role `Mcp.Tools.ReadWrite.All`. The azd templates `azmcp-obo-template` and `azmcp-foundry-aca-mi` set this up on Azure Container Apps. Source: https://github.com/microsoft/mcp/blob/main/docs/Authentication.md
- **Azure MCP Server telemetry is on by default.** Opt out with `AZURE_MCP_COLLECT_TELEMETRY=false`, or with `AZURE_MCP_COLLECT_TELEMETRY_MICROSOFT=false` to keep only your own Application Insights telemetry. Source: https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/README.md
- **The Microsoft Fabric MCP Server (public preview) is also built from `microsoft/mcp`.** Its source is under `servers/Fabric.Mcp.Server`, and version 1.8.0 was released on 2026-11-11. Source: https://github.com/microsoft/mcp ; https://github.com/microsoft/mcp/releases
- **Foundry MCP Server (preview) is a cloud-hosted remote MCP server.** It is at `https://mcp.ai.azure.com` (streamable HTTP) and gives tools for Foundry models, deployments and agents. It uses Entra ID with On-Behalf-Of, needs no infrastructure, and requires Contributor or higher on the Foundry project. Source: https://learn.microsoft.com/azure/foundry/mcp/get-started
- **Foundry agents can call external remote MCP servers through the `mcp` tool.** Settings include `server_url`, a unique `server_label`, `allowed_tools`, `require_approval` (default `always`; also `never` or per-tool lists) and `project_connection_id` for stored credentials. Approval-required calls return `mcp_approval_request`, and you answer with `mcp_approval_response` in the same conversation. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol
- **Foundry agents can authenticate to MCP and tool connections in four ways.** The options are key-based (custom headers), Microsoft Entra (agent identity or project managed identity), OAuth identity passthrough (On-Behalf-Of), or unauthenticated. Some servers can be added straight from the Add Tools catalog, such as the Azure DevOps MCP Server. Source: https://learn.microsoft.com/azure/foundry/agents/overview ; https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol
- **Foundry Agent Service supports A2A protocol v1.0 (GA) and v0.3 (preview).** Calls in both directions are supported. Incoming A2A is enabled with a PATCH on the agent (`agent_card` plus `protocol_configuration.a2a`) through REST or SDK, not the portal. The base path is `.../agents/{agent}/endpoint/protocols/a2a`, with cards at `.../agentCard/v1.0` and `.../agentCard/v0.3`. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **Incoming A2A on Foundry needs Entra auth and supports limited transports and modalities.** Callers need the `Foundry Agent Consumer` role (ID `eed3b665-ab3a-47b6-8f48-c9382fb1dad6`) at project or agent scope and a token for `https://ai.azure.com/.default`. Only JSON-RPC is supported for v1.0, and only text; no SSE streaming. Tasks and contexts are kept for 60 days. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **Outgoing A2A from a Foundry agent uses the `A2ATool`.** It needs a `RemoteA2A` project connection (for example, `authType` `AgenticIdentityToken`, audience `https://ai.azure.com`). Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **Azure API Management can expose a managed REST API as a remote MCP server.** The operations become tools at `https://<apim>.azure-api.net/<api-name>-mcp/mcp`. It works on Developer, Basic, Standard, Premium and the v2 tiers, and in the self-hosted gateway. Only MCP tools are supported (no resources or prompts), and APIM workspaces aren't supported. Source: https://learn.microsoft.com/azure/api-management/export-rest-mcp-server ; https://learn.microsoft.com/azure/api-management/mcp-server-overview
- **APIM can also front existing MCP servers and import A2A agent APIs.** Existing servers include those on Logic Apps, Functions or LangServe. MCP servers can be managed with REST, ARM, Bicep, the Azure CLI or Terraform, and registered for discovery in Azure API Center. Source: https://learn.microsoft.com/azure/api-management/mcp-server-overview ; https://learn.microsoft.com/azure/api-management/genai-gateway-capabilities
- **The APIM AI gateway applies token and safety policies to LLM APIs.** Policies include `llm-token-limit`, `llm-emit-token-metric`, `llm-semantic-cache-lookup`/`llm-semantic-cache-store` (with Azure Managed Redis) and `llm-content-safety`. Backends get load balancing (round-robin, weighted, priority, session-aware) and a circuit breaker that honors `Retry-After`. It supports OpenAI Chat Completions or Responses, Anthropic Messages (v2 tiers) and Vertex AI APIs. Source: https://learn.microsoft.com/azure/api-management/genai-gateway-capabilities
- **APIM's unified model API (preview) puts many LLM backends behind one endpoint.** It exposes a single OpenAI-compatible endpoint, including Amazon Bedrock backends. An AI gateway integrated into Microsoft Foundry is also in preview. Source: https://learn.microsoft.com/azure/api-management/genai-gateway-capabilities
- **The Azure Functions MCP extension turns a function app into a remote MCP server.** It offers tool, resource and prompt triggers, plus MCP Apps. Endpoints are streamable HTTP at `/runtime/webhooks/mcp` and deprecated SSE at `/runtime/webhooks/mcp/sse`. Languages are C# (isolated worker, `Microsoft.Azure.Functions.Worker.Extensions.Mcp`), Python, JavaScript/TypeScript and Java; PowerShell and Go aren't supported. Source: https://learn.microsoft.com/azure/azure-functions/functions-bindings-mcp
- **Functions MCP endpoints require the `mcp_extension` system key by default.** Send it in `x-functions-key`. Set `extensions.mcp.system.webhookAuthorizationLevel` to `Anonymous` when using built-in MCP OAuth with Entra (preview). Self-hosted MCP SDK servers on Functions (custom handlers, endpoint `/mcp`) are in preview and need `AzureWebJobsFeatureFlags=EnableMcpCustomHandlerPreview`. Source: https://learn.microsoft.com/azure/azure-functions/functions-bindings-mcp ; https://learn.microsoft.com/azure/azure-functions/functions-mcp-tutorial
- **The Microsoft Learn MCP Server is a free, unauthenticated remote MCP server.** It is at `https://learn.microsoft.com/api/mcp` (streamable HTTP; a browser GET returns 405). Its tools are `microsoft_docs_search`, `microsoft_docs_fetch` and `microsoft_code_sample_search`. The index refreshes incrementally and fully once a day. Source: https://learn.microsoft.com/training/support/mcp ; https://learn.microsoft.com/training/support/mcp-developer-reference
- **Copilot Studio, Microsoft 365 Copilot and Teams are integration points, not part of this note.** Foundry agents publish to Microsoft 365 and Teams through the Activity protocol (`azd ai agent publish`). Foundry IQ knowledge bases connect to Copilot Studio agents, and APIM MCP servers can be consumed by Copilot Studio. Source: https://learn.microsoft.com/azure/foundry/agents/overview ; https://learn.microsoft.com/azure/foundry/agents/concepts/what-is-foundry-iq
- **Foundry agent tools connect to several other data and SaaS platforms.** These include the Fabric data agent and Fabric IQ, Azure Databricks Genie MCP (On-Behalf-Of), Microsoft Dataverse, SharePoint, Work IQ (Microsoft 365), Azure DevOps MCP and Twilio (voice channels). Source: https://learn.microsoft.com/azure/foundry/agents/concepts/agent-identity ; https://learn.microsoft.com/azure/foundry/agents/overview
- **JDBC and ODBC drivers don't apply to Foundry or Agent Service.** Both are REST/SDK-only. SQL connectivity applies to the data services instead, such as Azure SQL and Fabric SQL endpoints, which are out of scope here. Source: https://learn.microsoft.com/azure/foundry/how-to/develop/sdk-overview
- **Agents can be triggered by events and schedules.** Foundry "routines" pair a trigger (for example, `--trigger recurring --cron`) with an agent invocation through `azd ai routine`. Hosted agents with the Invocations protocol can receive webhooks. Logic Apps triggers (classic) can also invoke agents. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/cli-agent-development ; https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents

## 8. CLIs and infrastructure as code

- **Install the Azure CLI on Windows with winget.** The command is `winget install --exact --id Microsoft.AzureCLI`, which installs 64-bit by default. Alternatives are the MSI (`https://aka.ms/installazurecliwindowsx64`) or a ZIP (preview, no admin needed). The current version is 2.92.0. Update with `az upgrade`. Source: https://learn.microsoft.com/cli/azure/install-azure-cli-windows
- **Sign in to the Azure CLI with `az login`.** Other modes are a service principal, a managed identity, or Cloud Shell. Since September 2025, MFA is required for user identities in the CLI (not for service principals or managed identities). Set the subscription with `az account set --subscription`, and get tokens with `az account get-access-token --resource <aud>` (use the `expires_on` POSIX field). Source: https://learn.microsoft.com/cli/azure/authenticate-azure-cli
- **The Azure CLI stores credentials and extensions under `%USERPROFILE%\.azure`.** The token cache is `msal_token_cache.bin` or `msal_token_cache.json`, and extensions are in `%USERPROFILE%\.azure\cliextensions`. Source: https://learn.microsoft.com/cli/azure/install-azure-cli-windows

## 10. Limits and gotchas

- **Azure OpenAI quota is granted per subscription, per region, per model and per deployment type, in TPM.** You assign TPM to each deployment, and each assignment sets that deployment's rate limit. RPM is derived from capacity units: older chat models get 6 RPM per 1,000 TPM; o3 and o4-mini get 1 RPM per 1,000 TPM; o1 gets 1 RPM per 6,000 TPM; o3-mini, o1-mini and o3-pro get 1 RPM per 10,000 TPM. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **RPM is enforced over 1-second or 10-second windows.** Short bursts can return 429 below the per-minute limit; for example, a 600-RPM deployment throttles above 10 requests in a second. TPM counts actual tokens, not `max_tokens`. 429 responses include `retry-after-ms`, and every response includes `x-ratelimit-remaining-tokens`/`-requests`. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **Standard deployments can get 429s below quota during temporary rate-limit cuts.** Standard and Global Standard share a capacity pool, and the service may lower a deployment's effective limit for a few hours. You can spot this when `x-ratelimit-limit-tokens` is lower than the configured TPM. Provisioned (PTU) deployments avoid this. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **Foundry has nine deployment types, each with a SKU code.** `GlobalStandard`, `GlobalProvisionedManaged`, `GlobalBatch`, `DataZoneStandard`, `DataZoneProvisionedManaged`, `DataZoneBatch`, `Standard`, `ProvisionedManaged` and `DeveloperTier`. The Developer tier is for fine-tune evaluation only: deployments expire after 24 hours and have no SLA. Batch tiers cost 50% less, target 24-hour turnaround and use separate enqueued quota. Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/deployment-types
- **Deployment type sets where inference data is processed.** Global types may process in any Azure region. Data Zone types stay in the US, EU (EU Data Boundary, which may include EFTA) or APAC zone. Standard and Regional Provisioned stay in the chosen geography. New models arrive in the order Global, then Data Zone, then geography, and geography types have no guaranteed date. Azure Policy can block specific SKUs. Source: https://learn.microsoft.com/azure/foundry/foundry-models/concepts/deployment-types
- **Foundry quota tiers (Tier 0 to Tier 6) set default TPM and RPM.** Subscriptions upgrade automatically based on usage, and you can opt out with `tierUpgradePolicy: NoAutoUpgrade` (preview API `2025-10-01-preview`). Tier 0 (free) can't request increases. For example, Tier 1 gives `gpt-4.1` GlobalStandard 1,000,000 TPM / 1,000 RPM and DataZoneStandard 300,000 TPM / 300 RPM. Source: https://learn.microsoft.com/azure/foundry/openai/quotas-limits
- **Quota is moving to shared subscription-wide pools, starting after 2026-05-07.** Global Standard deployments of the same model and version share one pool across all regions, and Data Zone Standard shares one pool per data zone. The change began with Realtime Translate and Realtime Whisper, with all models to follow. Source: https://learn.microsoft.com/azure/foundry/openai/quotas-limits
- **Azure OpenAI has fixed per-resource and per-request limits.** They are: 30 resources per region per subscription, 32 standard deployments per resource, 128 tools or functions per `/chat/completions` request, 2,048 messages, 2,048 embedding inputs (300,000 tokens), 100,000 PTU per deployment and 10 custom headers (more causes HTTP 431). Source: https://learn.microsoft.com/azure/foundry/openai/quotas-limits
- **Quota increases go through the request form `https://aka.ms/oai/stuquotarequest`.** Requests are prioritized for customers who are using their current quota. Partner and community models don't support increases, except Anthropic. Viewing quota requires the `Cognitive Services Usages Reader` role at subscription scope. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **Check quota and capacity through two ARM APIs.** Usages: `GET .../providers/Microsoft.CognitiveServices/locations/{location}/usages?api-version=2024-10-01`. Model Capacities: `GET .../providers/Microsoft.CognitiveServices/modelCapacities?api-version=2024-10-01&modelFormat=OpenAI&modelName=...&modelVersion=...`. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **Deleting a resource programmatically holds its quota for 48 hours.** Deleting an Azure OpenAI resource through the API with deployments still on it ties up their quota until the resource is purged. Purge the deleted resource to free it immediately. Source: https://learn.microsoft.com/azure/foundry/openai/how-to/quota
- **Non-streaming MCP tool calls from Foundry agents time out after 100 seconds.** For longer work, use background mode with a supported model (preview), or MCP tasks through a toolbox (preview). Source: https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol
- **Foundry agents accept only remote MCP endpoints.** Local stdio servers must be hosted on Azure Container Apps (Linux amd64, stateless) or Functions (no `npx`/`uvx`, key auth only). Private MCP servers need Standard Agent Setup with BYO VNet. "Invalid tool schema" errors usually come from `anyOf`/`allOf` or multi-type parameters. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol
- **Foundry Agent Service has fixed limits that can't be raised.** They are: 128 tools per agent, 1,000 versions per agent (a terminal `UserError` beyond that), 100,000 messages per thread, 1,500,000 characters per message, 512 MB per file, 300 GB of total files and 2,000,000 tokens per vector-store file. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions
- **Concurrent hosted-agent sessions are capped per subscription per region.** The default is 2,000 in Canada Central, East US 2, Japan East, North Central US, South Africa North, Southeast Asia and Sweden Central, and 1,000 elsewhere. Exceeding it returns 429 `session_quota_exceeded` or `regional_session_quota_exceeded`. A full delegated subnet returns `subnet_exhausted`. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions
- **Tool availability differs by region and model.** For example, file search isn't available in Italy North or Brazil South. Many open and partner models (such as Llama-4-Scout and Mistral-small) support only code interpreter and file search. Check the tool-by-region and tool-by-model matrices before choosing a region. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/limits-quotas-regions
- **Network-isolated Foundry doesn't support every agent tool.** Unsupported: Fabric Data Agent, Logic Apps, Browser Automation, Computer Use and Image Generation. Bing, web search and SharePoint still work but go over public endpoints. Tools that leave through the VNet need a project-level capability host, or they fail with `name or host unknown`. Source: https://learn.microsoft.com/azure/foundry/how-to/configure-private-link
- **Several Private Link setup steps for Foundry are fixed at creation or need manual work.** Outbound VNet injection can't be added or changed after creation, so you must redeploy. The subnet must be delegated to `Microsoft.App/environments` and be /27 or larger. Don't use 172.17.0.0/16. Private endpoints for BYO Storage, AI Search and Cosmos DB aren't created automatically. Projects created before 2026-06-25 need a public ACR for hosted-agent images. Source: https://learn.microsoft.com/azure/foundry/how-to/configure-private-link
- **Azure AI Search indexers behind private endpoints need a private execution environment.** Set `executionEnvironment` to `"Private"`, or indexing fails silently and leaves an empty index. Source: https://learn.microsoft.com/azure/foundry/how-to/configure-private-link
- **APIM response-body logging and buffering break MCP servers.** Set "Number of payload bytes to log" for Frontend Response to 0 at the All APIs scope, and don't read `context.Response.Body` in MCP server policies, because buffering breaks streaming. Use MCP Inspector 0.9.0 to test APIM MCP servers. Source: https://learn.microsoft.com/azure/api-management/export-rest-mcp-server
- **Agent identities start with no permissions.** Assign RBAC to each agent identity by its object (principal) ID, not its application ID. Migrating from shared project identities or Agent Applications to per-agent identities changes the identity, and existing role assignments don't carry over. Source: https://learn.microsoft.com/azure/foundry/agents/concepts/agent-identity ; https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **A2A requests with no version get preview v0.3, not v1.0.** Set `A2A-Version: 1.0`, use `?a2a-version=1.0`, or fetch the `agentCard/v1.0` card. If the header and query string disagree, the service returns HTTP 400 `version-ambiguous`. Source: https://learn.microsoft.com/azure/foundry/agents/how-to/enable-agent-to-agent-endpoint
- **On Windows, a new terminal is needed after installing the Azure CLI.** Until you reopen it, PATH isn't updated. Behind a proxy, allow `https://aka.ms/` and `https://azcliprod.blob.core.windows.net/`. Moving from the 32-bit to the 64-bit CLI means reinstalling extensions. Source: https://learn.microsoft.com/cli/azure/install-azure-cli-windows
- **Recent renames, with dates where known.** Azure AI Foundry became Microsoft Foundry (announced 2025-11-18). Azure AI Services became Foundry Tools. The Azure AI User/Owner/Account Owner/Project Manager roles became Foundry User/Owner/Account Owner/Project Manager (2026, date not stated). Semantic Kernel and AutoGen were succeeded by Microsoft Agent Framework (1.0 on 2026-04-03). The Azure MCP Server repo moved from `Azure/azure-mcp` to `microsoft/mcp`. Source: https://learn.microsoft.com/azure/foundry/ ; https://learn.microsoft.com/azure/foundry/agents/concepts/agent-identity ; https://learn.microsoft.com/agent-framework/overview/
