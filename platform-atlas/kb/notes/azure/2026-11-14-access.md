# Microsoft Azure: Access, identity, roles, governance and commercial model (as of 2026-11-14)

## 1. Getting access
- **Azure resource hierarchy.** Azure resources sit in a hierarchy of Microsoft Entra tenant > root management group ("Tenant root group", ID equal to the Entra tenant ID) > management groups > subscriptions > resource groups > resources, and Azure RBAC role assignments and Azure Policy assignments inherit downward from any of these scopes. Source: https://learn.microsoft.com/en-us/azure/governance/management-groups/overview
- **Management group limits.** One Entra directory supports up to 10,000 management groups and a management group tree up to six levels deep (not counting the root or subscription level); each management group or subscription has exactly one parent, and all subscriptions in a management group must trust the same Entra tenant. Source: https://learn.microsoft.com/en-us/azure/governance/management-groups/overview
- **Who controls the root management group.** No one has default access to the root management group; only a Microsoft Entra Global Administrator can "elevate access" to get Azure RBAC `User Access Administrator` at root, and then delegate any Azure role down the hierarchy. Source: https://learn.microsoft.com/en-us/azure/governance/management-groups/overview
- **Custom roles with DataActions can't be assigned at management group scope.** Azure custom roles that contain `DataActions` (which includes most Foundry data-plane custom roles) can't be assigned at management group scope; assign them at subscription or lower. Source: https://learn.microsoft.com/en-us/azure/governance/management-groups/overview
- **Billing account types.** Azure is bought through four billing account types: Microsoft Online Services Program (pay-as-you-go/free/Visual Studio, max 5 subscriptions for a new account), Enterprise Agreement (enrollment > departments > accounts; 5,000 subscriptions per EA account), Microsoft Customer Agreement (billing account > billing profile > invoice section; up to 10,000 subscriptions for an enterprise MCA), and Microsoft Partner Agreement for CSP partners. Source: https://learn.microsoft.com/en-us/azure/cost-management-billing/manage/view-all-accounts
- **Partner models need Azure Marketplace.** Foundry Models from partners and community (for example Anthropic Claude, Cohere) are Azure Marketplace offers that are Non-Microsoft Products under the Product Terms; Student, Visual Studio Enterprise and Free-credit subscriptions can't purchase these SaaS offers, and CSP subscriptions can't purchase third-party model offerings. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-from-partners
- **Permissions to subscribe to partner models.** Subscribing to a Marketplace model needs `Microsoft.MarketplaceOrdering/agreements/offers/plans/read`, `Microsoft.MarketplaceOrdering/agreements/offers/plans/sign/action`, `Microsoft.SaaS/register/action` and related actions on the subscription, plus `Microsoft.SaaS/resources/read` and `/write` on the resource group; Azure RBAC `Owner` or `Contributor` on the subscription covers them. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-from-partners
- **Claude in Foundry subscription restrictions.** Claude models in Foundry need a paid Azure subscription whose billing account is in a country where Anthropic sells the offer; unsupported are EA accounts located in South Korea, CSP subscriptions, subscriptions without an active pay-as-you-go payment method, and credit-only sponsored subscriptions. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-from-partners
- **Day-one asks for an engineer on a client engagement.** Ask for: a guest or member account in the client Entra tenant with MFA registered; the target subscription and resource group names; Azure RBAC `Foundry User` on the Foundry project (plus `Reader` on the Foundry resource), and `Foundry Project Manager` if you must publish agents or assign `Foundry User` to agent identities; `Cognitive Services Usages Reader` at subscription scope for quota views; a decision on network isolation (private endpoints, delegated subnet); and, if creating agent identities outside Foundry, Entra `Agent ID Developer`. Derived from Microsoft's role tables. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/entra/agent-id/authorization-agent-id
- **Foundry resource model.** A Microsoft Foundry resource (ARM type `Microsoft.CognitiveServices/accounts`) is the top-level administrative, security and monitoring boundary; Foundry projects (`.../accounts/<account>/projects/<project>`) are sub-scopes; and individual agents (`.../projects/<project>/agents/<agentName>`) are a narrower scope evaluated only for agent endpoint access. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Hub-based projects are legacy.** Foundry hub-based projects (Azure Machine Learning-based) are shown only in the Foundry (classic) portal; some catalog models (for example `mistralai-Mixtral-8x22B-Instruct-v0-1`, `tsuzumi-7b`) still require a hub-based project. No end-of-life date for hubs was found. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-from-partners
- **Rename: Azure AI Foundry to Microsoft Foundry.** Microsoft announced on 2025-11-18 (Ignite 2025) that Azure AI Foundry is now Microsoft Foundry, and Azure AI Services were rebranded "Foundry Tools" (GA November 2025); docs moved from `/azure/ai-foundry/` to `/azure/foundry/` and the old URL redirects. (secondary) Source: https://www.directionsonmicrosoft.com/microsoft-ignite-2025-ten-things-you-need-to-know/ ; https://mc.merill.net/message/AZ526132 ; https://learn.microsoft.com/azure/ai-foundry/
- **Docs entry points (verified resolving 2026-11-14).** Azure docs hub https://learn.microsoft.com/en-us/azure/ ; Microsoft Foundry docs hub https://learn.microsoft.com/en-us/azure/foundry/ (the `/azure/ai-foundry/` URL redirects here); Microsoft Entra docs hub https://learn.microsoft.com/en-us/entra/ (lists Entra ID, Entra Agent ID, Workload ID, ID Governance). Source: https://learn.microsoft.com/en-us/azure/ ; https://learn.microsoft.com/en-us/azure/foundry/ ; https://learn.microsoft.com/en-us/entra/
- **Foundry release notes.** Microsoft Learn publishes a monthly "What's new" page for Foundry docs (latest seen covers August 2026, updated 2026-11-05) and points to the Foundry DevBlog for product announcements. Source: https://learn.microsoft.com/en-us/azure/foundry/whats-new-foundry ; https://devblogs.microsoft.com/foundry/

## 2. Identity and authentication
- **Human identity is Microsoft Entra ID.** All Azure and Foundry human access is through Microsoft Entra ID user principals (members or B2B guests); Foundry recommends Entra ID over API keys for production because Entra enables Conditional Access, MFA, managed identities and per-principal RBAC and auditing. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry
- **Mandatory MFA for Azure (Phase 1).** Since October 2024 Microsoft enforces MFA for user accounts signing in to the Azure portal, Microsoft Entra admin center and Intune admin center for create, read, update and delete operations (Microsoft 365 admin center from February 2025); there is no opt-out. Source: https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication
- **Mandatory MFA for Azure (Phase 2).** From 2025-10-01 MFA enforcement gradually applies to user accounts doing create, update or delete through Azure CLI, Azure PowerShell, Azure mobile app, IaC tools, SDKs and REST calls to `https://management.azure.com`; tenants could postpone Phase 2 to 2026-07-01 at most; managed identities and service principals are not affected; Microsoft recommends Azure CLI 2.76+ and Azure PowerShell 14.3+. Source: https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication
- **ROPC breaks under MFA.** The OAuth 2.0 Resource Owner Password Credentials flow (for example `UsernamePasswordCredential`, or `DefaultAzureCredential` with `AZURE_USERNAME`/`AZURE_PASSWORD`) is incompatible with MFA and is deprecated in MSAL and Azure Identity libraries; move automation to workload identities. Source: https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication
- **Machine identity types.** Azure supports Entra service principals (app registrations with client secret, certificate or federated credential), system-assigned managed identities (lifecycle tied to one resource) and user-assigned managed identities (standalone resource attachable to many resources; Microsoft's recommended type for Microsoft services); managed identities cost nothing extra. Source: https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview ; https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry
- **Foundry token scope and endpoint.** Entra ID tokens for Foundry use scope `https://ai.azure.com/.default` against endpoints like `https://<resource>.services.ai.azure.com`; token auth requires a custom subdomain on the Foundry resource, and a 401 usually means the wrong scope. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry
- **API keys are all-or-nothing.** Foundry API keys grant full access to the resource with no role restrictions, no per-user attribution and no Conditional Access; Agent Service, evaluations and Toolbox don't support API keys at all; Microsoft advises removing key auth (disable local auth) after callers move to tokens. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry ; https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Azure AI Search defaults to keys.** A new Azure AI Search service defaults to key-based authentication; you must switch the service to "Both" or "Role-based access control" or all RBAC-token requests are denied, and if a request carries both a key and a token, the key wins. Data-plane token scope is `https://search.azure.com/.default`. Source: https://learn.microsoft.com/en-us/azure/search/search-security-rbac
- **Workload identity federation.** A user-assigned managed identity or an app registration can trust tokens from an external OIDC issuer (GitHub Actions, any Kubernetes cluster including EKS/GKE, Google Cloud, AWS via IAM Outbound Identity Federation, SPIFFE/SPIRE, Azure Pipelines service connections) and exchange them for Entra access tokens with no stored secret; `issuer`, `subject` and `audience` must match the external token case-sensitively. Source: https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation
- **Federation gotchas.** Entra-issued tokens can't be used as the external token in a federated credential flow, Entra caches only the first 100 signing keys from the external issuer's OIDC endpoint, and an app registration can hold at most 20 federated identity credentials when using managed identities as FIC. Source: https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation ; https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview
- **Access token lifetime.** Entra access tokens get a random default lifetime of 60-90 minutes (75 average); tenants with Continuous Access Evaluation get long-lived tokens of 20-28 hours, revocable by CAE events. Source: https://learn.microsoft.com/en-us/entra/identity-platform/access-tokens
- **RBAC changes for managed identities can lag.** Role assignments granted to a managed identity can take several hours to take effect because managed identity tokens are cached. Source: https://learn.microsoft.com/en-us/azure/search/search-security-rbac
- **Workload ID Premium licensing.** Managed identities and workload identity federation are free; Microsoft Entra Workload ID Premium (listed at $3 per workload identity per month on the page dated 2025-03-18) adds Conditional Access and ID Protection for workload identities (single-tenant service principals only; managed identities aren't eligible), access reviews and app health recommendations. Source: https://learn.microsoft.com/en-us/entra/workload-id/workload-identities-faqs
- **Microsoft Entra Agent ID is GA.** Microsoft Entra Agent ID, an identity type made for AI agents, is generally available (what's-new page dated 2026-05-01); it adds agent identity blueprints, agent identities, agent identity blueprint principals and agents' user accounts, plus agent-specific OAuth flows, Conditional Access, ID Protection and ID Governance. Source: https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id
- **Agent identity blueprint.** An agent identity blueprint is an Entra object that templates agent identities and holds their credentials; OAuth permissions granted to a blueprint apply to all its agent identities, it can apply Conditional Access to all of them, disabling it stops all of them authenticating, and its only tenant operation is provisioning or deprovisioning agent identities via the Graph permission `AgentIdentity.CreateAsManager`. Source: https://learn.microsoft.com/en-us/entra/agent-id/agent-blueprint
- **Agent identity.** An Entra agent identity is a special service principal created from a blueprint; it is always single-tenant even if the blueprint is multitenant, and the blueprint is authorized to impersonate it. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity ; https://learn.microsoft.com/en-us/entra/agent-id/agent-blueprint
- **Foundry creates agent identities automatically.** In the current Foundry agent model, creating an agent provisions a unique blueprint and a default-instance agent identity that starts with no resource permissions; legacy agents share a project-level blueprint and identity, and migrating changes the identity so downstream role assignments don't transfer. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **Foundry blueprint is keyless.** Foundry puts a federated identity credential on each blueprint that trusts the first-party "Azure Machine Learning" app (`0736f41a-0425-4b46-bdb5-1563eff02385`) acting in your tenant; no secret or certificate exists, and neither project, agent code nor project managed identity holds the credential. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **Hosted-agent token service.** Code in a Foundry hosted agent gets tokens for its own agent identity through the hosted-agent token service; the project managed identity isn't available to hosted-agent code, and each session runs in a VM-isolated sandbox with no blueprint credential. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **On-behalf-of agent access is preview.** A Foundry agent identity acting on behalf of the signed-in user (for example Work IQ, Foundry MCP, Azure DevOps MCP, Fabric IQ, Dataverse) is in preview and needs the preview `AgentBlueprint` endpoint authorization scheme. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **Agent ID for non-Microsoft agents.** Entra Agent ID documents integration (sidecar and federation patterns) for agents on AWS, GCP and n8n, including a guide to secure an Amazon Bedrock agent, plus migration guides from custom app registrations and from Copilot Studio agents. Source: https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id
- **Agent ID SDKs.** Microsoft recommends the Microsoft Agent 365 CLI and SDK for provisioning and runtime token acquisition, `Microsoft.Identity.Web.AgentIdentities` for .NET, and the Microsoft Entra ID Auth SDK (sidecar container) for non-.NET or containerized agents. Source: https://learn.microsoft.com/en-us/entra/agent-id/faq
- **Agent identities can't do SSO.** Agent identities can't sign in through Entra sign-in pages, so they can't use OIDC or SAML single sign-on; the admin consent workflow also doesn't work for agent identity permission requests. Source: https://learn.microsoft.com/en-us/entra/agent-id/faq
- **Agent ID limits.** Non-Microsoft platforms using app-only permissions can create at most 250 agent identities per blueprint (Foundry and Copilot Studio are exempt); soft-deleted agent identities are restorable for 30 days; sequential Graph creates can fail with `400 Object ... not found`, so add retries with backoff. Source: https://learn.microsoft.com/en-us/entra/agent-id/faq
- **Conditional Access for agents licensing.** Conditional Access for agents requires Microsoft 365 E7 (includes Agent 365 and Microsoft Entra Suite) or a Microsoft Agent 365 license paired with at least Microsoft Entra P1 or Microsoft 365 E3 (page dated 2026-07-31). Source: https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id
- **Conditional Access targets differ per access pattern.** For on-behalf-of access the policy must target the user; for app-only access target the agent identity or its blueprint; for agent-user access target "Agent Users" (policies scoped to "Users" don't apply to agents' user accounts); policies don't apply when an agent uses an API key. Source: https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id
- **Copilot Studio touchpoint.** Foundry agent identities appear in the same tenant-wide Entra admin center inventory as Copilot Studio agents, and agent registry experiences are converging under Microsoft Agent 365; Copilot Studio itself is covered in a separate note. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity ; https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id
- **Microsoft Agent 365 GA.** Microsoft Agent 365 became generally available worldwide on 2026-05-01, reported at $15 per user per month standalone and included in Microsoft 365 E7. (secondary) Source: https://www.licensingschool.co.uk/licensing-blog/2026/03/23/agent-365-ga-announcement/ ; https://www.itelio.com/en/microsoft-message-center/MC1296867
- **Logic Apps managed identity.** Azure Logic Apps Standard enables a system-assigned managed identity by default (Consumption must enable it manually); both plans can carry one system-assigned plus multiple user-assigned identities, but Standard hybrid deployment doesn't support managed identity and needs an app registration. Source: https://learn.microsoft.com/en-us/azure/logic-apps/authenticate-with-managed-identity
- **API Management keyless backend auth.** Azure API Management authenticates to Foundry/Azure OpenAI backends with its managed identity via the `authentication-managed-identity` policy with `resource="https://cognitiveservices.azure.com"` (or a backend with managed identity credentials), and validates inbound Entra tokens with `validate-azure-ad-token` (or `validate-jwt` for other IdPs). Source: https://learn.microsoft.com/en-us/azure/api-management/api-management-authenticate-authorize-ai-apis

## 3. Roles and permissions
- **Two separate role systems.** Microsoft Entra directory roles (for example `Global Administrator`, `Application Administrator`, `Agent ID Administrator`) govern the directory and Graph; Azure RBAC roles (for example `Owner`, `Foundry User`) govern Azure resources at management group, subscription, resource group, resource, project or agent scope; agents may need both plus Graph permission grants. Source: https://learn.microsoft.com/en-us/entra/agent-id/authorization-agent-id
- **Foundry role rename.** The Azure RBAC roles `Azure AI User`, `Azure AI Owner`, `Azure AI Account Owner` and `Azure AI Project Manager` were renamed `Foundry User`, `Foundry Owner`, `Foundry Account Owner` and `Foundry Project Manager`; role IDs and permissions are unchanged, old names may still appear, and Microsoft advises using role GUIDs in code. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Foundry role GUIDs.** `Foundry User` = `53ca6127-db72-4b80-b1b0-d745d6d5456d`; `Foundry Owner` = `c883944f-8b7b-4483-af10-35834be79c4a`; `Foundry Account Owner` = `e47c6f54-e4a2-4754-9501-8e0985b135e1`; `Foundry Project Manager` = `eadc314b-1a2d-4efa-be10-5d325db5065e`; `Foundry Agent Consumer` = `eed3b665-ab3a-47b6-8f48-c9382fb1dad6`. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Foundry User.** Azure RBAC `Foundry User` grants reader access to the Foundry resource and project plus all `Microsoft.CognitiveServices/*` data actions; it's the least-privilege role for developers building and testing agents and for the project managed identity on the Foundry resource; note its actions also include `Microsoft.CognitiveServices/accounts/listkeys/action`. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Foundry Agent Consumer.** Azure RBAC `Foundry Agent Consumer` has a single data action `Microsoft.CognitiveServices/accounts/AIServices/endpoints/interact/action` and is the least-privilege role for users or service principals that only call agents (for example the Responses API); the Azure portal assigns it only at Foundry account scope, so use `az role assignment create` for project or agent scope. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Foundry Project Runtime User.** Azure RBAC `Foundry Project Runtime User` (`142bfaed-a13f-4c2d-bed2-6db62c4a1009`) is a minimal runtime role whose data actions are `Microsoft.CognitiveServices/accounts/AIServices/responses/read`, `/write` and `/delete`. Source: https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Foundry Project Manager.** Azure RBAC `Foundry Project Manager` can create projects, build in them, publish agents and assign only the `Foundry User` role (ABAC-constrained); it is the minimum role on the Foundry resource to publish agents, and the recommended role for agent creators who must grant `Foundry User` to a new agent identity. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Foundry Account Owner.** Azure RBAC `Foundry Account Owner` can create Foundry accounts and projects, deploy models and conditionally assign `Foundry User`, ACR and monitoring roles, but has no data-plane rights (can't build or call agents). Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Foundry Owner.** Azure RBAC `Foundry Owner` combines control plane and data plane (create accounts/projects, manage models, build, publish, call agents) and is the only built-in role that can both fine-tune and deploy a fine-tuned model; Microsoft calls it a highly privileged self-serve role. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Owner and Contributor have no Foundry data plane.** Azure RBAC `Owner` and `Contributor` can create Foundry accounts, projects and deployments but can't create agents or call agent endpoints, because they carry no Foundry data actions. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Don't use Azure AI Developer for Foundry projects.** Azure RBAC `Azure AI Developer` (`64702f94-c441-49e6-a78b-ef80e0188fee`) and `Azure AI Administrator` apply only to Azure Machine Learning workspaces and Foundry hubs, not to Foundry projects or hosted agents. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Cognitive Services roles in Foundry.** Microsoft says not to assign `Cognitive Services *` roles for Foundry work except `Cognitive Services Usages Reader` (`bba48692-92b0-4667-a9ad-c31c7b334ac2`, subscription scope, for quota and deployment-eligibility views); `Cognitive Services OpenAI User` (`5e0bd9bd-7b93-4f28-af87-19fc36ad61bd`) still applies when code calls the account-level OpenAI endpoint directly, and `Cognitive Services User` (`a97b65f3-24c7-4388-baec-2e87135dc908`) for Speech, Vision or Language directly. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry ; https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Cognitive Services OpenAI Contributor.** Azure RBAC `Cognitive Services OpenAI Contributor` (`a001fd3d-188f-4b5d-821b-7da978bf7442`) adds deployment write/delete and RAI policy (guardrail) management to all `Microsoft.CognitiveServices/accounts/OpenAI/*` data actions. Source: https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/ai-machine-learning
- **Minimum Foundry setup.** Assign `Foundry User` on the Foundry resource to the developer and to the project managed identity; the portal does both automatically when the project creator can assign roles, but not when the resource or project is created by SDK or CLI. Source: https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry
- **Agent identity starts with nothing.** Foundry doesn't assign RBAC roles to a new agent identity; grant it access on each downstream resource (Azure RBAC, service data-plane roles such as Cosmos DB, or Graph app permissions) using the agent identity's object ID, preferring resource or resource-group scope. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **Agent implicit project access.** A Foundry agent has implicit access to model inference through its project endpoint and session storage without a role assignment; a narrow custom role with `Microsoft.CognitiveServices/accounts/AIServices/responses/*`, `.../agents/*/read` and `.../agents/*/write` is the documented least-privilege option when explicit project access is required. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Hosted agent supporting roles.** For hosted agents, grant the project managed identity `Container Registry Repository Reader` (or `AcrPull`) on ACR and `Log Analytics Data Reader` on the Log Analytics workspace; the deployer needs `Container Registry Repository Writer` (or `AcrPush`); trace viewers need `Monitoring Reader` on Application Insights; ACR must have `azureADAuthenticationAsArmPolicy` enabled. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Who can grant ACR and monitoring roles.** Only Azure RBAC `Owner`, `User Access Administrator` or `Role Based Access Control Administrator` on the target resource can create the ACR and Log Analytics role assignments for hosted agents; `Foundry Project Manager` and `Foundry Account Owner` are constrained to assigning `Foundry User`. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **User identity impersonation needs a custom role.** Sending the `x-ms-user-identity` header to a hosted agent requires data action `Microsoft.CognitiveServices/accounts/AIServices/agents/endpoints/UserIdentityImpersonation/action`, which is in no built-in role (it was removed from `Foundry User` and `Foundry Owner`), so create a custom role for the middle-tier identity. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **Standard agent setup roles.** In Foundry Agent Service standard setup the project managed identity needs `Cosmos DB Operator` and `Storage Account Contributor` at account level, `Search Index Data Contributor` and `Search Service Contributor` on Azure AI Search, `Storage Blob Data Contributor` on `<workspaceId>-azureml-blobstore`, `Storage Blob Data Owner` on `<workspaceId>-azureml-agent`, and `Cosmos DB Built-in Data Contributor` on database `enterprise_memory`. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/standard-agent-setup
- **Azure AI Search roles.** Azure AI Search data-plane roles are `Search Index Data Reader` (`1407120a-92aa-4202-b7e9-c0e197c71c8f`, query and knowledge-base retrieve) and `Search Index Data Contributor` (`8ebe5a00-799e-43f5-93ac-243d3dce84a7`, load and query); `Search Service Contributor` (`7ca78c08-252a-4471-8644-bb5ff32d4ba0`) manages indexes, indexers and knowledge bases but can also retrieve admin keys; data roles can be scoped to a single index via CLI, PowerShell or REST only. Source: https://learn.microsoft.com/en-us/azure/search/search-security-rbac
- **Who assigns Azure roles.** Creating Azure RBAC role assignments requires `Owner`, `User Access Administrator`, `Role Based Access Control Administrator`, or a custom role with `Microsoft.Authorization/roleAssignments/write` at the target scope; on the client side this is usually the subscription owner or cloud platform team. Source: https://learn.microsoft.com/en-us/azure/search/search-security-rbac ; https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry
- **Entra roles for agent identities.** Entra `Agent ID Administrator` (template `db506228-d27e-4b7d-95e5-295956d6615f`) manages the full lifecycle of blueprints, blueprint principals, agent identities and agents' user accounts; `Agent ID Developer` (template `adb2368d-a9be-41b5-8667-d96778e081b0`) can create a blueprint and its principal and becomes owner; `Agent Registry Administrator` (`6b942400-691f-4bf0-9d12-d8a254a2baf5`) manages the Agent Registry. Some third-party sources list `db506228...` for Agent ID Developer; the Learn permissions reference (dated 2026-11-03) is newer and authoritative. Source: https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference

Source: https://learn.microsoft.com/en-us/fabric/admin/service-admin-portal-developer

## 4. Governance, security and compliance
- **Foundry inbound network isolation.** A Foundry resource's public network access flag can be Disabled (private endpoint only, target sub-resource labelled "account"), "Enabled from selected IP addresses", or All networks; DNS uses a `privatelink` subdomain zone, and only Approved private endpoints carry traffic. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link
- **Agent Service outbound isolation.** Foundry Agent Service outbound isolation injects the agent client into a customer subnet delegated to `Microsoft.App/environments` (size /27 or larger); outbound settings can't be changed after creation (redeploy to add injection), private endpoints for Storage, AI Search and Cosmos DB aren't auto-created, and VNet tool calls need a project-level capability host. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link
- **Tool support behind a VNet.** In network-isolated Foundry, MCP (private), OpenAPI, Azure Functions and A2A tools go through your subnet; Azure AI Search and File Search through private endpoints; Code Interpreter and function calling over the Microsoft backbone; Bing, web search and SharePoint grounding over public endpoints; Logic Apps tool, Browser Automation, Computer Use, Image Generation and Fabric Data Agent are not supported. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link
- **Private ACR for hosted agents.** Foundry projects created after 2026-06-25 support a private Azure Container Registry (public access disabled) for hosted agents; older projects need the registry reachable on its public endpoint. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link ; https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
- **AI gateway in Foundry is public by default.** An AI Gateway (API Management) created from the Foundry portal for a private Foundry resource is automatically public; network isolation for the gateway must be configured in the Azure portal. AI gateway in Foundry is in preview. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link ; https://learn.microsoft.com/en-us/azure/api-management/genai-gateway-capabilities
- **Trusted Azure services exception.** A network-restricted Foundry resource can allow trusted services `Microsoft.CognitiveServices`, `Microsoft.Search` and `Microsoft.MachineLearningServices` through when their managed identity holds the right role. Source: https://learn.microsoft.com/en-us/azure/foundry/how-to/configure-private-link
- **Data never trains models (models sold by Azure).** For Foundry Models sold by Azure, including Azure OpenAI, prompts, completions, embeddings and training data are not available to other customers or to OpenAI or other model providers, aren't used to improve providers' models, and aren't used to train foundation models without permission; the models are stateless and don't call OpenAI-operated services. Source: https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy
- **Processing location by deployment type.** Standard and Regional Provisioned deployments process prompts within the resource's Azure geography; DataZone types process within the Microsoft-defined data zone (US, EU via the EU Data Boundary which may include EFTA countries such as Norway and Switzerland, or APAC); Global types may process in any region; data at rest stays in the customer geography for all types. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types ; https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy
- **Deployment type SKU names.** `GlobalStandard`, `GlobalProvisionedManaged`, `GlobalBatch`, `DataZoneStandard`, `DataZoneProvisionedManaged`, `DataZoneBatch`, `Standard`, `ProvisionedManaged`, `DeveloperTier` (fine-tuned model evaluation only, 24-hour lifetime, no SLA or data-residency guarantee); new models arrive Global first, then Data Zone, then geography-based. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types
- **Restrict deployment types with Azure Policy.** An Azure Policy rule on `Microsoft.CognitiveServices/accounts/deployments/sku.name` (for example denying `GlobalStandard`) enforces data-residency choices across subscriptions. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types
- **Stored data for stateful features.** Data stored by Responses API, Assistants threads, stored completions, Files and vector stores stays in the Foundry resource in the customer's geography, is AES-256 encrypted with optional customer-managed keys, and can be deleted anytime; preview features may not meet all these conditions. Source: https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy
- **Standard agent setup keeps agent data in your tenant.** Foundry Agent Service standard setup stores files in your Azure Storage, vector stores in your Azure AI Search and conversations and agent metadata in your Cosmos DB for NoSQL (at least 3000 RU/s); basic setup uses Microsoft-managed resources. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/standard-agent-setup
- **Abuse monitoring and human review.** Models sold by Azure run abuse monitoring: flagged prompts and completions are reviewed by automated means (LLMs) first and by authorized Microsoft employees only when needed, through Secure Access Workstations with JIT approval; for EEA deployments the reviewers are in the EEA; the abuse-monitoring store sits in the resource's geography. Source: https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/abuse-monitoring ; https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy
- **Opting out of abuse-monitoring storage.** Customers managed by a Microsoft account team or in an eligible program can apply for modified abuse monitoring via a Limited Access form; once approved, the resource shows capability `ContentLogging` = `false` in its JSON view or `az cognitiveservices account show`, though automated review may still run. Source: https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/limited-access ; https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy
- **Guardrails (previously content filters).** Foundry guardrails are named collections of controls covering Hate, Sexual, Self-harm, Violence, user prompt attacks, indirect attacks, protected material (text and code), PII (preview), Task Adherence (preview), Groundedness (preview, models only) and Spotlighting (preview, models only); models default to `Microsoft.DefaultV2`. Source: https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview
- **Agent guardrails are preview.** Guardrails for Foundry agents are in preview and add tool call and tool response intervention points; an agent's assigned guardrail fully overrides its model's guardrail, and an agent with none inherits the model deployment's guardrail; guardrails apply only to Foundry Agent Service agents, not other agents registered in the Foundry Control Plane. Source: https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview
- **Hosted agent egress controls.** Foundry hosted agents support network egress controls (preview) configured in the same guardrail (RAI policy) to limit outbound destinations. Source: https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview
- **Turning guardrails off needs approval.** All customers can set blocking levels and turn off content harms for inputs, but turning guardrails off for outputs requires approval through the "Limited Access Review: Modified Guardrails" form, available only to Microsoft-managed customers or eligible programs. Source: https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview ; https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/limited-access
- **Groundedness detection retirement.** Groundedness detection (preview) in Azure OpenAI retires on 2027-04-30; other guardrail controls are unaffected. Source: https://learn.microsoft.com/en-us/azure/foundry/guardrails/guardrails-overview
- **Claude data handling differs.** For Claude in Foundry, "Hosted on Azure" keeps prompts and outputs on Azure infrastructure, while "Hosted on Anthropic infrastructure" may process data outside Azure and outside the selected geography; in both, Anthropic is the seller and an independent data processor under Anthropic's DPA and Commercial Terms, and Foundry provides no built-in content filtering for Claude at deployment time. Source: https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/claude-models/data-privacy ; https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/claude-models
- **Claude Data Zone.** Hosted-on-Azure versions of several Claude models (for example `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`) are available as Data Zone Standard in the US only; Data Zone Standard isn't offered for Claude in Europe or APAC. Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/claude-models ; https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-from-partners
- **Agent sign-in and audit logs.** Entra sign-in logs can be filtered by agent type (blueprint, agent identity, agent's user account) and show delegated user context; Entra audit logs record blueprint and identity creation/deletion with `agentType` and `blueprintId`; Foundry tracing to Application Insights shows tool calls per agent. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity
- **Audit log caveat.** Entra audit logs don't distinguish agent identities by default: operations on agent objects land in the ApplicationManagement category, agent-initiated operations appear as service principals, and Graph activity logs show agents as applications. Source: https://learn.microsoft.com/en-us/entra/agent-id/faq
- **API Management AI gateway controls.** Azure API Management's AI gateway (all tiers) offers `llm-token-limit` (TPM or quota per key), `llm-emit-token-metric`, semantic caching (`llm-semantic-cache-store`/`-lookup`), `llm-content-safety`, prompt/completion logging to Azure Monitor, and exposure or passthrough governance of MCP servers and A2A agent APIs. Source: https://learn.microsoft.com/en-us/azure/api-management/genai-gateway-capabilities
- **FedRAMP and DoD scope.** In Azure public cloud, Azure OpenAI, Azure AI Search, API Management, Logic Apps, Functions, Microsoft Fabric, Private Link and Copilot Studio are in FedRAMP High and DoD IL2 scope; in Azure Government, Azure OpenAI and Azure AI Search reach DoD IL6, and the Microsoft Foundry portal and Azure AI Content Safety are FedRAMP High and IL2 (list last updated February 2026). Source: https://learn.microsoft.com/en-us/azure/azure-government/compliance/azure-services-in-fedramp-auditscope
- **Other attestations.** Azure publishes ISO 27001, SOC 1/2/3, HIPAA BAA, PCI DSS and EU Data Boundary offerings through Microsoft's compliance offerings pages; per-service scope for Foundry was not confirmed in this pass. (unverified) Source: https://learn.microsoft.com/en-us/azure/compliance/

## 5. Commercial model
- **Foundry Models are pay-per-token or reserved capacity.** Azure OpenAI and other models sold by Azure bill per 1M tokens (input, cached input, output) on Standard types, per Provisioned Throughput Unit (hourly, or monthly/yearly reservations; minimum 15, 25 or 50 PTUs by model) on provisioned types, and Batch at 50% off Global Standard with a 24-hour target. Prices weren't rendered on the page on 2026-11-14. Source: https://azure.microsoft.com/en-us/pricing/details/cognitive-services/openai-service/ ; https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types
- **Fine-tuning billing.** Fine-tuning bills training per hour or per 1M tokens (model dependent) and hosting of the fine-tuned deployment per hour. Source: https://azure.microsoft.com/en-us/pricing/details/cognitive-services/openai-service/
- **Foundry Agent Service billing.** Creating and running Foundry-native agents (prompts and workflows) has no extra charge; you pay for model tokens and tools: hosted agents per vCPU-hour and per GiB-hour, file search storage per GB-day (1 GB free), code interpreter per session, web search and custom search per 1,000 transactions, and connectors (Logic Apps, Fabric, SharePoint, Bing) separately. Dollar figures weren't rendered on 2026-11-14. Source: https://azure.microsoft.com/en-us/pricing/details/foundry-agent-service/
- **Claude billing unit.** Claude models in Foundry bill through Azure Marketplace in Claude Consumption Units (CCU). Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/claude-models
- **Fabric billing unit.** Microsoft Fabric bills by capacity: F SKUs (F2 to F8192, sized in capacity units, CU) bought through Azure, billed per second with a one-minute minimum and no commitment, or reserved yearly; viewing Power BI content with a Free license needs F64 or larger, and Power BI Premium P SKUs are being retired in favor of F SKUs. Source: https://learn.microsoft.com/en-us/fabric/enterprise/licenses
- **Identity add-on licensing.** Entra Agent ID Conditional Access needs Microsoft 365 E7 or Agent 365 plus Entra P1/Microsoft 365 E3; Workload ID Premium is a separate per-workload-identity SKU; managed identities and workload identity federation are free. Source: https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id ; https://learn.microsoft.com/en-us/entra/workload-id/workload-identities-faqs
- **Cost visibility permission.** Showing Foundry costs in billing currency needs `Microsoft.Billing/billingProperty/read` at subscription or billing-account scope (for example `Cost Management Reader`); resource-group scope doesn't cover it. Source: https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agent-permissions
